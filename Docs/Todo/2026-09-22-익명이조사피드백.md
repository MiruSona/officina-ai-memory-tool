# 익명이 손님 그림 조사에서 쓴 느낌 (2026-09-22)

## 잘 된 것

- `mem search 손님 그림` 이 앞 두 판의 판정 기록(`20260921-ffeef288`)을 바로 집어 줘서
  「v1·v2 가 왜 물러났나」를 문서 안 읽고 알았다.
- `mem add` 의 거절 메시지가 다섯 가지를 **한꺼번에** 알려 줘서 한 번만 고치면 됐다.
  한 개씩 튕겼으면 다섯 판 돌았을 것이다.

## 걸린 것

- **한글 태그가 막히는 것을 미리 알 길이 없었다.** 서브에이전트는 `mem tags --list` 를 안 돌려 보면
  표준 27가지를 모른다. 거절 뒤에 따라 나온 「다음에 할 것」 이 `mem tags --suggest` 를 가리켰는데,
  실제로 필요한 것은 **`--list`** 였다. 거절 이유가 `tag-shape` 일 때는 `--list` 를 먼저 권하는 쪽이 맞다.
- `mem tags` 를 인자 없이 치면 「할 일을 안 줬다」로 끝난다. 인자 없이 치면 **`--list` 를 보여주는 쪽**이
  사람 손에 더 맞는 것 같다 (읽기라 위험도 없다).

## 아쉬운 것 (제안)

- `mem add --check` 가 있다는 것을 거절 메시지 맨 끝 줄에서 알았다. 도움말 위쪽에도 한 줄 있으면 좋겠다.
