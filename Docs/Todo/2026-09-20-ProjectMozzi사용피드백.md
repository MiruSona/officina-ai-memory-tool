# ProjectMozzi 사용 피드백 (2026-09-20)

> 반영 (2026-09-21) : 바라는 것 셋을 다 넣었다 — 거절에 가까운 표준 태그 후보 · `mem tags --list` ·
> `저장됨 : <id>` / `거절됨` 을 늘 끝줄로. 「게임 저장소 AGENTS.md 한 줄 예」는 그 저장소 몫이라 그대로 남는다.
> 자세한 것은 `진행상황.md` 의 「2026-09-21 사용 피드백 반영」.

게임 저장소 ProjectMozzi2 에서 하루 동안 `mem` 을 쓴 기록이다.

## 막힌 것

| 무엇 | 자세히 | 제안 |
| --- | --- | --- |
| `mem add` 가 세 번째에야 들어갔다 | 첫 시도는 `--summary` · `--scope` 가 필수라는 안내만 나왔다. 다음 시도는 한 번에 네 가지로 거절됐다 — summary 길이(30~120자, summary-len), sources 접두(`file:` `commit:` `url:` `mem:` `note:`), 본문 3줄 이상(body-thin), howto 는 `1.` `2.` 번호 차례(howto-numbered). 결국 `--help` 를 읽고 들어갔다 | 거절 때 「고친 꼴 예시 한 줄」을 같이 찍는다 |
| 게임 저장소 `AGENTS.md` 의 한 줄 예가 모자라다 | `mem add --type … --title … --tags … --sources …` 에는 summary · scope · body 가 없다. 그대로 치면 반드시 거절된다 | — (게임 저장소 쪽 문서 일이다. 여기에는 겪은 일로만 적는다) |

## 헷갈린 것

| 무엇 | 자세히 | 제안 |
| --- | --- | --- |
| 표준 밖 태그를 썼을 때 결과가 안 보인다 | 태그 `sprite` 를 쓰니 「mem tags --add sprite」 안내만 나왔다. **저장됐는지 거절됐는지가 출력 끝 3줄로는 안 보였다** (id 가 안 찍혔다) | 저장 성공 / 실패를 마지막 줄에 늘 한 줄로 찍는다 |
| 표준 태그 전체를 보는 명령을 못 찾았다 | `mem tags --suggest` 를 쳤더니 동의어 후보만 나왔다. 표준 태그 목록을 보는 명령이 도움말에서 바로 안 보인다 | `mem tags --list` 같은 표준 태그 · scope 보기 |

## 잘 된 것

| --- | --- |
| 거절 사유가 규칙 이름과 함께 한 줄씩 나온다 | summary-len 처럼 이름이 있어 무엇을 고칠지 바로 알았다 |
