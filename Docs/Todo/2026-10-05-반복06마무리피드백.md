# 반복 06 마무리 피드백 (2026-10-05)

게임 저장소(ProjectMozzi2)에서 반복 06 을 닫으며 할 일(todo)을 정리할 때 본 것이다. 판은 `mem/0.3.0` 이다.

## 막힌 것

| # | 명령 | 본 것 | 바라는 것 |
| --- | --- | --- | --- |
| 1 | `mem search --type todo --status open` | `SQL logic error: no such column: status (1)` 을 내고 종료 1 이다. `mem search --status open --limit 2` 처럼 `--status` 만 줘도 같다. `mem help search` 에는 `--status` 가 조건으로 적혀 있다 | `--status` 가 `todo_status` 칸을 보게 고친다. 열린 할 일만 뽑는 길이 지금은 없다 |
| 2 | `mem search --type todo` | 끝난(done) 것이 열린 것과 섞여 나온다. 이 저장소에서 35건 중 done 15 · open 20 이었다 (`--json` 의 `todo_status` 로 셌다). 표에는 상태 칸이 없어 어느 것이 끝났는지 `mem show` 로 하나씩 봐야 한다 | 표에 상태 칸을 넣거나, 할 일은 기본으로 open · doing 만 보이고 `--all` 일 때 done 까지 보인다 |

## 헷갈린 것

- `mem set <id> --summary …` 가 「고칠 것을 큐에 넣었다 (`mem index` 가 반영한다)」 로 끝난다. 바로 `mem show` 를 치면 반영돼 있는지 알기 어려워 `mem index` 를 한 번 더 쳤다. 「이미 반영됨 / 다음 명령 때 반영」 중 어느 쪽인지 한 줄 있으면 좋겠다.
- `mem add` 의 title-shape 거절 (「제목이 요약 앞머리를 그대로 베꼈다」) — 제목과 요약 첫 낱말들이 같으면 걸린다. 맞는 규칙이지만 거절 글에 「요약을 다른 말로 시작한다」 예시가 있으면 한 번에 고친다.

## 잘 된 것

- `mem help set` · `mem help add` 가 옵션과 종료 코드를 한 화면에 다 보여 줘서 닫는 꼴(`--done`)을 바로 찾았다.
- `mem show` 끝의 「나를 근거로 삼은 기억」 목록 덕에 할 일을 닫아도 되는지 이어진 결정을 따라가 볼 수 있었다.
- 본문을 PowerShell here-string 으로 `--body` 에 넘겨도 한글 · 여러 줄이 깨지지 않았다.

## 덧붙임 — 추가 피드백 마무리 판 (같은 날)

### 막힌 것

| # | 명령 | 본 것 | 바라는 것 |
| --- | --- | --- | --- |
| 3 | `mem add --type decision … --by <옛id>` | 옛 결정을 뒤집으려고 `--by` 를 줬는데도 「닮은 기억이 있다 (duplicate-hard)」로 거절됐다. 안내는 `--new` 나 `mem set <옛id> --by-new` 였다. 결국 `--new` 로 넣고 `mem set <옛id> --by <새id>` 를 따로 쳤다 (두 번 침) | `--by <옛id>` 로 가리킨 바로 그 기억과 닮은 것은 중복 관문이 지나가게 한다. `mem help add` 에는 `--by` 가 덮는 길이라고 적혀 있다 |
| 4 | `mem add` (`--body` 없이) | 앞 판에서 본문을 안 주자 말없이 표준입력을 기다리며 멈췄다. 에이전트는 입력을 못 넣어 시간 한도까지 기다린다 | 터미널이 아닌 곳(입력이 빈 파이프)에서 본문이 없으면 바로 「--body 나 --stdin 을 준다」로 거절한다 |
| 5 | `mem add --type issue` | 아직 안 고친 문제를 적으려 했는데 `## 증상` · `## 해결` 절이 둘 다 있어야 한다고 거절됐다. 해결 전이라 `todo` 로 바꿔 넣었다 | 안 고친 issue 는 `## 해결` 대신 `## 다음에` 절로도 받는다. 또는 거절 글에 「안 고쳤으면 todo 로」 한 줄 |

### 잘 된 것

- `mem set <옛id> --by <새id>` 가 한 번에 됐고, 덮인 기억을 근거로 삼은 기억 수를 바로 알려 줬다.
- `mem set --link <id>` 로 있던 연결을 안 지우고 하나만 더할 수 있었다.
- 거절 글이 「다음에 할 것」 명령을 그대로 보여 줘서 다시 치기 쉬웠다.
