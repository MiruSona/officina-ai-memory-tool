# 찹쌀이 아트 작업에서 나온 mem 피드백 (2026-09-20)

게임 저장소(ProjectMozzi2)에서 찹쌀이 그림을 레이어로 나누고 점프 애니를 붙이는 작업을 서브에이전트 4판으로 돌리며 `mem` 을 쓴 기록이다.

## 결론

- 찾기·남기기 흐름과 세션 시작 훅은 좋았다. **막힌 것은 전부 「덮기(`--by`)」와 「색인 전 id」 주변**이다.
- 거절 메시지가 「무엇이 틀렸다」까지만 알려 주고 **「그럼 무엇을 쓰면 되나」를 안 알려 줘** 한 번 더 왕복했다.

## 막히거나 헷갈린 것

| 무엇 | 자세히 | 제안 |
| --- | --- | --- |
| 덮으려고 넣은 기억이 색인 때 합쳐졌다 | 옛 결정을 덮으려고 `--by <옛id>` 로 새 기억을 넣었는데 `mem index` 가 옛 기억에 **합쳐 버려 새 id 가 사라졌다.** 결국 옛 기억의 제목·요약을 손으로 고치고 `--new` 로 다시 세운 뒤 `--by` 를 다시 걸었다 | 덮기(`--by` · `mem set --by-new`)로 들어온 기억은 **합침 대상에서 뺀다** |
| 색인 전 id 가 「색인 대기」라 바뀔 수 있다 | 보고서·문서·커밋에 id 를 적기가 어렵다. store 파일이 아직 없어 커밋에서 빠진 것도 있다 (`20260920-22f5bcd3` · `20260920-dfbfc6f8`) | `add` 직후 id 를 굳히거나, 굳지 않았다는 표시와 「다음에 `mem index` 를 돌려라」는 안내를 같이 찍는다 |
| 표준 목록 밖 태그가 그냥 거절된다 | 태그 `농장` · `border` 가 `Memory/vocab.toml` 밖이라 거절. 무엇을 대신 쓸지 몰라 한 번 더 시도했다 | 거절 메시지에 **가까운 허용 태그 후보 몇 개**와 `mem tags --add` 명령을 같이 찍는다 |
| `--type todo` 에 `--todo-status` 를 빠뜨리면 거절 | 새 할 일은 거의 다 열린 상태라 매번 `--todo-status open` 을 붙여야 하는 것이 군더더기다 | 기본값을 `open` 으로 둔다 |
| 막는 기준과 경고 기준의 차이가 안 보인다 | 주제가 다른 기억(`20260920-7f23b10a` FloatCurve 바인딩 vs 점프 설계 결정)을 「같은 자리」라고 막아 `--new` 로 우회했다. 반면 닮음 0.32 짜리는 경고만 붙고 들어갔다 | 거절·경고 메시지에 **닮음 값과 문턱값**을 같이 찍는다 |
| 훅의 실패 알림이 무엇인지 안 알려 준다 | 세션 시작 훅이 「inbox/bad 에 실패 1건, `mem index` 를 돌려라」고만 한다. 무엇이 왜 실패했는지·어떻게 푸는지는 안 나온다 | 실패한 파일 이름과 까닭 한 줄, 푸는 명령을 같이 찍는다 |

## 잘 된 것

| 무엇 | 왜 좋았나 |
| --- | --- |
| 세션 시작 훅의 요약 | 문맥이 끊긴 뒤에도 실측 함정(Animator `Update(0f)` · 캡처 크기)을 **다음 서브에이전트가 바로 피했다** |
| `mem search` → `add` 흐름 | 겹치는 기억을 먼저 찾아보고 넣는 손 흐름이 매끄러웠다 |
