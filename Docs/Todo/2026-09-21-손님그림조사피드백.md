# 손님 그림 레퍼런스 조사에서 쓴 mem 피드백

> 2026-09-21 · ProjectMozzi2 에서 조사 한 판(손님 그림 레퍼런스)을 돌며 쓴 느낌.

## 걸린 것 하나 — decision 관문이 주제가 다른데도 막았다

`--type decision --scope art --tags art,ui,reference,design` 로 「손님 그림을 어떻게 그릴까」 결정을 넣으려 했더니
**`20260920-ca7f4400`(찹쌀이 캔버스 64×64) 때문에 거절**이 났다. 사유는 「같은 자리(scope art · 태그 겹침)에 살아 있는 결정이 있다」였다.

- 두 결정은 **대상이 다르다** — 하나는 찹쌀이 캔버스, 하나는 손님 그림 규격이다. 덮는 관계가 아니다.
- `--new` 를 붙여 바로 통과했으니 **막힌 것은 아니다.** 다만 `scope` 가 다섯 개뿐이라 `art` 안의 결정은
  주제가 아무리 달라도 자주 부딪칠 듯하다. 태그 겹침만으로 잡으면 **「덮어라」라는 잘못된 권유**가 먼저 나온다.
- 제안 : 거절 메시지에서 **`--by` 와 `--new` 의 순서를 바꾸거나**, 부딪친 기억의 제목을 같이 보여 주면
  사람이 「아, 저건 다른 얘기구나」를 바로 안다. 지금은 id 만 나와서 `mem show` 를 한 번 더 쳐야 한다.

## 잘 된 것

- `mem search` 세 번(찹쌀이 레이어 · 아트 규칙 팔레트 · 가판대 카페)으로 **필요한 지난 결정이 다 나왔다.**
  특히 「찹쌀이를 네 겹으로 나눈다」와 「가게는 현대 카페풍」이 바로 잡혀 조사 방향이 첫판에 섰다.
- `mem tags --list` 가 표준 태그와 scope 를 한 화면에 보여 줘서 태그 고르기에 시간이 안 들었다.
- `mem help add` 의 「여러 개는 쉼표로 잇는다. 공백으로 이으면 뒤가 사라진다」 주의가 실제로 도움이 됐다.

## 헷갈린 것

- `mem tags` 를 인자 없이 치면 「할 일을 안 줬다」만 나온다. **`--list` 가 기본이면 한 번 덜 친다.**

## 덧 — 같은 날 2판 (방향이 바뀌어 결정을 덮었다)

- **덮기 흐름은 아주 좋았다.** `mem set <옛id> --by-new` 가 「새 기억을 넣을 때 `mem add … --by <옛id>` 를 주라」고
  **다음 명령을 그대로 찍어 줘서** 한 번에 이어졌다. `mem show` 로 `superseded_by` 도 확인됐다.
- **걸린 것 하나** : `mem set` 에 `--type` 이 없다. 「결정을 덮으며 종류도 같이 준다」고 착각해
  `mem set <id> --by-new --type decision …` 을 쳤다가 **「모르는 옵션 : --type」** 으로 막혔다.
  `mem set` 은 **있는 기억의 칸만 고치는 것**이고 새 기억은 `mem add` 라는 게 `mem help set` 첫 줄에 있긴 하다.
  거절 메시지에 **「새 기억을 만들려면 mem add 를 쓴다」** 한 줄이 붙으면 바로 알아챈다.
- `mem add` 가 **「위 1가지는 경고다」**만 말하고 **무엇이 경고인지는 안 보여 줬다** (`tail` 로 잘려서가 아니라
  줄 자체가 위에 따로 있었다). 경고 본문을 마지막 줄 가까이 붙여 주면 놓치지 않는다.
