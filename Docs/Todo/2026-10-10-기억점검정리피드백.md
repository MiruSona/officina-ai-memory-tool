## 막힌 것

- **`gc --retired --apply` 뒤 `mem lint` 오류가 70 → 110 으로 늘었다.** 접힌 본문(「본문을 접었다…」 한 줄)에
  B01 「본문이 실질 1줄이다」(거절 등급)가 39건 붙는다. 접힌 기억(`state: cold` · `archived`)은 B01 을 건너뛰어야 한다.
  훅이나 커밋 관문이 lint 오류를 막는 저장소였다면 정리하자마자 막혔을 것이다.
- **접힌(덮인) 기억이 다른 큐에 그대로 남는다.** 접은 뒤 큐를 다시 보니 contradict 106줄 중 40 ·
  gone 12 중 4 · value 18 중 4 · expired 8 중 7 이 접힌 기억 자신이었다. 설계 문서는 D05·D06 을 산 기억만 본다고
  했는데 D02(dead-path) · B12(no-value) · C07(expired) · C13 은 죽은 기억에도 돈다. 접힌 B12 는 접은 뒤에 새로 생겼다
  (value 13 → 18). retired 가 맡은 기억은 나머지 큐에서 빼 주면 좋겠다.
- **contradict 가 정리 뒤 73 → 106 으로 늘었다.** 접힌 기억 짝이 빠진 자리를 「기억 하나당 3쌍」 상한이 새 짝으로 채운 듯하다.
  산 기억만 세면 65 라 실제로는 줄었다. 늘어 보이는 것이 헷갈린다.
- **review 의 다음 명령 `mem set <id> --sources …` 가 없는 옵션이다.** gone 큐가 30줄 모두 이 명령을 권하는데
  `mem set` 은 「모르는 옵션 : --sources」로 거절한다. 그래서 근거 20건은 md 파일 머리말을 손으로 고치고 `mem index` 했다.
  `mem set --sources a,b`(통째 갈아 끼우기)가 있으면 좋겠다.
- **`mem set --by` 가 큐에만 넣고 그 자리에서 반영하지 않을 때가 있다.** 「덮음 표시를 달았다」고 찍고 `log.md` 에도 덮음 줄이
  남았는데 파일에는 `superseded_by` 가 없었다. `inbox/new/` 에 patch 가 남아 있었고 `mem index` 를 치자 반영됐다.
  `--link` 는 「큐에 넣었다 — 다음 index 때 반영」이라고 정직하게 말해 줬다. `--by` 도 같은 글을 내면 좋겠다.

## 이어서 (같은 날 정리 2판)

- **`mem init` 이 AGENTS.md 의 mem 블록에서 저장소 고유 문장을 템플릿으로 덮어썼다.** mem.toml 빠진 키 2개를 채우려고 돌렸는데
  `<!-- >>> mem >>> -->` 블록 안의 「`--summary`·`--scope` 예시」「decision · issue · caution · fact 는 `--sources` 도」
  「언제 무엇을 남기나는 `mem-usage` 스킬」 두 줄이 템플릿 한 줄로 바뀌었다. `git checkout -- AGENTS.md` 로 되돌렸다.
  되돌린 뒤 `mem status`·`--doctor` 는 아무 경고도 안 내지만 `init --dry-run` 은 다시 「옛 mem 블록 있음 → 갈아 끼움」이라 한다.
  설정만 채우는 길(`init --only-config` 같은 것)이 있거나, 블록을 사람이 고쳤으면 안 덮고 묻기를 바란다.
- **`--origin stop` 과 `--new` 가 같이 안 듣는다.** 두 기억을 합친 새 기억은 원본과 닮을 수밖에 없는데, 자동 관문 R4-no-merge 가
  원본을 duplicate-hard 로 보고 거절한다. 명세대로 `--new` 를 무시해서 합치기(merge 큐의 권장 처리)는 자동 기억으로 못 남긴다.
  origin 을 빼고 `mem add --new` 로 넣었다. 「합칠 원본으로 적은 `mem:` 근거와의 닮음」은 관문에서 빼 주면 좋겠다.
- **덮으면 그 기억을 `links` 로 단 기억이 basis 큐에 떨어진다.** 결정 `20260912-ae6a4d35` 를 덮자 3건이 C14 로 떴다.
  `mem set --links` 로 새 id 로 바꿔 끼워 0 이 됐다. `set --by` 가 「가리키던 기억 n건 — 새 id 로 바꿀까」를 미리보기로 내 주거나
  `--by <새> --relink` 같은 옵션이 있으면 좋겠다. (review 의 basis 안내는 「근거」라고 하는데 실제로 걸린 건 `links` 였다.)
- **NLI(`nli-studio-v2`, 8092) 로 contradict 를 돌려 본 소감.** `--nli --nli-pairs 1000 --all` 로 516건에서 **56쌍**을 물었고
  두 번째 실행 포함 26초, 짝당 평균 131ms(최대 325ms)였다. 결과는 A(지지) 35 · C(중립) 15 · B(반대) 6. 확신선(0.82) 넘은 B 는 3짝이고
  **셋 다 오탐**이었다 — ① 「되돌릴 수 있다」는 주의 ↔ 「되돌렸다」는 결정(이행인데 반대로 봄, 0.86) ② 「README 의 v5~v7 소절」 ↔
  「v11 소절」(이름만 다름, 0.94) ③ pro_flash 「투명이 너무 됨」 ↔ pixflux 「투명이 안 됨」(다른 도구, 0.95).
  scope 당 20쌍 상한에 걸려 24쌍은 못 물었다 — scope 상한만 따로 올리는 깃발이 없다. 물은 짝 수가 출력·JSON 에 안 나와 판정 캐시를 세서 알았다.
  규칙 층 C13 108줄 + C19 3줄이라 어긋남 큐는 여전히 손검사 몫이 크다.
- `--nli` 가 SemIf(llm.toml 의 `url`) 를 안 부른다는 것은 설계 문서에만 있고 help 에는 없다. 그래서 돌리는 동안 `url` 줄을 주석 처리했다 되돌렸다. help 에 한 줄 있으면 좋겠다.

## lint 오류 정리 (같은 날 3판)

- **접힌 기억이 lint 오류의 절반을 넘는다.** 오류 90 중 54 가 접힌 것이다 — body-thin 44 · stale-after-passed 7 · issue-sections 1 ·
  duplicate-hard 2(산 기억이 접힌 기억과 닮았다고 걸림, 접힌 쪽은 본문이 한 줄뿐인데도). 접힌 기억은 본문 규칙·다시 볼 날·중복 짝에서 빼야 한다.
- **duplicate-hard(문턱 0.08)가 산 기억 10건을 오류로 잡는데 열 건 모두 다른 내용이었다.** 닮음 0.089~0.143 이다.
  같은 날 쓴 조사 둘, 결정 ↔ 그 결과 history, 할 일 ↔ 거기 빠진 하위 할 일 같은 짝이다. `links` 로 이어도 오류가 안 사라진다.
  add 때 막는 자와 이미 있는 기억을 거절로 찍는 자를 나누거나, 서로 links 로 이은 짝은 빼 주면 좋겠다.
- `mem set --stale-after ""` 로 다시 볼 날을 지울 수 있었다 — help 에 「빈 값이면 지운다」 한 줄이 있으면 좋겠다.
