# 타일 작업에서 쓴 피드백 (2026-09-20)

게임 저장소에서 바닥 타일·울타리 그림 한 판을 끝내고 기억 4건을 남기며 겪은 것이다.

## 결론

- **관문이 거절 사유를 한 번에 다 알려 주는 것이 제일 좋았다.** 한 번 고치면 통과한다.
- **막힌 것은 거의 「규칙이 문서에 안 적혀 있어서」다.** 본문 3줄 · 제목 길이 · `numbered` 본문 꼴이
  쓰는 쪽 스킬 문서에 없어, 서브에이전트마다 한 번씩 거절을 맞고 배운다.
- **태그·상태를 알려 주는 안내 문구가 한 발 모자란다.** 거절할 때 쓸 수 있는 목록을 같이 보여 주면
  파일을 직접 열 일이 없다.

## 잘 된 것

| 무엇 | 왜 좋았나 |
| --- | --- |
| `add` 관문이 사유를 **한꺼번에** 준다 | 고치고 다시 걸리는 되돌이가 없다 |
| 중복 soft 경고 | 「닮은 기억 있다」를 막지 않고 알려 줘, 새 주제인지 스스로 판단하게 한다 |
| decision 게이트가 덮을 후보 id 와 `--by` · `--new` 두 길을 같이 찍는다 | 다음에 칠 명령이 바로 나온다 |
| `search` 가 낱말+의미 둘로 찾는다 | 「풀밭」 한 낱말로 관련 결정·요령이 다 나왔다 |

## 막힌 것

| # | 무엇 | 어떻게 됐나 | 바라는 것 |
| --- | --- | --- | --- |
| 1 | `--body` 3줄 필수 · 제목 6~40자 · `howto` 는 번호 본문 | 이 규칙이 쓰는 쪽 스킬 문서에 없어 **서브에이전트마다 한 번씩 거절**당한다 | 이 셋을 `add` 의 `--help` 첫 화면이나 스킬 문서 본문에 한 줄씩 적는다 |
| 2 | 표준 밖 태그 거절 | **쓸 수 있는 목록도, 가까운 후보도 안 보여 준다.** 어쩔 수 없이 낱말 표 파일을 직접 열었다. `tilemap` 이 이미 있는데 도구는 `--add tile` 로 새로 만들라고 권했다 | 거절할 때 ① 표준 목록 ② 가장 가까운 후보 2~3개를 같이 찍는다 |
| 3 | `tags` 를 인자 없이 치면 | 목록이 아니라 **오류**다. 목록을 보려고 친 것인데 | 인자 없는 `tags` 는 표준 태그·scope 목록을 찍는다 |
| 4 | 「색인 대기」 상태에서 `show` | **「없다」고 한다.** 방금 id 를 받았는데 못 보니 실패로 읽힌다 | 「아직 색인 전이다 — 지금 보려면 `index` 를 돌린다」로 답한다 |
| 5 | `inbox/bad` 에 남은 patch 1건 | 덮어쓴 옛 id 를 고치려던 찌꺼기였다. `index` 를 돌려도 안 풀려 **손으로 지웠다** | `index` 가 못 푸는 조각은 왜 못 푸는지 한 줄 찍고, 치우는 명령을 준다 |
| 6 | `--severity medium` 거절 (09-20 문서 고치기 판) | 값이 `high·mid·low` 인 것이 쓰는 쪽 스킬 문서에 없어 한 번 거절당했다. 1~3번(제목 길이 · 태그 수 · 표준 태그)도 같은 판에서 또 걸려 **세 번 만에** 들어갔다 | `medium` 을 `mid` 별칭으로 받거나, 스킬 문서에 세 값을 적는다 |
