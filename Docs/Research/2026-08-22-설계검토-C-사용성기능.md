# AIMemoryTool — AI 가 쓰는 입장에서의 사용성·빠진 기능 조사

## 결론 먼저

**넣기·찾기 자체는 잘 돈다.** 205건이 실제로 쌓였고, 검색은 20~30ms 에 그럴듯한 답을 낸다.
내가 이 세션에서 `mem search` 로 필요한 근거를 실제로 다 찾았다. **툴의 뼈대는 성공이다.**

문제는 셋으로 모인다.

1. **주입 블록이 세션을 못 본다.** `mem context --query` 배관은 이미 코드에 있는데 아무 훅도 안 쓴다.
   지금 주입되는 24줄은 어느 세션에서나 똑같다. 고정 42건 중 어느 5건이 보일지는 `updated_at` 순, 사실상 제비뽑기다.
2. **품질 규칙이 사람 말로만 있고 코드에 없다.** "핀 10건 안쪽" 은 규칙 문서에만 있고 42건이 됐다.
   `mem lint` 는 오류 0 · 경고 0 을 내는데, 내가 손으로 센 문제는 60건이 넘는다. 린트가 보는 것과 실제 품질이 안 겹친다.
3. **필수 칸이 값을 못 낸다.** `severity` 는 86건이 채워 넣었는데 **읽는 코드가 0곳**이다.
   랭킹·출력·필터 어디에도 안 쓰인다. 내는 비용은 매번, 얻는 것은 없다.

### 블록 구성(고정 / 열린 할일 / 최근 결정 / 이슈→해결 / 주의)이 최선인가

**대체로 맞다.** 특히 "열린 할일" 은 어느 세션에서나 값이 있었다. 다만 셋을 고쳐야 한다.

1. **"최근 이슈→해결" 은 이미 해결된 것을 올린다.** 해결된 이슈는 다음 세션이 다시 물어볼 것이 아니다.
   `issue` 에 열림/닫힘 상태가 없어서(status 는 todo 전용) 가릴 방법이 아예 없다.
2. **`## 고정` 이 5줄로 잘리는데 고르는 기준이 `updated_at DESC` 다** (`internal/search/engine.go:116`).
   205건이 같은 날 한꺼번에 색인돼서 사실상 파일 쓴 순서다. 42건 중 어느 5건이 보일지 아무도 정하지 않았다.
3. **scope 로 안 거른다.** `scope: officina` 인 Unity·미니PC 결정이 AIMemoryTool 작업 세션에 들어온다.

### 세션 맥락(cwd·브랜치·최근 바뀐 파일)을 못 쓰는 한계

지금 훅은 `SessionStart` 하나이고 stdin 의 훅 JSON 에서 `source`(startup/resume/…) 만 쓴다.
**cwd 는 훅 JSON 에 들어오고, 브랜치와 최근 바뀐 파일은 `git` 한 번이면 나온다.** 지금은 셋 다 안 본다.

가장 싼 개선은 **cwd 기준 scope 추론**이다. `<작업폴더>\AIMemoryTool` 에서 세션을 열면
`scope: aimemorytool` 을 위로 올리고 `officina` 를 내린다. 지금 이 세션이라면 쓸모없던 2줄이 바로 빠진다.

### `UserPromptSubmit` 훅으로 질문에 맞춰 꺼내 주는 방안

**이미 코드가 다 돼 있다.** `hook.Options.Query` → `relatedSection` → `## 관련 (3)` 절
(`internal/hook/context.go:150`, `cmd/mem/hook.go:19`). `mem context --query` 로 직접 돌려 봤다.

```
mem context --query "사용성 기능 빠진" --budget 800
## 관련 (3)
- [20260822-6ac7b8ac] AIMemoryTool 요구사항 10개 — …
- [20260822-e576df82] 코드 구조에서 설계와 달리 정한 것 — …
- [20260822-c53698fe] exe 이름은 mem 으로 정했다 — …
```

3줄 중 2줄이 이 과제에 맞았다. **고정 5줄(맞은 것 2줄)보다 명중률이 높다.**
그런데 `mem init` 이 등록하는 훅은 `SessionStart` 하나뿐이다(`internal/install/settings.go:16`). 배관이 놀고 있다.

| | 득 | 실 |
| --- | --- | --- |
| `UserPromptSubmit` 훅 | 질문에 맞는 기억이 온다. 세션 중간에 주제가 바뀌어도 따라온다. 배관은 이미 있음 | **매 턴 비용**이다. 훅 실행 20~30ms × 턴 수, 주입 토큰 3줄×약 35토큰 = 약 100토큰/턴. 한 세션 100턴이면 1만 토큰 — SessionStart 1,200토큰의 8배 |
| 절충 (추천) | 사용자 프롬프트가 일정 길이 이상일 때만, 그리고 **같은 id 는 세션 안에서 한 번만** 주입 | 상태를 들고 있어야 해서 단발 exe 원칙이 흔들린다 |

**추천 : 지금은 켜지 말고 `mem context --query` 를 규칙에 넣는다.**
`Memory/사용법.md` 에 "새 주제를 시작할 때 `mem search` 를 먼저" 한 줄이면 AI 가 스스로 부른다 — 비용이 필요할 때만 든다.
훅으로 강제하는 것은 턴당 비용을 재 보고(설계 4절이 `PostToolUse` 를 거절한 것과 같은 계산) 정한다.

## 3. 넣기 흐름 — `mem add`

### 필수 칸 부담

`--type --scope --summary --tags --body` 5개 + 종류에 따라 `--severity` 또는 `--status`.
**부담 자체는 크지 않다.** 실제로 205건이 들어갔다는 것이 증거다.

문제는 **값을 못 내는 칸이 섞여 있다는 것**이다.

| 칸 | 내는 비용 | 얻는 것 |
| --- | --- | --- |
| `type` | 6개 중 고민 | 크다 (감쇠·주입 절이 갈린다) |
| `scope` | 낱말을 지어야 함 | **지금은 거의 없다.** 검색 필터로만 쓰이는데 어휘를 볼 방법이 없어 흔들린다 |
| `summary` 30~120자 | 큼 | 크다 (주입 블록이 이걸로 만들어진다) |
| `tags` 1~5개 | 큼 (110종으로 흩어짐) | 작다. `--tag` 필터 하나뿐이고 어휘를 볼 방법이 없다 |
| `severity` (86건) | 매번 | **0. 읽는 코드가 없다** |
| `status` (todo) | 작음 | 크다 (열린 할일 절) |
| `title` | — | 0건이 씀 |

`severity` 를 코드로 확인했다 — `internal/model/validate.go:89` 가 필수로 잡고 `internal/index/rows.go:102` 가 DB 에 넣는데,
**꺼내 쓰는 곳이 없다.** 점수식(`internal/search`)에도 없고, `search`/`list`/`show`/`context` 출력에도 안 찍히고,
`readFlags`(`cmd/mem/read.go:16`)에 `--severity` 필터도 없다. `caution` 이 severity high 든 low 든 결과가 똑같다.

### 오류 메시지는 친절한가 — **친절하다**

`internal/i18n/i18n.go:110~140` 을 봤다. 규칙과 실제 값을 같이 준다.

```
`summary` 는 30~120자여야 한다. 지금 16 자다.
`scope` 는 영어 소문자·숫자·하이픈 1~30자여야 한다 : My-Scope
`type` 이 여섯 가지(todo history issue caution decision howto) 중 하나가 아니다 : note
```

게다가 `model.Validate` 가 **어긴 규칙을 전부 모아서 한 번에** 낸다(`validate.go:25`). 두 번 왕복하지 않아도 된다. 잘 만들었다.

**다만 README 의 예시 자체가 거절당한다.** `AIMemoryTool/README.md:83` 의
`--summary "PATH 반영은 새 터미널부터"` 는 **16자**다. 최소 30자에 걸린다.
AI 는 예시를 그대로 흉내 내는데, 첫 시도가 반드시 실패한다.

### `--stdin` · 여러 줄 · 따옴표

- `--stdin` 은 **body 전용**이다(`cmd/mem/commands.go:83`). 나머지 칸은 여전히 플래그로 줘야 한다.
- PowerShell 에서 한글은 문제없다(205건이 증거). 위험한 것은 본문에 `"` 나 `$` 가 들어갈 때인데,
  여기서 안전한 길은 `--stdin` + here-string 하나뿐이고 **`Memory/사용법.md` 에 그 예시가 없다.**
  (추측 : `--body` 안의 `$env:` 같은 문자열은 PS 가 전개해 버려 조용히 다른 내용이 저장될 수 있다. 안 돌려 봤다 — 쓰기 명령이라)
- **한 번에 여러 건 넣기가 없다.** JSON/JSONL 일괄 넣기도 없다.
  실제로 이 저장소는 문서 11개 + 3개를 mem 으로 옮기면서 `add` 를 100번 넘게 불렀다(커밋 `049cdf7`·`5139650`).
  `inbox/new/` 에 직접 쓰는 우회로가 있지만 **비밀정보 검사를 건너뛴다**(기억 `2c121929` — 실제로 AWS 키가 git 추적 폴더까지 갔다).
  즉 지금 구조는 "일괄 넣기를 하려면 위험한 길로 가라" 고 떠미는 모양이다.

## 6. 규칙 3줄 + 사용법 30줄로 AI 가 정말 쓰는가

**솔직히 : 반은 쓰고 반은 안 쓴다.** 내가 이 세션에서 겪은 것으로 적는다.

### 쓰게 되는 것

- **`mem search`** 는 쓴다. 주입 블록에 id 가 보이니 `mem show` 로 이어지는 길이 자연스럽다.
- 주입 블록 맨 위 `규칙 : Memory/사용법.md` 한 줄이 실제로 먹는다 — 나는 이 줄 때문에 그 파일을 열었다.

### 안 쓰게 되는 것 — 솔직하게

| 상황 | 왜 안 쓰게 되나 |
| --- | --- |
| **작업 도중 막혔을 때 검색할 생각을 못 함** | 규칙이 "세션을 시작하면" 이라고 말한다. 세션 중간에 새 주제를 만났을 때 찾으라는 말이 없다. 나는 오늘 코드를 먼저 읽고, 한참 뒤에야 "이거 mem 에 있겠다" 고 떠올렸다 |
| **넣을 타이밍을 놓침** | 규칙은 "완료 보고를 쓰기 전에" 다. 그런데 **완료 보고를 쓸 때는 이미 컨텍스트가 다 차 있고 요약을 쓰느라 바쁘다.** 그 시점에 `--summary` 30자를 새로 짓는 것은 추가 일이라 미루게 된다. 실제로 이 저장소의 todo 는 열린 채 7건, `done` 0건이다 — **넣기는 시켰는데 닫기는 아무도 안 시켰다** |
| **뭘 넣을지 판단이 안 섬** | "다음 세션이 다시 물어볼 것" 은 맞는 기준인데 경계가 흐리다. 그래서 안전하게 다 넣거나(중복 34건) 안전하게 안 넣거나 둘 중 하나가 된다 |
| **잘못 넣은 걸 고칠 생각을 안 함** | 고치는 명령이 없다는 걸 알면 애초에 신경 안 쓴다 |
| **`mem context --query` 를 부를 생각을 못 함** | `mem help` 에도 `--query` 가 있는데 사용법.md 에 없다. **AI 는 사용법.md 만 읽는다** |

### 문서만으로 되는 보완 (코드 0줄)

`Memory/사용법.md` 에 세 줄 추가하면 위의 절반이 없어진다.

```
- 새 주제를 시작할 때 mem search 를 먼저 한 번 돌린다. 세션 시작 때만이 아니다.
- 넣기 전에 mem search 로 비슷한 게 있나 본다. 있으면 새로 넣지 말고 그 기억을 고친다.
- 소단계가 끝날 때마다 '지금 남길 것 있나' 를 본다. 완료 보고 때 몰아서 하지 않는다.
```

그리고 `mem lint` 가 오류 0 을 내는 한 아무도 품질을 안 볼 것이다. **규칙을 코드로 옮겨야 한다.**

## 발견 상세 (근거 → 왜 문제 → 보완 2안)

### 1. 주입 블록이 세션 맥락을 안 본다 [상]

**근거** : `internal/hook/context.go:141` `relatedSection` 은 `options.Query` 가 비면 그냥 `nil` 을 낸다.
`cmd/mem/hook.go:60` `runHook` 은 `session-start` 만 받고 query 를 안 넘긴다.
`internal/install/settings.go:16` 이 등록하는 훅은 `SessionStart` 하나뿐.
직접 `mem context --query "사용성 기능 빠진"` 을 돌려 3줄 중 2줄이 과제에 맞는 것을 확인했다.

**왜 문제** : 고정 5줄의 명중률(2/5)보다 관련 3줄의 명중률(2/3)이 높은데, 후자는 아무도 안 부른다.
그리고 다른 프로젝트 범위(`officina`) 기억이 그대로 섞여 들어온다.

**보완**
- (가) `SessionStart` 훅에서 **cwd 로 scope 를 추론**해 그 scope 를 위로, 다른 scope 를 아래로. 훅 JSON 에 cwd 가 온다. 코드 20줄쯤.
- (나) `UserPromptSubmit` 훅을 붙여 매 턴 `--query` 로 3줄.
