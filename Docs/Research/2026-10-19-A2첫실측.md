# A2 `mem retain` 첫 실측 — 틀린 저장 0 · 쓸모 있는 저장도 0

- 쓴 날 : 2026-10-19 · 쓴 사람 : Opus 서브에이전트 (1~3판은 메인이 돌렸고, 대조판·K 재측정·후보 판정은 이 문서를 쓴 에이전트가 했다)
- 앞 문서 : `../Design/2026-10-19-A2-retain설계.md`(이하 「설계」) 1·4·7·10절
- 생성 서버는 「미니PC」(Strata), 판정 서버는 메인 PC 의 JudgeModel(8092, `nli-studio-v10`, model `d4e99e1b`)이다.

## 0. 결론

1. **틀린 저장 위험은 이번 판에서 안 보였다.** 네 판 후보 28건(3판 14 · 대조판 14) 중 관문을 지난 것이 **0건**이다. 틀린 제목을 단 후보 하나(「미니PC」 아닌데 「미니PC」)도 막혔다.
2. **그러나 쓸모 있는 저장도 0건이다.** 지금 그대로 실제 판을 돌리면 해는 없지만 남는 것도 거의 없다.
3. **가장 큰 까닭은 R3 문턱이다.** 지지 문턱 0.89 를 넘어야 통과인데, K 48 의 「정말 지지」 16쌍 중 0.89 를 넘는 것이 **6쌍(38%)뿐**이다. 글자만 보면 K 는 46/48 로 통과지만, retain 의 엄격 판정으로 보면 좋은 후보 열에 여섯을 버린다.
4. **둘째 까닭은 「인용 하나하나가 요약 전체를 뒷받침해야 한다」는 꼴이다.** 요약이 두세 가지를 묶어 말하면, 한 가지만 말하는 인용은 「무관」으로 잡힌다.
5. **R4(중복)는 대체로 맞게 막았다.** 대조판 R4 6건 모두 실제로 같은 기억이 있다. 다만 같은 내용이 판에 따라 R4 에 걸리기도 하고 안 걸리기도 했다(3절 함정 ②).
6. **`chunk_chars` 36,000 은 그대로 둔다.** 36,000자 토막이 17,098 토큰(약 2.1자/토큰)이라 64K 문맥에 넉넉하다.

**권장** : 실제 판은 **R3 를 손본 뒤**에 돌린다. 위험 때문이 아니라 지금은 저장이 0 이라 돌릴 값이 없어서다. 손볼 곳은 5절에 적었다.

## 1. 절차

1. `mem retain --dry-run` 을 스튜디오 뿌리에서 돌린다. 실행 파일은 `AIMemoryTool/bin/mem-a2.exe`.
   `--dry-run` 은 생성 → 자식 `mem add --check` 로 관문까지 돌리고 저장·큐 표시는 안 한다 (설계 0절 #11).
2. 결과는 `Memory/local/retain-log/2026-10-19.jsonl` 에 세션당 한 줄로 남는다 (git 밖).
3. 대조판 앞에 로그를 키웠다 — dry `items` 에 후보의 `summary` 와 거절 까닭 글 `reasons[]` 를 더했다 (`cmd/mem/retain_log.go` · `retain_session.go`, 시험 `TestRetainDryRunLogsSummaryAndReasons`).
4. 대조판은 후보가 나온 네 세션에 `--session <8자>` 로 **차례로** 돌렸다 (로컬은 한 번에 한 판).
5. 후보마다 거절이 맞았는지 사람 눈으로 다시 봤다.
   - R1(인용 없음) : 대화 기록 파일에서 그 인용을 직접 찾았다.
   - R4(중복) : `mem search` 로 겹친 기억을 찾아 내용을 견줬다.
   - R3(지지 못 받음) : 인용과 요약을 읽고, 같은 쌍을 `mem judge support --stage nli` 로 다시 물어 세 칸 확률을 받았다.

- **36,000자 토막 = 17,098 토큰 (약 2.1자/토큰).** 생성 상한 1,500 토큰과 시스템 글을 더해도 64K 의 3분의 1 이 안 된다. 코드가 많은 대화로 1.5자/토큰까지 떨어져도 24K 다. **바꿀 까닭이 없어 36,000 을 둔다.**
- 생성 시간은 토큰 수보다 출력 길이에 더 끌린다. 후보 3개를 쓰는 토막은 25~38초, 후보 없는 빈 세션은 1.6초다.
- 대조판 네 세션은 합 **2분 10초**. 3판 여덟 세션은 2분 12초.

### 함정 셋

1. **R3 는 요약만 본다. 제목은 안 본다.** c15843cd 의 「미니PC … 이동 완료」는 요약은 맞고 제목만 틀렸다. 이번엔 R3 unsure 로 막혔지만, 요약 확률이 0.89 를 넘었으면 틀린 제목으로 저장됐다.
2. **R4 는 낱말 차이에 흔들린다.** 같은 venv 경로 caution 이 3판에선 R4 에 걸리고 대조판에선 안 걸렸다. 중복이 R3 까지 통과하면 그대로 들어간다.
3. **temperature 0 이어도 같은 토막에서 후보가 판마다 다르다.** 같은 prompt 토큰 수(5,041 · 17,098)인데 제목·인용이 바뀌었다. 판 한 번의 결과로 규칙 효과를 단정하면 안 된다.

## 5. 남은 일

1. **R3 를 retain 에 맞게 손본다.** 길은 둘이다. 하나를 고르는 것은 메인·사용자 몫이다.
   - (가) 인용 묶음 전체를 한 근거로 이어 요약과 한 번만 묻는다. 「인용 하나 = 요약 전체」 꼴을 버린다.
   - (나) 생성 시스템 글에 「summary 는 quotes 하나로 다 뒷받침되는 한 문장」을 더한다.
   - 문턱 0.89 를 내리는 것은 권하지 않는다. K 에서 거짓 통과 0/32 가 지금 문턱 덕이다.
2. **R3 가 제목도 묻게 한다** (함정 1). 제목 · 요약 둘 다 지지를 받아야 통과.
3. **로그를 조금 더 키운다.** R4 거절 까닭에 겹친 기억 id 를, R3 「뒷받침 안 함」 까닭에 세 칸 확률을 싣는다. 지금은 unsure 일 때만 확률이 나온다.
4. 같은 세션을 두세 번 돌려 판마다 후보가 얼마나 흔들리는지 본다 (함정 3).
5. 설계 10절의 「잡음+중복 ≤ 30% · 틀림 0」 표본 30건은 저장이 0 이라 아직 못 잰다.
