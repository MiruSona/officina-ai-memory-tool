## 결론 먼저

1. **자료·라이선스는 막힌 것이 없다.** KLUE-NLI 학습 24,998 · 검증 3,000, KorNLI 학습 942,854(SNLI 550,152 + MNLI 392,702) 모두 CC BY-SA 4.0 이다.
   KorNLI dev/test 는 저장소 표기는 BY-SA 4.0 이지만 **원본 XNLI 의 LICENSE 파일이 CC BY-NC 4.0** 이라 안 쓴다는 앞 결정이 맞다.
   ko-decision 검증 행 수는 **둘 다 맞다** — 2,080행 공통 조각 안에 NLI 가 999행이다.
2. **가장 큰 걸림은 학습 기계다.** 미니PC 의 학습용 venv 는 `torch 2.14.1+cpu` 뿐이다. GPU(gfx1151) 학습에는 ROCm 판 torch 설치가 필요하고, 이건 패키지 추가라 **사용자 승인 몫**이다.
   CPU 로는 KorNLI 95만 1 epoch 가 **약 50~80시간**(추정)이라 못 쓴다. CPU 로 되는 판은 「KLUE-NLI 전부 + KorNLI 일부(2~5만)」 정도다.
3. **메모리는 게임 서버 중에도 될 만하다.** 지금(10-09 00시) 게임 서버 RSS 4.1GB · `agent` llama 적재 · 가용 24GB · 스왑 78MB.
   roberta-large 전체 미세학습은 fp32 AdamW 로 **8~12GB**(추정)라 가용이 12~16GB 로 내려간다. 10GB 선 위지만 **실측 안 된 판**이라 규칙상 첫 판은 게임 서버 내린 뒤에 잰다.
4. **사이드카는 Go 쪽을 거의 안 고친다.** 응답 꼴 `{"a","b","c","model","ms"}` 만 지키면 된다. 고칠 자리는 `serve.py`(새 판정 꼴) · `export_onnx.py` · 판 이름 상수 하나다(5절).
5. **실물 쌍은 짧다.** train 근거+주장 합 중앙 139자 · p95 560자 · 최대 1,020자, game90 은 최대 296자. `max_len 256` 이면 game90 전부, train 약 93% 를 덮는다(토큰 수는 추정).

**ko-decision 검증 행 수 (999 vs 2,080)** — 둘 다 맞다. 카드 원문 : 「Fixed 2,080-row KLUE slice (NLI 999 rows / 333 premise groups, YNAT 1,000, STS 81)」.
NLI 정확도 90.69% 는 999행 기준이다(`eval/paired_vs_laya.json` : rows 999 · candidate 0.9069 · baseline Laya 0.7367).
카드 스스로 「공개 KLUE 검증 자료이고 앞 작업에서 본 적이 있어 블라인드 시험이 아니다」라고 적었다. 따로 고른 시험 600행은 91.8%.

**「같은 조건 공유(SA)」가 우리에게 요구하는 것 (한 줄)** — 학습한 가중치를 **밖에 내놓을 때만** 출처 표시와 함께 CC BY-SA 4.0 으로 내놓아야 한다(기반 가중치 자체가 BY-SA 라서). 우리 학습 코드·머리 정의 파일은 우리가 쓴 코드라 조건이 안 걸리고, 가중치를 git 밖에 두고 혼자 쓰면 의무가 없다.
ko-decision 의 `DATA_NOTICE.md` 도 「자료 라이선스만으로 가중치 공개 조건이 정해지지는 않는다」고 적었다. 법률 판단은 아니다.

## 4. 학습 판 어림

**실측 바탕 (미니PC CPU 8 스레드, Laya 322M)** — v2 train 1,230쌍 6 epoch 3,281초 = **쌍·epoch 당 0.44초** · 피크 RSS 3.98GB (`~/judge-laya/laya2/ft/train_info.json`). ft1000 은 0.29초(쌍이 더 짧음, `Docs/Research/2026-10-08-Laya1000건실측.md` 3절).
Laya 기반(mmBERT)은 파라미터 대부분이 큰 낱말표(25만)라 층 계산은 약 1억 몫이다. klue/roberta-large 는 층 계산이 약 3억이라 **같은 길이면 약 2.5~3배 무겁다**. 대신 NLI 쌍에는 Laya 의 물음 머리(질문·선택지 글)가 안 붙어 입력이 짧다.

**어림 표** (추정 · max_len 128~256 · 길이별 묶음 패딩 · batch 16~32 · lr 1e-5 · fp32)

| 판 | 쌍 수 | CPU 16~32 스레드 (쌍당 0.2~0.3초) | GPU gfx1151 (어림 1,000~3,000 쌍/분) |
| --- | --- | --- | --- |
| KLUE-NLI 1 epoch | 25,000 | 1.5~2시간 | 10~25분 |
| KorNLI 10만 표본 1 epoch | 100,000 | 6~8시간 | 35~100분 |
| KorNLI 전부 1 epoch | 942,854 | **52~79시간** (못 씀) | 5~16시간 |
| mem 덧학습 1 epoch | 1,230 | 4~6분 (근거가 길어 더 걸릴 수 있음) | 1분 안팎 |

- GPU 눈금 근거 : 8060S 의 fp16 이론값 약 59 TFLOPS 의 10~20% 를 쓴다고 보고, 학습 계산량 6 × 3억 × 토큰 수로 셈. **gfx1151 에서 BERT 학습 실측 공개 자료는 못 찾았다.** 공식 pytorch.org 판 wheel 은 gfx1151 에서 「invalid device function」 로 안 돈다는 보고가 있고, AMD 야간 판(`rocm.nightlies.amd.com/v2/gfx1151/`)이나 TheRock 판을 쓴다는 글이 있다. gfx1151 은 flash·메모리 절약 SDPA 가 기본으로 없어 attention 이 느린 길로 간다는 보고도 있다(웹 검색 · huggingface.co/axjns/strix-halo-kernels).
- 참고 : ko-decision 은 127,162행 2 epoch 를 CUDA(Colab, GPU 이름 미상)로 batch 32 · max_len 512 · encoder lr 1e-5 로 학습했다(`eval/training_config.json`).
- KLUE·KorNLI 논문 쪽 근거 : 소설 모순 저장소는 KorNLI+KLUE 를 **섞어** roberta-base 를 1번 돌렸다(앞 조사 RAG원리 문서). 이어서 학습하면 KLUE 점수는 오르고 실물 모순 재현이 떨어졌다는 보고도 같은 곳에 있다.

**메모리** (추정) : fp32 가중치 1.35GB + 기울기 1.35GB + AdamW 상태 2.7GB = 5.4GB, 여기에 활성값(batch 32 · 128 토큰 · 24층) 2~5GB → **8~12GB**. 그래디언트 체크포인트·batch 16 이면 7GB 안팎.
- 게임 서버 중 : 지금 가용 24GB 에서 빼면 12~16GB 가 남아 10GB 선 위다. 다만 llama `agent` 가 판정 뒤 RSS 를 +8GB 키운 실측이 있어(미니PC.local.md 표) 겹치면 4~8GB 까지 내려갈 수 있다.
  → **첫 판은 게임 서버 내린 때 재고**, 같이 돌아도 되는지는 그 실측으로 정한다. `systemd-run -p MemoryMax=12G -p MemorySwapMax=0` 로 묶는 지금 방식이 그대로 쓰인다.
- GPU 길은 메모리가 GTT(시스템 메모리)에서 나가 같은 몫을 먹는다. **GPU 가 멎으면 claude 계정으론 못 살린다**(mem `minipc-gpu-hang`, 09-15 두 번) — 밤 무인으로 처음 띄우는 판은 금지 규칙에 걸린다.

**CPU 만으로 되나** — 「KLUE-NLI 전부 + KorNLI 2~5만 + mem 덧학습」이면 한 판 10~20시간으로 된다. 95만 전부는 안 된다. 메인 PC(Windows, GPU 미확인)는 조사 안 했다.

**ONNX CPU 추론 어림** — Laya v2 는 메인 PC onnx 4 스레드에서 HTTP p50 224ms · p95 496ms 였다(`2026-10-08-자체판정프로그램실측.md` 3절). klue/roberta-large 3갈래 머리(한 번 계산)는 층이 무겁고 입력은 짧아 **p50 200~400ms**(추정). int8 동적 양자화면 2~3배 빨라질 수 있다(정확도는 재야 함).
ko-decision 꼴(선택지마다 한 번, 3번 계산)은 **약 3배 → p95 1.0초 자에 걸릴 위험**이 있다.

**3갈래 모델을 꽂을 때 고칠 자리**

## 6. 대안 비교

| 안 | 무엇 | 공수 | 좋은 점 | 위험 |
| --- | --- | --- | --- | --- |
| A. 길 1 기본 | klue/roberta-large 에 3갈래 머리 · KLUE-NLI + KorNLI 학습 → mem 덧학습 | 2~3.5일 | 반대 쌍이 수만 개 · 표준 꼴(한 번 계산) · 사이드카가 단순 | GPU 길이면 ROCm torch 설치·GPU 멎음 위험, CPU 길이면 KorNLI 일부만 |
| B. ko-decision 받아 덧학습만 | 이미 KLUE-NLI 90.7% 인 모델을 우리 1,230쌍으로만 더 학습 | 1~1.5일 | 기반 학습 생략 · 0번(무학습) 측정이 2~3시간에 출발점을 알려 준다 | 꼴이 「선택지마다 점수」라 추론 3배 · 학습 스크립트를 직접 짜야 함 · 1인 모델·자기 보고 · KorNLI 를 안 배움(모순 수 KLUE 의 약 8천뿐) |
| C. klue/roberta-base | A 와 같은 길을 0.11B 로 | 1.5~2.5일 | 학습·추론 약 3배 빠름 → CPU 로 KorNLI 10만 이상 가능 · ONNX 빠름 | KLUE-NLI 84.8~85.0 (large 89.2, KLUE 논문) — 기반 4점 낮음 |

- 셋 다 우리 자(0.85 · 0.75 · ≤3)에 닿는다는 근거는 없다. **B 의 0번(무학습 측정)은 어느 안을 고르든 싸게 출발점을 알려 준다.**

## 7. 위험 · 미정

| 위험 | 내용 | 무엇으로 줄이나 (설계 몫) |
| --- | --- | --- |
| 번역체 | KorNLI 는 기계 번역. 앞 조사가 옮긴 수치로 사람 넷이 모두 정답과 맞은 쌍 38%(KLUE-NLI 91%) — **원문 미확인** | KLUE-NLI 비중을 높이거나 KorNLI 는 표본만 |
| 라벨 뜻 차이 | NLI 「중립」은 같은 장면에서 참·거짓 모름이고, 우리 「무관」은 주제가 다른 쌍이 대부분(sscope·xscope 428/475). NLI 「함의」는 반드시 참 — 우리 지지는 요약·반올림 · 링크 문장도 지지로 친다 | 덧학습이 이 차이를 메워야 한다. 기반 모델만으로 재면 지지가 낮게 나올 수 있다 |
| 실물 반대 부족 | train 반대 294 중 flip 167 · 다시 씀 115 · 실물 덮음 8 — 실물 꼴 반대가 거의 없다 | NLI 모순이 일반 반대를 메우길 기대. 실물 반대는 측정에만 |
| 부정어 지름길 | NLI 모순의 상당수가 부정어를 넣어 만든 것 — 모델이 「부정어 = 반대」를 배운다. 규칙 층이 이미 잡는 꼴과 겹친다 | 측정 때 규칙 층이 안 잡은 반대만 따로 센다 |
| 거짓 지지 ≤ 3 | Laya v2 는 반대를 지지로 본 14쌍이 거짓 지지 대부분이었다. 모델 정확도만으로 3 아래는 어렵다 | 길 2 확신 문턱(지지는 높은 문턱 · 모르면 C/보류) 로 맞출 일 |
| dev 낙관 | dev 기억 131개 중 115개가 train 에도 쓰였다 | epoch·온도 고르기는 dev, 판정은 game90 한 번만 |
| game90 미확정 | 사람 확인 17건 남음 · FROZEN 안 함 | 측정 전에 끝낸다 |
| GPU 학습 | gfx1151 torch 는 야간·남이 만든 판 · 멎으면 재부팅만 됨 | 처음 판은 사람이 있을 때, 게임 서버 내린 때 |
| 메인 PC 상태 | `laya-v2` 서빙 폴더 · `venv-train` 이 없어짐 | 메인이 경위 확인 |

**설계에서 정할 것**

1. 기반 : A(large) · B(ko-decision) · C(base) 중 무엇. 0번(ko-decision 무학습 측정)을 먼저 할지.
2. 학습 기계 : 미니PC GPU(ROCm torch 설치 승인 · 어느 판) · 미니PC CPU · 컨테이너 안 torch 재사용.
3. KorNLI 몫 : 전부 · 10만 · 2~5만 / KLUE 와 섞기 vs 이어서.
4. 덧학습 방식 : 기반 위에 mem 만 · mem + NLI 일부 섞어 (잊음 막기) / epoch · lr.
5. 라벨 매핑 : 중립 → C 그대로 둘지, 덧학습에서 뜻을 바꿀지.
6. `max_len`(256 안) · 긴 근거 자르는 쪽.
7. 온도 맞추기 셋(dev 100 은 train 과 기억이 겹침) · 측정 자는 앞 판 그대로(정확도 ≥0.85 · 반대 ≥0.75 · 거짓 지지 ≤3 · p95 ≤1.0초).
8. 사이드카 : `serve.py` 에 backend 갈래 추가 vs 새 파일 · 설정 칸 이름 · `LayaVersion` 새 이름 · int8 양자화 여부.
9. 내려받기 승인 범위 : klue/roberta-large 1.35GB · KLUE-NLI · KorNLI 학습 셋 · (B 면) ko-decision 1.35GB.
