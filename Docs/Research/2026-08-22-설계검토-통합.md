원본 보고서 5개는 같은 폴더의 `2026-08-22-설계검토-A-설계구조.md` `2026-08-22-설계검토-B-검색품질.md` `2026-08-22-설계검토-C-사용성기능.md` `2026-08-22-설계검토-D-운영견고성.md` `2026-08-22-설계검토-E-외부동향.md`.
**코드 버그는 다른 에이전트가 맡고 있어 여기서는 설계·기능·운영 관점만 봤다.** 프로젝트 파일은 하나도 안 고쳤다.

## 한 줄 결론

**뼈대는 맞다.** 바깥(Letta·mem0·Zep·Claude auto-memory 등)과 견줘도 "싼 저장 + 진짜 검색" 자리는 비어 있던 자리고, LLM 0·MCP 없음·임베딩 없음 결정은 2026년 자료로도 뒷받침된다.
**문제는 세 덩어리에 몰려 있다.**

1. **"설계에는 있는데 코드에 없는 것"** — hit_count(사용 빈도) 아무도 안 올림, gc 한 번도 안 돎, severity 읽는 곳 0, pin 상한 없음, `add` 가 id 안 줌, howto 가 접힘, lint --fix 가 락 없이 씀.
2. **"시간이 지나면 터지는 것"** — gc 면제 78% 라 잡음 무한 증가, 아카이브가 git 바이너리로 매 커밋 새 blob + 병합 불가, gc 가 지운 파일이 `git pull` 로 되살아남, 락 남으면 10분 침묵, reindex 하면 통계 0, clone 하면 `updated_at` 순서 붕괴.
3. **"AI 가 자연스럽게 하는 행동이 조용히 실패하는 것"** — `mem search "훅 성능"` 따옴표 → 구절 검색 0건, 한영 섞인 구절 절대 못 맞춤, 붙여 쓴 한글(`기억품질`) 0건, 한 글자 낱말 26% 유실, `--status` 조용히 무시, 결과 총계 없음, 주입 블록이 세션과 무관(쓸모 25%), README add 예시가 거절됨.
