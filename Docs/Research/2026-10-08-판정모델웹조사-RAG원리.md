# 판정 모델 웹 조사 — RAG 실무 · 판정 원리 · 자료 만드는 법

> 2026-10-08 · `mem judge`(지지 A / 반대 B / 무관 C)를 서버 없이 돌릴 길을 찾는 조사 셋 중 하나.
> 이 문서는 **제품·프레임워크 실무, 판정 원리, 반대 자료 만들기, 2단 구조**를 맡는다. 논문·저장소 조사는 다른 문서가 맡는다.

## 결론 먼저

1. **상용 RAG 검사기는 거의 다 2갈래다.** 「받쳐짐 / 안 받쳐짐」만 가르고, 반대(모순)와 무관을 나누지 않는다 (AWS · Google · Azure · HHEM). 우리 A/B/C 3갈래와 딱 맞는 건 **NLI(자연어 추론) 3갈래 분류기**다 — 함의 / 모순 / 중립.
2. **기억 제품(Mem0 · Zep)은 충돌 판정을 큰 LLM 에 맡긴다.** Mem0 는 GPT-4o-mini 도구 호출로 ADD/UPDATE/DELETE/NOOP 을 고른다. 서버(또는 API) 없이 도는 기억 제품의 충돌 판정은 못 찾았다.
3. **서버 없이 도는 작은 판정기는 실무에 많다.** HHEM-2.1-Open(110M, CPU 2k 토큰 1.5초), MiniCheck(355M~770M, GPT-4 급), AlignScore(355M), Galileo Luna(440M). 다 **수십만 쌍의 공개 NLI·합성 자료**로 먼저 배우고 나서 좁은 일에 맞췄다.
4. **우리 뿌리 문제(반대 자료가 적다)의 실무 답은 「공개 한국어 NLI 로 먼저 배우기」다.** KorNLI 학습 942,854쌍 · KLUE-NLI 24,998쌍에는 모순 쌍이 약 1/3 씩 들어 있다. 한 한국어 소설 모순 검출 저장소는 이 둘로 `klue/roberta-base` 를 1번 돌려 **모순 재현 0.47 → 0.82, CPU 쌍당 약 15ms** 를 냈다(평가 150쌍 · 같은 셋으로 고르고 잼 — 낙관 값).
5. **「Jev」는 실제 있는 도구다.** TypeSafe AI 의 「글을 안 쓰고 정답칸 확률만 내는」 판정 모델이다. 원리는 우리 SemIf(첫 토큰 확률로 A/B/C)와 같고, **확신이 높으면 받고 낮으면 큰 모델로 넘기는** 2단 구조를 권한다. 다만 **API 전용 · 가중치 비공개 · 로컬 실행 안 됨** 이라 우리 「서버 없이」에는 못 쓴다. 원리만 가져온다.

### 추천 순위 (서버 없이 A·B 까지)

| 순위 | 길 | 무엇을 하나 | 공수 어림 |
| --- | --- | --- | --- |
| 1 | **한국어 NLI 먼저 → mem 쌍으로 덧학습** | KorNLI + KLUE-NLI 를 **섞어서** 3갈래 학습 → mem 1,230쌍을 얹어 덧학습 → ONNX CPU | 1.5~2.5일 |
| 2 | **3단 캐스케이드 + 「보류」 칸** | 규칙(Go) → 작은 NLI → 확신 낮으면 SemIf(서버 있을 때) / 없으면 보류. 문턱은 K·game90 으로 맞춤 | 1~1.5일 (1 뒤) |
| 3 | **큰 모델로 반대 자료 늘리고 증류** | 실물 반대 수십 개를 씨앗으로 Opus·Qwen 이 비슷한 반대를 만들고, 큰 판정기로 거르고, 사람이 일부 고침. 작은 모델이 헷갈린 쌍만 큰 모델이 이름표 | 3~5일 |

**공통점 셋.**
- **처음부터 좁은 자료로만 배운 모델이 없다.** HHEM·AlignScore 는 공개 NLI·사실 검증 자료 수십만 쌍, MiniCheck 은 ANLI 21K + 합성 14K 로 먼저 배웠다.
- **2갈래가 대세다.** 「받쳐지나」만 물으면 반대 자료가 따로 많이 필요 없기 때문이다. 3갈래를 쓴 곳은 AlignScore 하나이고, 그쪽도 NLI 공개 자료를 썼다.
- **한국어 공개판이 없다.** 그대로 가져다 쓸 수는 없고, 한국어 바탕 모델에 같은 방법을 얹어야 한다.

### 1-3. 평가 프레임워크 (Ragas · DeepEval · TruLens · LlamaIndex)

| 프레임워크 | 방식 | 모델 |
| --- | --- | --- |
| Ragas faithfulness | ① LLM 이 답을 짧은 주장들로 쪼갬 ② 주장마다 근거에서 나오나 0/1 ③ 평균 | 큰 LLM. **②만 HHEM 으로 바꿀 수 있다** (Ragas 공식 문서) |
| DeepEval faithfulness | 주장 쪼개기 → 주장마다 yes / no / idk → 받쳐진 비율. **반대(no)를 잡는 데 무게** | 큰 LLM |
| TruLens groundedness | 근거 조각과 답을 넣고 생각 사슬 + 0~1 점수 | 큰 LLM |
| LlamaIndex FaithfulnessEvaluator | YES / NO 한 번. 출력에 「yes」가 들어 있으면 통과 | 큰 LLM |

**우리에게 주는 뜻.** 프레임워크는 다 큰 LLM 판정기다. 쓸 만한 건 둘이다.
- **DeepEval 의 yes / no / idk 3칸**이 우리 A / B / C 와 같은 모양이다. idk(모름)를 따로 둬서 「반대」와 「근거 없음」을 나눈다.
- Ragas 가 **판정 단계만 작은 분류기로 갈아끼우는 길**을 공식으로 열어 뒀다. 큰 LLM 은 쪼개기에만 쓴다.

### 1-4. 에이전트 기억 제품은 충돌을 어떻게 판정하나

| 제품 | 충돌 판정 | 모델 | 서버 없이 |
| --- | --- | --- | --- |
| Mem0 | 새 사실과 비슷한 기억 10개(s=10)를 꺼내 LLM 이 도구 호출로 ADD / UPDATE / DELETE / NOOP 중 고름. DELETE = 모순 | GPT-4o-mini (논문: 「모든 LLM 작업」) | ✗ |
| Mem0g (그래프판) | 충돌 감지 → LLM 갱신 판정기가 낡은 관계를 **지우지 않고 무효 표시** | GPT-4o-mini | ✗ |
| Zep / Graphiti | 새 간선과 뜻이 비슷한 기존 간선을 LLM 이 비교해 모순 찾음 → 옛 간선의 무효 시각 = 새 간선의 유효 시각. **늘 새 정보 우선** | LLM | ✗ |
| Letta (MemGPT) | 에이전트가 스스로 기억 블록을 고쳐 씀. 따로 충돌 판정 단계가 문서에 없음 | 에이전트 LLM | ✗ |

알려진 약점도 있다.
- Memory-R1 논문: Mem0 기본 관리자가 모순이 아닌 걸 모순으로 보고 DELETE+ADD 를 내 기억을 쪼갠다.
- Graphiti 이슈 #1728: 사실 문장만 넘겨 **같은 대상에 대한 말인지** 모른 채 판정하고, 판정을 검사하는 장치도 없다.

**우리에게 주는 뜻.** 기억 제품 쪽에는 「서버 없이 충돌 판정」 선례가 없다. 그리고 큰 LLM 도 「같은 대상이냐」를 놓치면 틀린다. 우리 규칙 층의 「같은 자리 숫자」처럼 **같은 대상인지 먼저 맞추는 단계**가 판정 품질에 크다.

## 2. 판정(judge / verifier) 원리

### 2-1. LLM 판정이 왜 맞나

큰 LLM 은 많은 글에서 「이 말이 저 말에서 나오나」를 이미 배웠다. 판정은 그 능력을 **고르기 문제**로 꺼내 쓰는 것이다. 방식은 셋이다.

| 방식 | 하는 일 | 장점 | 단점 |
| --- | --- | --- | --- |
| **첫 토큰 확률** (우리 SemIf · Jev · G-Eval) | 정답칸(A/B/C) 토큰 확률을 바로 읽음 | 빠름 · 확신 숫자가 공짜로 나옴 | 확률이 0.8 위·0.2 아래로 몰려 **지나치게 확신** (쌍 비교 연구) |
| **채점표** (G-Eval · TruLens) | 기준을 주고 1~5점. 확률로 가중 평균 | 미세한 차이 표현 | G-Eval 에서 확률 가중의 이득은 Spearman 0.514 vs 0.502 로 작음 (블로그 2차 인용) |
| **쌍 비교** (RewardBench 류) | 두 답 중 나은 것 | 사람 선호와 잘 맞음 | **순서 편향** — 순서를 바꾸면 판정이 바뀜 |

### 2-2. 「Jev」 — 있는 도구다

| 항목 | 값 (원문: arXiv 2609.26550 · MLflow 블로그) |
| --- | --- |
| 만든 곳 | TypeSafe AI |
| 성격 | 글을 생성하지 않음. 정해진 칸 중 하나와 칸별 확률만 냄 (「System One」 모델) |
| 크기 · 가중치 | 비공개 · API 전용 |
| 확신 | q = 칸 확률 중 최댓값 |
| 2단 규칙 | q ≥ τ 면 받고, 아니면 큰 판정기로 넘김 |
| HaluEval (근거 있는 판정) | Jev 87.5 vs GPT-6 86.7 → 「Jev 써도 됨」 |
| JudgeBench (어려운 정답 판정) | 78.6 vs 93.1 → 「넘겨라」 |
| 근거 없는 글 판정 | 52.5 · 오류 AUROC 0.518 → 「지원 안 함」 |
| τ = 0.9 캐스케이드 | 53.7% 를 Jev 가 받음 · 92.5% vs GPT-6 93.1% · 비용 56.8% |
| 확신별 정확도 | q < 0.6 에서 47.7% · q = 1 에서 99.1% |
| 순서 바꾸면 판정 바뀜 | RewardBench 3.25% · JudgeBench 11.14% |
| 온도 보정 | 자료마다 방향이 달라 **옮겨지지 않음** (HaluEval 좋아짐, 나머지 나빠짐) |
| 값 | 1,000번에 $0.044 · 중앙 지연 0.152초 |

참고로 같은 줄기의 논문(arXiv 2610.02516)은 「TypeSafe 의 Jev 와 오픈소스 Laya 프로젝트」를 같은 종류(인코더 분류기 System-1)로 묶는다.

**우리에게 주는 뜻.**
- Jev 의 강점은 **「근거가 주어진 판정」**이고, 약점은 「풀어서 따져야 하는 판정」이다. 우리 judge 는 근거가 주어진 쪽이라 작은 판정기에 맞는 일이다.
- **확신이 낮은 구간(q < 0.6)은 거의 동전 던지기**다. 그 구간을 큰 모델로 넘기거나 보류하는 게 핵심이다.
- 보정값(온도)은 자료가 바뀌면 안 맞는다. **문턱은 우리 실물 셋으로 직접 맞춰야 한다.**

### 2-3. 작은 모델로 가면 무엇이 무너지나

| 무너지는 것 | 근거 |
| --- | --- |
| 사람과의 맞음 | 「Judging the Judges」: 판정기 13개 중 **가장 크고 좋은 것만** 사람과 쓸 만큼 맞음. 그래도 최대 5점 차 |
| 너그러움 편향 | 같은 논문: 작은 판정기는 「맞다」 쪽으로 기움 → 우리 말로 **거짓 지지** |
| 순서·문체 | Jev: 꾸민 글이 붙으면 정확도 74.8% 로 떨어짐 (GPT-6 94.6%) |
| 확신 숫자 | 첫 토큰 확률이 양끝에 몰림. 작은 모델일수록 확신 숫자로 오류를 덜 잡음 (Jev JudgeBench AUROC 0.745 vs GPT-6 0.907) |

우리 Laya 의 「거짓 지지 16건」은 이 「너그러움 편향」과 같은 모양이다.

### 2-4. 여러 표 합치기 · 자기 일관성

| 방법 | 수치 |
| --- | --- |
| PoLL (작은 모델 셋의 배심) | 6개 자료 · 3가지 판정 설정에서 큰 판정기 하나보다 낫고 7배 넘게 쌈 (Cohere) |
| Trust or Escalate 의 「모의 평가자」 | 여러 가상 평가자의 표가 엇갈리는 정도를 확신으로 씀 → 단일 확률보다 보정·실패 예측이 좋아짐 |
| Jev 두 순서 평균 | 순서를 바꿔 두 번 보고 확률 평균 → 문턱 판단 전 순서 편향 줄임 |

**우리에게 주는 뜻.** 서버 없이 쓸 수 있는 「표 합치기」는 **규칙 층 + 작은 NLI + (근거·주장 순서 바꿔 한 번 더)** 정도다. 근거와 주장을 바꿔도 반대는 반대로 남아야 한다. 이건 반대 판정의 싼 검사로 쓸 수 있다 (내 추론, 원문 근거 없음).

## 3. 반대 자료가 적을 때 자료 만드는 법

### 3-1. 실무 사례

| 사례 | 어떻게 만드나 | 크기 | 결과 |

### 3-2. 만든 반대가 실패하는 까닭 (우리가 겪은 것)

- 2026 검색 연구: LLM 이 만든 어려운 반례는 **뻔하거나 주제가 새는** 글이 되기 쉽고, 만든 티(분포 차이)로 모델이 「만든 것」을 알아본다.
- 코드 임베딩 연구: LLM 이 만든 어려운 반례로 학습하면 **실물에서 캐낸 반례보다 크게 나빠졌다.**
- 우리 「숫자 바꾸기 · 부정 넣기」가 실물에 안 통한 것과 같은 모양이다. **기계적 변형은 규칙 층이 이미 잡는 종류**라, 모델에 가르쳐도 새로 배우는 게 없다 (내 해석).

그래서 실무는 둘을 지킨다.
1. **씨앗은 실물에서** 고른다 (WANLI). 우리는 실물 반대 수십 개가 씨앗이다.
2. **큰 판정기로 거르고 사람이 일부 고친다** (MiniCheck 의 GPT-4 확인 · WANLI 의 사람 고침).

### 3-3. 증류 · 능동 학습

| 방법 | 하는 일 | 근거 |
| --- | --- | --- |
| 큰 판정 → 작은 모델 증류 | 큰 모델 이름표로 작은 분류기 학습 | MiniCheck(GPT-4 판정 자료 → 770M) · Luna |
| 능동 학습 | 작은 모델이 가장 헷갈린 쌍만 큰 모델에 이름표 요청 | LLM on a Budget (2511.11574) |
| 학생이 후보 좁히고 선생이 재정렬 | 작은 분류기가 후보를 좁히고 큰 NLI 가 이름표 → 학생 다시 학습 | 2610.02516 (선생 일치 77.5%, 200개 · 진행 중) |

### 3-4. 우리 조건에 맞춘 순서 (큰 모델은 가끔 · 실물 반대 수십 개)

1. **공개 한국어 NLI 로 3갈래 바탕 모델을 만든다.** 반대 부족이 여기서 거의 풀린다.
2. **그 모델로 mem 전체 쌍을 돌려 「반대 같다」 상위 쌍을 캐낸다.** 사람이 쓴 반대는 드물지만 캐내면 수십 → 백 단위로 는다 (예상, 실측 필요).
3. 캐낸 쌍 · 헷갈린 쌍만 **SemIf(Qwen)로 이름표**, 엇갈리면 Opus 로 한 번 더. 사람이 반대만 훑는다.
4. 실물 반대를 씨앗으로 **WANLI 식 생성**: Opus 에게 「이 반대와 같은 꼴로 다른 기억 문장의 반대를 써라」. SemIf 로 거르고 사람이 일부 고친다.
5. 공개 NLI + mem 쌍을 **섞어서** 덧학습 (이어서 학습하면 좁은 셋에 맞추다 일반화가 무너진다 — 위 순서 실험).

## 4. 2단 구조(캐스케이드) 실무

| 사례 | 구조 | 수치 |
| --- | --- | --- |
| Trust or Escalate (ICLR 2025) | 싼 판정기 → 확신 낮으면 더 센 판정기. **작은 보정 셋으로 문턱을 정해 「사람과 맞음 ≥ 목표」를 보장** | Chatbot Arena: 80% 넘는 사람 맞음 · 표본 79.1% 처리 · 그 중 88.1% 를 Mistral-7B·GPT-3.5 가 처리 · 약한 줄도 GPT-4 비용의 12.6% |
| Jev 캐스케이드 | q ≥ 0.9 면 받음 | 위 표 (53.7% 받음 · 정확도 거의 유지) |
| AWS · Google | 문턱 하나로 막기 | AWS 예시 0.85 · Google 기본 0.6 |

**설계 요령 넷.**
1. **문턱은 보정 셋으로 정하고 얼린다.** Jev 논문도 「점수 보고 정한 문턱」과 「미리 얼린 문턱」을 나눠 보고했다. 우리는 K 48 로 정하고 game90 으로 확인한다 (또는 그 반대).
2. **칸마다 문턱을 다르게 둔다.** retain 에서 거짓 지지가 가장 비싸다 → **A 는 높은 문턱**, 못 넘으면 넘기거나 보류. B 는 놓쳐도 다음 검사에서 다시 볼 수 있으니 조금 낮게.
3. **넘길 곳이 없을 때는 「보류」가 답이다.** 서버가 없으면 큰 판정기 대신 「보류 — 사람이 보거나 서버 있을 때 다시」로 둔다. Trust or Escalate 도 판정 안 함(abstain)을 정식 칸으로 둔다. `mem add --hold` 와 이미 맞물린다.
4. **처리율(커버리지)을 같이 잰다.** 정확도만 보면 다 보류해도 100% 다. 「작은 모델이 몇 %를 맡았나」를 꼭 같이 적는다.

## 추천 자세히

### 1위 — 한국어 NLI 먼저 → mem 쌍 덧학습 (1.5~2.5일)

- **왜:** 실패의 뿌리가 「반대 자료 부족」인데, 공개 한국어 NLI 에 모순 쌍이 수십만 개 있다. 실무 작은 판정기(HHEM · MiniCheck · AlignScore)도 모두 공개 NLI 로 먼저 배웠다. 한국어 사례에서 모순 재현이 0.47 → 0.82 로 올랐다.
- **어떻게:** KorNLI 학습셋 + KLUE-NLI 학습셋을 섞어 3갈래 학습 → mem 1,230쌍을 섞어 덧학습 → ONNX 로 CPU. 바탕은 `klue/roberta-base` (또는 KLUE-NLI dev 88.37 이 보고된 `kakaobank/kf-deberta-base`).
- **주의:**
  - **라이선스** — KorNLI 학습셋 · KLUE-NLI 는 CC BY-SA 4.0, KorNLI dev/test 는 원본 XNLI 라 CC BY-NC 4.0 (비상업). 툴킷 공개 계획이 있으면 dev/test 는 빼고, BY-SA 가 학습한 가중치에 어떻게 걸리는지는 따로 확인해야 한다.
  - KorNLI 는 기계 번역이라 이름표 질이 낮다 (네 평가자가 모두 정답과 맞은 쌍 38%. KLUE-NLI 는 91.00%).
  - 소설 사례는 평가 150쌍을 고르기와 보고에 같이 써서 낙관 값이다. 우리 game90 으로 다시 재야 한다.
- **목표 대비 예상:** 반대 재현 0.75 는 닿을 가능성이 있다. 거짓 지지 ≤3 은 이것만으로는 어렵다 → 2위와 같이 간다.

### 2위 — 규칙 → 작은 NLI → SemIf / 보류 캐스케이드 (1~1.5일, 1위 뒤)

- **왜:** Jev·Trust or Escalate 모두 「확신 높은 것만 받고 나머지는 넘김」으로 큰 판정기 정확도를 거의 지켰다. 서버가 없으면 넘길 곳을 「보류」로 바꾼다.
- **어떻게:** 규칙 층(지금 K 48 중 20쌍 · 틀림 0)을 맨 앞에 → 작은 NLI 확률 → A 는 높은 문턱(예: 0.9), B·C 는 각자 문턱 → 못 넘으면 서버 있으면 SemIf, 없으면 보류. 문턱은 K 48 로 정하고 game90 으로 확인. 근거·주장 순서를 바꿔 한 번 더 보고 반대가 유지될 때만 B.
- **잴 것:** 정확도 · 반대 재현 · 거짓 지지 · **처리율**.

### 3위 — 큰 모델로 반대 자료 늘리고 증류 (3~5일)

- **왜:** 1·2 로 반대 재현이나 거짓 지지 목표에 못 닿을 때, 실물과 닮은 반대를 늘리는 길이다. WANLI·MiniCheck 이 같은 방법으로 작은 모델을 크게 올렸다.
- **어떻게:** 3-4 의 2~5단계. 큰 모델 호출은 「캐낸 쌍 · 헷갈린 쌍 · 생성한 쌍 거르기」에만 쓴다.
- **주의:** 만든 반대만 많으면 만든 티로 배운다. **실물 씨앗 · 큰 판정기 거름 · 사람 고침** 셋을 다 지킨다. 섞어서 학습한다.

## 확인 못 한 것

- KorNLI · KLUE-NLI 의 정확한 갈래 비율은 원문에서 숫자로 확인하지 않았다 (「약 1/3」 은 3갈래 균형 설계에서 나온 어림. KLUE 논문은 dev/test 가 갈래 균형이라고만 적음).
- 소설 모순 검출 사례는 개인 저장소 PR 한 건이다. 실무 근거로는 약하다.
- 한국어로 공개된 MiniCheck·HHEM 급 판정 모델은 찾지 못했다.
- Cleanlab 의 실시간 RAG 판정기 비교 논문(2503.21157)은 PDF 를 못 읽어 수치를 못 옮겼다.
- Jev 수치는 거의 다 회사 쪽 또는 최근(9~10월) 발표다. 독립 재현은 없다.
