# 모음 기억 B1 측정 — 규칙 판 `mem consolidate`

> 2026-10-05 · Opus 서브에이전트 · 설계 `Docs/Design/2026-10-05-자동쌓기와모음기억설계.md` 3절 · 5절 B1 줄 · 6절.
> B1 전 exe 와 B1 exe 를 스튜디오 기억 사본(833건)에서 비교했다. 카드는 사본에만 썼다.

## 0. 결론 먼저

1. **회귀 0.** 모음 기억(카드)이 0건인 저장소에서는 B1 전후의 검색 결과가 같다. 여섯 셋, 두 모드(의미·낱말)의 모든 질의에서 got · all · 순위 · 칸 · wide · 밀림이 같다. 토큰 수만 ±1 차이가 난다. 머리말에 들어가는 걸린 시간(ms) 자릿수 때문이다.
2. **판정 : B1 줄에 못 미친다.** 카드를 의미 모드 60장, 낱말 모드 37장 넣었다.
   - multisession 은 새 자로 재도 **+0건**이다 (자는 +2건).
   - 낱말 모드 v3 옛 자 r@5 는 **-1건**이다. 카드가 원본 1건을 접어 넣었다.
   - G2 와 probe strict 오답률은 나빠지지 않았다.
3. **까닭 : 코드 규칙이 못 잇는 짝이다.** v3 에서 놓친 multisession 질의의 정답 두 건을 한 묶음에 함께 담은 카드가 거의 없다 (0/2, 한 질의만 1/2). 덮음 사슬·링크·같은 scope 뜻 무리로는 서로 다른 주제를 가로지르는 짝을 못 묶는다.
4. **권고 : 카드를 검색 기본에 섞지 않는다.** 실제 저장소에 카드를 늘 써 두는 흐름(훅·정기 실행)을 만들지 않고, `mem consolidate` 는 사람이 손으로 돌리는 도구로만 둔다. 저장소에 카드가 없으면 검색은 B1 전과 똑같다. 그래서 「안 돌리면 손해 0」이다. 쓴 카드는 검색에 뜬다 — 검색에서 카드를 빼는 손잡이는 아직 없다 (다음 판 몫).
5. **묶음 자체의 질은 쓸 만하다.** 20개를 골라 읽으니 맞음 15 · 애매 5 · 틀림 0 이다. 애매한 것은 한 툴 안의 두 갈래 주제를 하나로 묶은 넓은 무리였다.
6. **빠르다.** 893건에서 `consolidate --plan` 명령 전체가 약 0.15초다. 카드를 넣어도 검색 p50 은 거의 그대로다.

### 3-3. strict 손잡이

`obs_strict_full = true` (카드는 칸 0·1 에서만 strict) 로도 같은 판을 돌렸다. 두 모드 모두 **결과가 기본과 같았다.** 카드가 칸 2 이하로만 맞은 질의가 없었다. 기본은 꺼 둔다.

## 4. 손 흐름

낱말 사본에서 손으로 돈 순서다. 전체 출력은 측정 로그에 있다.

1. `mem consolidate --plan --rule link` → 묶음 3개, 12건 넘는 무리 8개는 건너뜀.
2. `--apply --rule link --max 1` → 카드 1건. 되돌리는 명령을 같이 알려 준다.
3. `mem search "lint 새 파일 검사"` → 카드가 4위. 아래에 `↳ id 제목` 세 줄과 `… 외 4건`. 머리말은 「상위 5건」(근거 줄은 안 센다).
4. 근거 1건의 요약을 `mem set` 으로 고침 → `--type observation` 검색에 `[낡음]`.
5. `--plan` → 「다시 · (근거가 바뀜)」.
6. `mem auto undo --origin card --apply` → 카드가 보류로 돌아가 검색에서 사라짐. 파일은 남는다.

`mem lint` 에는 C15 `obs-stale` 로 낡은 카드가 뜬다.

## 6. 측정 뒤에 고친 것 — lint 소음

카드를 넣은 사본에서 `mem lint` 가 카드 때문에 걸림을 늘렸다. 짧은 사슬 카드의 본문 3줄 규칙, 원본과 닮음(중복), 원본 이웃 셈(link-missing) 따위다. 카드는 원본을 옮겨 적은 글이라 늘 걸린다. 그래서 고쳤다.

- 카드에는 본문·중복 규칙 13개를 안 건다. 카드 글 모양은 B13 `obs-cite` 가 본다.
- 중복 표 · link-missing · notation-drift 셈에서 카드를 뺀다.

고친 뒤 결과 : 카드 37장 사본의 걸림이 카드 0장 사본과 같다. 다른 것은 저장소 단위 `tag-too-broad` 1건뿐이다 (카드도 태그를 달아서 한 태그의 비율이 넘었다). 카드 0장 사본의 lint 결과는 고치기 전후가 같다.

이 손질은 검색 코드를 안 건드린다. 3절 숫자는 그대로 유효하다.

## 7. 재는 법

- 사본 : 스튜디오 `Memory/` 를 얼려 두고 판마다 복사. 의미 모드는 ko 모델이 깔린 시험 홈, 낱말 모드는 빈 시험 홈.
- 셋 : `testdata/golden/` 의 v2 · v3 · v4 · abstain-probe · fresh · fresh-b.
- 명령 : `mem index --full`, `mem eval --no-index --json --golden <셋>`. 새 자는 eval JSON 의 `results[].obs_rank` 로 센다.
- 카드 넣기 : `mem consolidate --apply` (모든 묶음).
