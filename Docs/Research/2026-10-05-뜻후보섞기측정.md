> 기억 전체 벡터에서 뜻이 가까운 것을 따로 데려와 낱말 후보와 RRF 로 섞었다. 스튜디오 기억 사본(830건)에서 C2 전 exe 와 C2 exe 를 견줬다.
> 같은 날 2차 판(7절) : 두 몫을 더하지 않고 큰 쪽 하나만 쓰는 규칙을 미리 정해, 두 번째 눈가림 셋 fresh-B 로 한 번 판정했다.

## 0. 결론 먼저

> 2차 판(7절)까지 반영한 결론이다. 1차 판 결론은 바로 아래 「1차 판」에 그대로 둔다.

0. **최종 : 기본 끔 (`[embed] mix = false`, 켜면 바닥 0.58 · 뜻 순위 3).** 한때 0.58 로 켰다가(8절) 헛답이 늘어, 사용자 결정대로 바닥 0.60 으로 조여 다시 쟀다(9절). probe 헛답 15 → **16**/29 · fresh-B 답 없음 abstain 2 → **0**/9 라 미리 정한 기준 넷 중 둘을 못 채워 껐다.
1. **판정 : 2차 판도 자 다섯 중 셋만 넘는다. 기본은 끈 채 둔다 (`[embed] mix = false`).** 코드는 2차 규칙으로 바꿔 둔다.
2. **1차의 흠은 고쳤다.** 두 몫을 더하지 않고 **큰 쪽 하나**만 쓰니 낱말 상위 답이 안 밀린다. 새 눈가림 셋 fresh-B(답 있음 34)에서 밀림 **0**, 1차 판은 같은 셋에서 −2(25 → 23)였다.
3. **오르는 폭이 모자란다.** fresh-B r@5 25 → **27 (+2)**, v3 51 → **53 (+2)**. 미리 정한 자는 둘 다 +3 이다. 개발 셋 fresh-A 에서는 14 → 19 (+5) 였다 — 개발 셋으로 손잡이를 고른 만큼은 새 셋에 덜 옮겨 갔다.
4. **헛답은 늘어난다.** probe strict 답 15 → 18/29 (1차 17), fresh-B 답 없는 질문 7 → 9/9 (1차도 9). 22/29 는 안 넘었다.
5. **끄면 · 낱말 모드면 C2 전과 건마다 같다.** v2 · v3 · v4 · probe · fresh-A 모두 0건 다름.
6. **몸통 결론 : 「어느 쪽도 아님」에 가깝다.** fresh-A 에서 순수 뜻 r@5 는 ko-v2 17 · e5-base 18 · bge-m3 17 /26 으로 몸통을 키워도 거의 같다. 지금 몸통으로 순수 뜻(17)을 넘는 19 까지는 왔다. 남은 실패는 「여러 일을 한 기억 속 한 문장」·「다른 이름으로 부른 것」(7-1)이라 몸통보다 기억 글 모양 쪽 문제다. 헛답을 막는 관문 없이 켤 근거는 없다.

### 1차 판 결론 (그대로 둠)

1. **판정 : 자 다섯 중 셋만 넘는다. 기본은 끈다 (`[embed] mix = false`).** 코드는 남긴다. 켜면 아래 값으로 돈다.
2. **골든셋에서는 오른다.** 의미 모드 v3 r@5 51 → **54 (+3)**, v2 47 → 49 (+2), v4 52 → 55. MRR 0.568 → 0.632. 오른 것은 update · paraphrase · temporal 이다.
3. **처음 보는 질문 셋(fresh 26문항)에서는 안 오른다.** r@5 14 → 14 (+0). 살아난 2건과 밀린 2건이 같다. 밀린 2건은 **낱말 1·2위였던 정답이 10위 밖으로** 나갔다. 손잡이를 골든셋으로 고른 만큼이 새 질문에는 안 옮겨 갔다.
4. **헛답은 2건 는다.** 답 없는 질문(probe) strict 답 15/29 → 17/29. 골든셋 안의 답 없는 질문은 v3 1/10 → 3/10.
5. **끄면 C2 전과 건마다 같다.** 낱말 모드는 켜도 같다 (모델이 없으면 섞기가 안 돈다). 의미·낱말 × v2·v3·v4·probe·fresh 모두 id · 순위 · 칸 · 넓힌 순위까지 0건 다름.
6. **권고 :** 지금 몸통(ko-v2)으로는 켜지 않는다. 다음 판은 ① 낱말 상위 답을 지키는 섞기(낱말 1~3위 자리 보장 같은 규칙)를 **골든셋으로 고르지 말고** 미리 정해 fresh 로 한 번 재거나, ② 진단 문서의 bge-m3 몸통과 같이 잰다.

## 6. 어떻게 쟀나

- 사본 : 스튜디오 기억 830건 사본 · 색인과 벡터는 C2 전 exe 로 한 번 만들고 두 exe 가 같이 썼다. 의미 모드 홈(ko-v2 + onnxruntime)과 빈 홈(낱말 모드) 둘.
- exe : C2 전 = 코드 고치기 전 작업 트리 빌드 · C2 = 이 판 `bin\mem.exe`.
- 손잡이 고르기는 시험용 뒷문 `MEM_MIX` · `MEM_MIX_FLOOR` · `MEM_MIX_RANK` · `MEM_MIX_TOP` · `MEM_MIX_WEIGHT` · `MEM_MIX_K` 로 같은 exe 에서 판만 바꿨다. v3 · v4 · v2 · probe 로만 골랐다.
- 골든셋 v4 = v3 에서 의심스러운 정답 셋을 고친 판 (`testdata/golden/goldenset-v4.yaml` 머리말).
- 스크립트·로그 : 스크래치 `memmix\` (`run.sh` · `sum.py` · `same.py` · `brief.py` · `wall.py` · `logs\`).

## 7. 2차 판 — 미리 정한 규칙

> 2026-10-05 · fresh-B(`testdata/golden/fresh-b-2026-10-05.yaml`)를 **한 번도 돌리기 전에** 적었다.
> 손잡이 값은 v3 · v4 · v2 · fresh-A 로만 고른다. fresh-B 는 맨 끝에 전 · 1차 · 2차를 한 번씩만 잰다.

1차의 흠은 **두 목록에 다 든 후보가 두 몫(합)을 받아** 낱말 상위 답을 밀어낸 것이다. 그래서 2차는 더하지 않고 **나은 쪽 하나만** 쓴다.

1. **낱말 차례는 C2 전 그대로다.** 섞기가 돌아도 사다리 안의 옛 재정렬(뜻으로 낱말 후보 차례 바꾸기)은 그대로 돈다.
2. **뜻 후보는 뜻 순위 `mix_rank` 안 · 코사인 `mix_floor` 이상인 것만 쓴다.** 나머지 뜻 순위는 아무 몫도 없다.
3. **한 후보의 점수는 두 몫 중 큰 쪽이다 (더하지 않는다).** 낱말 j 위는 `1/(k+j)`, 뜻 p 위는 `w/(k+p)`. 같으면 낱말 쪽이 앞이다. 같은 무게(w = 1)에서는 「뜻 p 위 후보는 낱말 p 위 바로 뒤로 올라온다」와 같다. 낱말 j 위 답 앞에는 뜻 1~(j−1) 위만 끼어들 수 있으므로 **낱말 j 위는 섞은 뒤 2j−1 위보다 뒤로 안 간다** (1위는 1위 · 3위는 5위 안).
4. **낱말 상위 `mix_keep` 건은 자리를 지킨다** — 섞은 뒤에도 원래 자리보다 뒤로 안 간다. 값은 0 · 1 · 3 중 개발 셋으로 고른다.
5. 뜻으로만 온 답(낱말 후보에 없음)은 1차처럼 `[뜻]` 칸 strict 답이다. 낱말 답은 칸을 안 바꾼다.
6. 끄면(`mix = false`) · 모델이 없으면 C2 전과 건마다 같다 (1차와 같은 성질).

고른 까닭 : fresh-A 를 갈래로 나눠 보니(7-1) 놓친 것의 절반은 **뜻 1~3위인데 섞기에서 밀린** 경우였고, 1차가 잃은 둘은 **낱말 1·2위가 두 몫 받은 후보에 밀린** 경우였다. 「나은 쪽 하나」는 두 흠을 같이 고친다 — 뜻 상위는 낱말 순위와 상관없이 위로 오고, 낱말 상위는 두 몫 받은 후보가 없어 덜 밀린다. 「낱말 후보가 아닌 것에만 뜻 몫」 안은 버렸다 — fresh-A 의 `background script …` 처럼 정답이 낱말 42위에 걸려 있으면 뜻 2위여도 못 올라온다.

**손잡이 (fresh-B 를 보기 전에 고정)** : `mix_rank` 5 → **3** · `mix_keep` **0** · `mix_floor` 0.58 · `mix_top` 20 · `mix_weight` 1 · `mix_k` 60. v3 · v4 · v2 · fresh-A 로만 골랐다 (7-3 표). `mix_keep` 3 은 r@5 가 같고 MRR 만 내려 버렸다 — 「큰 쪽 하나」만으로 낱말 3위 안이 5위 밖으로 안 간다.

- fresh-B 의 두 헛답은 0.60 으로도 안 막힌다 — 코사인이 0.60 위다. 바닥만으로는 헛답을 못 막는다는 뜻이고, 다음 걸음은 그대로 뜻 답 전용 관문이다.
- 끔 판은 2차 판 끔 로그와, 0.58 켬 판은 2차 판(`rank 3 · keep 0` · fresh-B 2차) 로그와 다섯 셋 모두 건마다 같다 (`same.py` 0건 다름).
- 새 기본값으로 다시 빌드한 `bin\mem.exe` 를 뒷문 없이 돌린 판도 끔 판과 여섯 셋 모두 0건 다름이다.

### 9-3. 어떻게 쟀나

- 저장소 사본 : 2차와 같은 830건 의미 모드 사본(`memmix\bM`)을 `memmix3\bM` 으로 복사했다. 지금 작업 트리는 색인 판이 바뀌어 옛 `index.db` 를 못 읽으므로, 이 판 exe 로 `index --full` 을 다시 했다 — 벡터는 「0건 새로 · 830건 그대로」로 2차와 같은 `vectors.bin` 을 썼다. 홈(ko-v2 + onnxruntime)은 2차 그대로(`memmix\home`).
