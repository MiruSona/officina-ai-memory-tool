# A2 `mem retain` 2판 실측 — 살아 있는 세션은 맞게 건너뛰고, scope 는 못 쟀다

## 0. 결론

1. **Pick 의 살아 있는 세션 건너뛰기는 설계대로 돈다.** 진짜 큐에는 지금 살아 있는 세션이 없어서, 스크래치 저장소에 가짜 큐 다섯 칸을 만들어 쟀다. 건너뛸 셋은 건너뛰고 집을 둘은 집었다(2절).
2. **진짜 큐 6건은 모두 빈 세션이었다.** 대화 글자 0~220자, 후보 0건, 합 4.7초. 지금 큐로는 retain 이 할 일이 없다.
3. **scope 틀림 비율은 못 쟀다.** retain-log 의 후보 칸에 `scope` 가 없다(5절 버그 ①). 생성 응답을 엿보는 프록시를 세우려 했지만 자동 분류기가 막았다. **첫 실측과 견주는 3번 일은 못 했다.**
4. **R4 흔들림의 뿌리는 생성이다. 판정은 같은 글에 같은 값을 준다.** 같은 세션 3판에서 글이 같은 후보는 R3 세 확률까지 똑같이 나왔다. 판마다 갈린 것은 요약 글이 바뀐 후보뿐이다(3절).
5. **R4 가 늘 놓치는 중복이 하나 있다.** 「폴더 이동 시 venv·스케줄러 경로 깨짐」 caution 은 `20261017-0123b331` 과 같은 내용인데 3판 모두 R4 를 지났다. 흔들림이 아니라 고정된 놓침이다. 이번엔 R3 가 막았다.

## 4. scope — 못 잰 까닭과 이번에 안 것

- dry-run 의 retain-log `items` 칸은 `title · type · summary · quotes · sources · verdict · reasons` 뿐이다. **생성이 고른 scope 와 추정으로 바꾼 scope 가 안 남는다.** 자식 `mem add --check` 도 log.md 에 안 쓴다.
- 대안으로 `MEM_LLM_CONFIG` 를 스크래치 llm.toml 로 돌려 생성 응답을 기록하는 로컬 프록시를 세우려 했다. 자동 분류기가 「트래픽 돌리기」로 막았다. 우회하지 않았다. 프록시는 한 요청도 받지 않은 채 내렸다.
- 그래서 **2판의 scope 규칙 한 줄 · cwd 추정 효과는 확인 못 함.** 표본으로 보면 이번 후보 11건 중 환경 사실 꼴이 2건(fact 루트 경로 · PowerShell here-string caution)이라, 로그가 있었어도 표본은 작았다.
- 큐 21건 모두 `cwd` 가 없다. 지금 큐로는 `GuessScope` 가 세션 cwd 를 못 쓰고 저장소 뿌리 이름으로만 추정한다 — 뿌리 세션이 아닌 툴 폴더 세션도 프로젝트 scope 로 간다 [코드 읽기로 추정, 안 돌려 봄].

## 5. 찾은 문제

1. **retain-log 후보 칸에 scope 가 없다.** dry-run 으로 scope 품질을 잴 수 없다. `items` 에 `scope`(생성 값)와 `scope_guessed`(추정으로 바꿨는지)를 실으면 된다. 고치는 곳 : `cmd/mem/retain_log.go` · `retain_session.go`.
2. **R4 가 venv caution 을 늘 놓친다.** 같은 caution `20261017-0123b331` 이 있는데 hard·soft 어느 쪽에도 안 걸린다. 첫 실측 대조판부터 4판째. R3 가 막아 주는 동안은 해가 없지만, 요약이 인용 하나로 받쳐지면 중복이 들어간다.
3. **Pick 이 건너뛴 칸을 말하지 않는다.** `--json` 끝 요약에도 건너뛴 수가 없다. 「왜 안 집혔나」를 알려면 큐 파일과 mtime 을 손으로 봐야 한다. `skipped_live` 수 하나면 된다.
4. (참고) 윈도 PowerShell 5.1 의 `Get-Content` 로 retain-log 를 읽으면 한글이 깨지고 `ConvertFrom-Json` 이 실패한다. 파일 문제가 아니라 읽는 쪽 문제다(BOM 없는 UTF-8). Python · `-Encoding utf8` 로 읽는다.
