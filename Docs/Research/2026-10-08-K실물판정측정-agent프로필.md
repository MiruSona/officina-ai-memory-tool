# K 실물 판정 측정 — `agent` 프로필 (E1)

> 앞 측정 : `2026-10-08-K실물판정측정.md` (flashnext · 10절 v3). 자는 루트 `Docs/Research/2026-10-08-SemIf대체판정모델조사.md` 5절 E1.

## 1. 왜

- 게임 서버가 떠 있는 동안 미니PC 의 평소 프로필은 `agent`(Qwen3.6-35B-A3B-MTP)다. flashnext 를 따로 올리지 않고 **`agent` 로 K 판정(R3)을 맡길 수 있나**를 본다.
- 결론 : **v3 는 세 자를 다 넘었다 — 42/48 · p95 1433ms · 거짓 지지 2.** 단 거짓 지지 둘이 **높은 확률(0.81 · 0.96)** 로 나와 B2 Verify 0.7 을 뚫는다. 둘 다 약한 쌍이다 (4절).

## 5. 판정

- **E1 통과 (v3).** 전체 42/48 · p95 1433ms · 거짓 지지 2 — 세 자 다 넘음. 기본 판은 그대로 `support-v3` 다 (strict 는 agent 에서 더 나쁨).
- **주의 하나 — 확신 높은 거짓 지지.** flashnext 의 거짓 지지는 A 0.44 아래라 확률 선이 걸렀다. agent 는 0.81 · 0.96 이라 B2 Verify 0.7 · R3 「A ≥ 0.6」 어느 선으로도 못 거른다. 약한 쌍 손질(앞 문서 10-7 1번) 전에는 이 차이가 쌍 탓인지 모델 탓인지 못 가른다.
- 한 판만 돌렸다. 41 선과 한 쌍 차이라 반복하면 41 로 내려올 수 있다.

다음 할 일 : 1. E2 (2단 모의 계산) — 이번 확률로. 단 거짓 지지 둘이 확신이 높아 2차로 안 넘어간다는 점을 같이 본다.
2. 약한 쌍 손질 뒤 agent · flashnext 를 다시 견준다 — 확신 높은 거짓 지지가 남는지.
3. 반복 2회 (flashnext 10-8 처럼) — 42 가 안정한지.

## 7. Gemma 4 비교 (E3-gemma4)

결론 : **미달 — 40/48, 한 쌍 모자람.** 지연은 셋 중 가장 빠르다(p95 506ms). 거짓 지지는 1 이지만 그 쌍(k037)을 **A 0.99** 로 확신해 확률 선으로 못 거른다.

**조건.** 미니PC `gemma4` 프로필 (Gemma 4 26B-A4B-it UD-Q4_K_XL · `--reasoning-budget 0`) · 게임 서버 떠 있음. 같은 exe · 같은 48쌍 · `--fresh` · v3 → v3-strict → v2 순차 · `timeout_ms` 5000 그대로. 메모리 used 28356 → 36678 · avail 32535 → 24213 · **swap 77 → 77**.

**템플릿 손질.** 손질 전에는 첫 토큰이 늘 `<|channel>`(logprob 0)이라 글자를 못 읽었다. 까닭은 GGUF 템플릿이 아니라 **서버가 `enable_thinking` 을 참으로 넘긴 것**이다 — 렌더 결과 system 머리에 `<|think|>` 가 붙고 생성 머리에 빈 생각 칸이 없었다. 템플릿에는 이미 「생각 끔이면 `<|channel>thought\n<channel|>` 를 깐다」 줄이 있다.
