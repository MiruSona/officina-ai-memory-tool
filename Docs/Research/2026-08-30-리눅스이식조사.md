# mem 리눅스(미니PC) 이식 조사

조사 날 : 2026-08-30 · 방법 : 메인 PC 에서 크로스빌드 실측 + 코드 grep
대상 코드 : `AIMemoryTool/` (2026-09-03 에 v0.4 를 이 자리로 올렸다. 조사 당시 경로는 `AIMemoryTool/v0.4/` 였다)

## 결론

미니PC(소형 리눅스 미니PC · Ubuntu Server headless · 계정 `claude` · sudo 없음 · 작업 자리 `~/llm`)
에서 **mem 은 조건부로 된다.** 조건은 하나 — **임베딩(의미) 검색을 끄는 것**이다.

실측으로 확인한 것 :

```
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build ./cmd/mem   → 통과
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go vet ./...          → 경고 0
```

SQLite 가 `modernc.org/sqlite`(순수 Go, `AIMemoryTool/v0.4/go.mod:9`) 라서 cgo 가 필요 없다.
`CGO_ENABLED=0` 은 v0.4 설계의 제약 26 이다 (`AIMemoryTool/v0.4/Docs/Design/2026-08-24-v0.4설계.md:64`).

**다만 지금은 이식할 필요가 없다.** 아래 「언제 필요한가」를 본다.

---

## 1. 그냥 되는 것

| 무엇 | 왜 되나 |
| --- | --- |
| `search` `show` `add` `set` `index` `review` `gc` `tags` `lint` `eval` | OS 분기가 아예 없다 |
| 경로 | 전부 `filepath`. 하드코딩된 `\` 없음 |
| 기계별 설정 자리 | `~/.aimemory/` 하나 (`v0.4/internal/install/install.go:20` 의 `rootDirName`, `Paths()` 103~107) |
| 저장소 찾기 | cwd 에서 위로 올라가며 `Memory/mem.toml` 을 찾는다 (`v0.4/internal/config/locate.go`). `~/.claude` 는 안 본다 |
| 에이전트가 붙는 길 | 거의 모든 명령에 `--json`, `add --jsonl`, 어디서 부르든 `--repo <경로>` |
| 훅 없이 세션 요약 받기 | `mem hook session-start --dry-run </dev/null` — 훅 JSON 이 안 들어오면 지금 폴더로 떨어진다 (`v0.4/internal/hook/hook.go:378` `startDir`). `CLAUDE_PROJECT_DIR` 도 읽는다 (`hook.go:36`) |
| 색인 잠금 | `alive_windows.go` / `alive_other.go` 짝이 이미 있다 (`v0.4/internal/index/`) |
| Gemini 훅 꼴 | `mem init --gemini` 로 지원 (`v0.4/cmd/mem/cmd_init.go:16`) |
| 첫 실행 | `index.db` 가 없으면 `search` 가 알아서 만든다 |

**시험은 손댈 것이 없다.** 시험 코드에서 GOOS 를 보는 자리는 `v0.4/internal/store/v01_test.go:35` 하나뿐인데,
그건 링크 만들기 헬퍼가 Windows 에서만 `mklink /J` 로 되돌아가는 것이고 리눅스에서는 `os.Symlink` 가 그냥 된다.
링크를 못 만드는 기계면 같은 파일 20줄에서 이미 `t.Skipf` 로 넘어간다.

## 3. 두 기계가 git 으로 기억을 나눠 쓸 때

**올라가는 것** — `Memory/store/**/*.md` · `mem.toml` · `vocab.toml` · `log.md` · `archive/` · `golden/`
**안 올라가는 것** — `index.db`(+`-wal` `-shm`) · `index.lock` · `inbox/` · `local/`(`hits.jsonl`·`miss.jsonl`) · `vectors.bin` · `mem.exe`
(다 `.gitignore` 111~127 의 `# >>> mem >>>` 구역에 이미 들어 있다)

`.gitattributes` 는 지금 이렇다.

```
Memory/store/**/*.md text eol=lf
Memory/archive/*.jsonl merge=union text eol=lf
```

### 충돌은 한 자리뿐이다

- **id 충돌은 사실상 없다.** id 는 `날짜 + sha256(본문·UnixNano·PID·세는수) 앞 4바이트` 다
  (`v0.4/internal/model/id.go:23-27`). 게다가 기억 하나가 파일 하나라 겹쳐도 git 이 add/add 로 잡아 준다.
- **진짜 충돌 자리는 `Memory/log.md`** 다. `AppendLog` 가 파일을 통째로 다시 쓴다
  (`v0.4/internal/store/log.go:38`, `appendFileRetry` 68). `merge=union` 이 아직 안 걸려 있어
  두 기계가 같은 날 기록을 남기면 그대로 충돌한다.
  → `.gitattributes` 에 **`Memory/log.md merge=union`** 한 줄 추가. **1분.**
- `local/hits.jsonl` 이 기계별이라 gc 판단이 기계마다 갈린다. → **gc 는 메인 PC 에서만** 돈다.
- `mem.toml` 이 저장소에 하나뿐이라 **기계별로 embed on/off 를 나눌 수단이 없다.**
  (임베딩을 켜려면 이 문제를 먼저 풀어야 한다)

### 공유 방식 후보

| 안 | 내용 | 판정 |
| --- | --- | --- |
| **A** | git 으로 저장소를 공유 | **추천.** 미니PC 가 읽기 위주면 문제가 거의 없다 |
| B | 미니PC 에 별도 저장소 | 기억이 갈라진다. mem 은 저장소를 하나만 연다. **최악** |
| C | SMB · NFS 로 `Memory/` 를 공유 | SQLite 잠금이 깨진다. **비추천** |
| D | 미니PC 는 mem 을 아예 안 쓴다 | **지금 그림.** `llama-server` 만 돌리고 Claude Code 는 메인 PC 에서 `ANTHROPIC_BASE_URL` 로 붙는다 (LLM 서버 설정은 별도 비공개 설계를 따른다) |

## 4. 언제 이식이 필요한가

- **필요 없는 경우 (지금)** — 서브에이전트가 **메인 PC 의 Claude Code 에서 돌고 모델만 미니PC 에 있다.**
  mem 은 이미 메인 PC 에 있으므로 이식할 것이 없다.
- **필요한 경우** — **미니PC 위에서 에이전트 런타임을 직접 돌릴 때만.**

## 5. 최소 이식 경로 (그때가 오면)

1. Go 타르볼을 `~/llm/go` 에 푼다
2. `~/llm/<작업폴더>` 로 clone
3. `CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o ~/.aimemory/bin/mem ./cmd/mem`
4. `~/.profile` 에 `PATH` 한 줄
5. `mem index --full`
6. **`mem init` 은 돌리지 않는다** (allow 규칙이 Windows·Claude Code 꼴이다)
7. `.gitattributes` 에 `Memory/log.md merge=union`
8. 미니PC 의 에이전트는 명령 **둘만** 쓴다
   - `mem search "<질의>" --json --limit 8`
   - `mem hook session-start --dry-run </dev/null`

## 7. 못 한 것

- **실제 리눅스 런타임에서 안 돌려 봤다.** 파일 잠금 동작, `0700`/`0600` 권한, `LANG=C` 에서 한글 출력이
  깨지는지는 미확인이다.
- `GOOS=linux go test` 를 안 돌렸다 (크로스 컴파일이라 그 기계에서만 돈다).
- `v0.4/internal/gc/` 는 안 읽었다.

**신뢰도 85%** — 빌드와 `go vet` 은 직접 돌려 눈으로 봤고 GOOS 분기는 전부 grep 으로 찾았다.
깎은 15% 는 리눅스에서 실제로 안 돌려 봐서다.
