# 서버 없는 판정기 — 논문 조사 (2026-10-08)

`mem judge` 의 지지(A) / 반대(B) / 무관(C) 판정을 큰 LLM 서버 없이 할 길을 논문에서 찾았다.
같은 날 다른 두 갈래(저장소 조사·RAG 실무 조사)와 짝을 이룬다. 이 문서는 **논문 몫**만 다룬다.

## 결론 먼저

1. **서버 없이도 된다는 근거는 있다. 단, 「서버를 학습 때만 쓰는」 꼴이어야 한다.**
   작은 판정기(0.4~0.8B)가 GPT-4 급에 닿은 논문들(MiniCheck·FactCG)은 모두 **큰 LLM 으로 그럴듯한 오류 자료를 만들어** 학습했다.
   규칙으로 만든 오류(숫자 바꾸기·부정 넣기, FactCC 식)는 실물에 일반화가 안 된다는 보고가 여럿이다 — 우리가 Laya 에서 겪은 그대로다.
2. **MiniCheck 의 절제 실험이 가장 강한 증거다.** LLM 합성 자료 14K 를 빼면 평균 정확도가 74.7 → 59.9 로 **14.8점** 떨어진다.
   합성 자료의 질이 모델 크기보다 중요했다.
3. **Laya 가 한국어에 약한 기반이었을 수 있다.** 같은 KLUE-NLI 검증 조각에서 Laya 다국어판 73.7%, `klue/roberta-large` 미세학습판 90.7% 라는 보고가 있다(블라인드 시험 아님).
   한국어 NLI 를 이미 잘하는 기반에서 시작하면 출발점이 크게 다르다.
4. **「거짓 지지 ≤3」은 모델만으로는 어렵고, 확신 문턱(모르면 C 또는 미루기)으로 맞추는 게 정석이다.**
   JEV-as-a-Judge 논문이 정확히 이 꼴(확신하면 받고, 아니면 큰 모델로 넘김)을 실측했다.
5. **「Jev」는 실제로 있는 이름이다.** TypeSafe AI 의 비공개 판정 모델(API 전용)이고, 우리가 시험한 **Laya 가 바로 Jev 의 오픈소스 대안**이다.
   Jev 자체는 서버(남의 API)가 필요해서 우리 목적에는 안 맞는다.

**추천 순위** (자세한 건 맨 끝 절):

| 순위 | 길 | 한 줄 | 공수 어림 |
| --- | --- | --- | --- |
| 1 | 교사 증류 + LLM 합성 반대 + 한국어 강한 기반 | 미니PC Qwen3.6 이 학습 자료를 만들고 라벨을 붙인다. 실행 때는 300M 급 한국어 분류기만 돈다 | 3~4일 |
| 2 | 확신 문턱·미루기 층 | 어떤 분류기든 확신이 낮으면 C(또는 서버 있으면 SemIf)로 넘긴다. 거짓 지지를 문턱으로 누른다 | 0.5~1일 |
| 3 | 작은 LLM(1.7B~4B) CPU 판정 | llama.cpp CPU 로 첫 토큰 logprob + 보정. 필요하면 LoRA 증류 | 시험 1일, 증류 3일 |

## 1. 사실 일관성·NLI 판정 모델 — 작은 모델은 어디까지 가나

벤치마크 이름부터 짧게:

- **LLM-AggreFact** : 「근거 문서 + 주장 한 문장」이 지지되나를 사람이 라벨 단 11개 자료 모음. 점수는 균형 정확도(BAcc, 지지·비지지 재현율 평균). **두 갈래(지지 / 비지지)** 라서 우리 세 갈래와 다르다.
- **FaithBench / RAGTruth / HaluBench** : 요약·RAG 답의 환각 탐지 모음.
- 모두 **영어, 그리고 근거가 긴 문서**다. 우리는 한국어 짧은 문장 쌍이다. 수치는 「어느 정도 가능한가」의 감으로만 본다.

| 후보 | 원리 한 줄 | 크기 | 보고 수치 | 라이선스 | 한국어 |
| --- | --- | --- | --- | --- | --- |
| FactCC (2020) | 원문 문장에 규칙 변형(부정·개체·숫자 바꾸기)을 가해 오류 자료를 만들고 BERT 학습 | 110M | 손 라벨 시험 가중 정확도 74.2%, F1 0.51 | BSD | 없음 |
| SummaC (2022) | 문장 단위로 NLI 를 돌려 점수를 모음 | 300M 급 | SummaC 벤치 기준(현재는 AlignScore·MiniCheck 에 밀림) | — | 없음 |

읽는 법:

- **작은 판정기의 천장은 영어 장문에서 BAcc 75 언저리**다. 7~8B 로 키워도 77 이다. 큰 LLM 과 거의 같은 자리다.
  이건 과제가 어려워서(장문·여러 단계 추론) 그런 것이고, 짧은 문장 쌍은 더 쉽다. 한국어 짧은 쌍 NLI(KLUE-NLI)는 아래 2절처럼 90% 가까이 간다.
- **「같은 점수, 다른 실수」 주의.** Verify with Caution(ACL 2025 Findings)은 BAcc 가 비슷한 gpt-4-turbo 와 Bespoke-7B 가 **낱개 판정은 자주 엇갈리고** 지지·비지지 쪽 오류 비율이 다르다고 보고했다.
  평균 정확도가 같아도 우리 「거짓 지지 ≤3」 같은 한쪽 자는 따로 재야 한다.
- **시험 자료의 라벨 자체가 흔들린다.** Verifying the Verifiers(2025)는 14개 벤치 예제의 **약 16%가 모호하거나 라벨이 틀렸다**고 했다.
  K 48·game90 103쌍처럼 작은 셋에서는 1~2건 라벨 오류가 판정을 바꾼다. 틀린 쌍을 사람이 다시 보는 단계가 필요하다.

| --- | --- | --- | --- |

| KLUE-RoBERTa-base | 110M | 84.8~85.0 | 〃 |

정리:

- **한국어 NLI 자체는 300M 급으로 89~90% 가 나온다.** 기반 모델 고르기가 결과를 크게 가른다. 다국어 모델(mDeBERTa·mmBERT)은 한국어에서 10점 넘게 낮다.
- **쓸 수 있는 한국어 NLI 자료** :
  - KLUE-NLI (약 25K, 사람이 쓴 한국어 원문, CC BY-SA 4.0)
  - KorNLI (SNLI·MNLI 기계번역, 약 95만, CC BY-SA 4.0)
  - multilingual-NLI-26lang-2mil7 의 `ko_mnli`·`ko_anli` 등 (MNLI·Fever·ANLI·LingNLI·WANLI 기계번역. **라이선스 표기 없음, 원본 ANLI 는 CC BY-NC** — 상용이면 빼야 한다)
- **한국어 특유의 어려움** (한국어만 다룬 논문은 못 찾음. 영어 연구와 한국어 구조에서 끌어낸 것):
  - NLI 자료의 반대 쌍은 **부정어를 넣어 만든 게 많아** 모델이 「부정어 = 반대」 지름길을 배운다(Gururangan 2018, 가설만 보고도 맞힘). 우리 규칙 층이 부정 짝을 B 로 보는 것과 같은 함정이다.
  - 한국어 부정은 「안/못/-지 않다/없다/아니다」에 이중 부정·반어(「~지 않나」)까지 있어 낱말 단위 규칙이 잘 깨진다.
  - 기계번역 자료(KorNLI)는 번역투라 실물 한국어 기억 문장과 말투가 다르다. **기억 문장은 주어가 빠지고 「~함」「~로 정함」 꼴이 많다.**

## 3. 반대 자료가 모자랄 때 — 무엇이 통했나

우리 뿌리 문제다. 실물 반대는 수십 개, 만든 반대는 실물과 닮지 않았다.

| 방법 | 논문 | 무엇을 했나 | 보고된 효과 | 우리에게 |
| --- | --- | --- | --- | --- |
| 규칙 변형 | FactCC (2020) | 부정·개체·숫자·대명사 바꾸기 | 쉬운 예(원문을 거의 베낀 경우) 90%↑, 바꿔 쓴 예에서 70%로 떨어짐. WeCheck 등이 「합성과 실물 오류 분포가 다르다」고 지적 | **우리가 Laya 에서 본 실패와 같다** |
| 조절 생성 | Falsesum (NAACL 2022) | 조절 가능한 생성 모델로 사람 요약에 여러 종류 오류를 넣음. 「틀렸지만 그럴듯한」 예 | 4개 사실 일관성 벤치에서 당시 최고 | 「그럴듯함」이 열쇠 |
| LLM 이 그럴듯한 오류 합성 | MiniCheck (EMNLP 2024) | GPT-4 가 주장을 원자 사실로 쪼개고, 사실 하나를 빼거나 비튼 문서·주장을 만듦(C2D·D2C, 합 14K) | 합성 빼면 74.7 → 59.9 (**−14.8**). C2D·D2C 둘 다 각각 2~3점 몫 | **가장 직접적인 근거** |
| 그래프 기반 다단계 합성 | FactCG (NAACL 2025) | 문맥 그래프에서 여러 단계 추론이 필요한 주장 생성 | 0.4B 가 GPT-4o 와 비슷 | 기억 쌍은 짧아 다단계는 덜 중요 |
| 사람+AI 협업 | WANLI (2022) | 모델이 어려워하는 패턴을 GPT-3 가 새로 쓰고, 사람이 라벨·다듬기 | 4배 큰 MNLI 보다 HANS +11, ANLI +9 | **「어려운 예 위주 + 사람 검수」**가 양보다 낫다 |
| LLM 반사실 + 여러 심판 거르기 | NLI 반사실 (arXiv 2512.18462) | gpt-5-mini 가 최소 변경 반례를 만들고 두 LLM 심판이 만장일치로 통과한 것만 씀 | 대조셋 일관성 63.5 → 81.0. 균형 샘플링으로 원래 성능 하락을 −5.3 → −1.0 으로 줄임 | 걸러내기와 **섞는 비율**이 중요 |
| 작은 LLM 강화학습 | 5G 규격 모순 탐지 (2025) | 큰 LLM 이 만든 합성 모순으로 3B 를 RL 학습 | GPT-3.5 보다 F1 +7.6 | 「합성 품질이 성능을 정한다」고 저자가 밝힘 |
| 대조 원형 생성 | 2310.14732 | LLM + 규칙(부정·반의어·숫자)으로 모순 유형별 생성 | 수치 없음 | 참고만 |

우리 상황(실물 반대 수십 개)에 맞춰 읽으면:

- **규칙 변형으로 만든 반대는 「쉬운 반대」만 가르친다.** 이건 이미 Go 규칙 층이 잡는 몫이다. 모델에게 또 가르칠 필요가 없다.
  모델 학습 자료에서는 규칙 층이 잡는 꼴(숫자 다름·부정 짝)을 **오히려 줄이고**, 규칙이 못 잡는 반대(의미로 엇갈림·결정 뒤집기·범위 바뀜)를 늘려야 한다.
- **LLM 합성의 씨앗은 실물 문장이어야 한다.** MiniCheck·Falsesum 모두 사람이 쓴 문장에서 출발했다. 실물 mem 한 줄을 주고 「이 기억과 모순되는, 같은 팀원이 나중에 쓸 법한 한 줄」을 만들게 한다.
- **수십 개 실물 반대는 학습이 아니라 「본보기와 시험」에 쓴다.** 생성 프롬프트의 예시(few-shot)로 넣어 말투를 맞추고, 최종 판정은 실물 반대로만 잰다.
- **거르기 필수.** 생성 모델(Qwen3.6)이 만든 반대를 SemIf 판정으로 다시 돌려 B 가 나온 것만 쓰고, 일부(수십 쌍)는 사람이 본다.

## 4. LLM 판정(judge / verifier)의 원리와 작은 모델로 옮기기

- **첫 토큰 logprob 판정** : 지금 SemIf 가 쓰는 꼴. 생성 없이 「A/B/C 다음 토큰 확률」만 본다. 빠르고 확률이 나온다.
- **보정(calibration)** : LLM 은 특정 라벨을 더 좋아하는 버릇이 있다. **Contextual calibration**(Calibrate Before Use, 2021)은 「N/A」 같은 내용 없는 입력의 라벨 확률을 재서, 그걸로 나눠 버릇을 지운다. GPT-3 에서 정확도가 최대 30점 올랐다. 코드 몇 줄이다.
- **순서 바꿔 평균** : 쌍 비교라면 근거·주장 순서를 바꿔 두 번 보고 확률을 평균한다(JEV-as-a-Judge 가 씀). 우리 판정은 방향이 있어(근거→주장) 그대로는 못 쓰지만, A/B/C 선택지 순서를 섞어 평균하는 건 쓸 수 있다.
- **확신 문턱 + 미루기(cascade)** : JEV-as-a-Judge(CMU, 2026)는 작은 판정기가 최대 확률 ≥ 문턱이면 받고, 아니면 큰 모델로 넘겼다.
  JudgeBench 에서 문턱 0.9 로 **61%를 넘기고 큰 모델 정확도의 98.2%를 비용 62%로** 지켰다. 고정 정책으로는 53.7%만 받아 92.5% (큰 모델 93.1%).
  우리에게 「큰 모델」이 없을 때는 넘기는 대신 **C(판정 못 함)** 로 두면 된다. 거짓 지지를 문턱으로 직접 누를 수 있다.
- **작은 모델로 옮기기(증류)** :
  - 큰 판정기의 라벨로 작은 분류기를 학습하는 게 표준이다(Luna: DeBERTa-large 가 GPT-3.5 판정을 넘음. 약지도 증류 2604.06277: LLM 심판을 학습 때만 씀).
  - 작은 LLM 은 **분류 머리를 붙여 학습**하는 게 낫다는 보고가 있다(Qwen3 0.6B 에서 라벨 생성식보다 2~3점, 2607.03801). 다만 llama.cpp 로는 분류 머리 서빙이 안 되니 ONNX 쪽이 맞다.
  - 작은 LLM 의 zero-shot 분류는 약하다(gemma-3-1b 평균 0.46, BTZSC). 1B 이하는 학습 없이는 기대하기 어렵다.

## 5. 「Jev」 — 이름이 실제로 있다

| 항목 | 내용 |
| --- | --- |
| 정체 | TypeSafe AI 의 비공개 판정 모델 가족. 현재 판 1.13.0 |
| 꼴 | 생성하지 않는 분류기. 한 번 앞으로 계산해 **Choice(선택지 확률) / Score(등급 확률) / Noul(예·아니오 확률)** 셋을 낸다. Kahneman 의 「시스템 1(빠른 판단)」을 빌려 System One 이라 부른다 |
| 학습 | RLCD 라는 비공개 방식(적절한 점수 규칙을 보상으로) |
| 실행 | **API 전용.** 로컬에서 못 돌린다. 크기 비공개 |
| 수치 | JudgeBench 78.6% (GPT 최상위 93.1%) · ECE 0.246(자체 평가) · LLM-AggreFact 79.1(개인 저장소, 개발셋으로 문턱 맞춤이라 공식 비교 아님) |
| Laya 와의 관계 | **Laya 는 Jev 의 오픈소스 대안**(ConvAI, Apache 2.0). 같은 세 가지 출력 꼴. 우리가 이미 시험해 접었다 |
| 우리에게 | Jev 는 서버(외부 API)라 목적과 반대. 「원리」로는 이미 SemIf·Laya 가 같은 꼴(확률을 내는 판정 + 문턱)이라 새로 얻을 건 4절의 **확신 문턱·미루기** 정도다 |

## 6. 우리 자(정확도 ≥0.85 · 반대 재현 ≥0.75 · 거짓 지지 ≤3)에 닿을 전망

논문 중 **한국어 짧은 기억 쌍**을 잰 것은 없다. 아래는 비슷한 과제에서 끌어낸 어림이다.

| 자 | 전망 | 근거 |
| --- | --- | --- |
| 정확도 ≥0.85 | **닿을 만하다** | 한국어 짧은 쌍 NLI 에서 337M 이 89~90%. Laya 다국어 기반보다 17점 높은 출발점 |
| 반대 재현 ≥0.75 | **가장 어렵다. 반반** | 작은 판정기들도 반대(비지지) 쪽이 약하다. MiniCheck 식 합성이 +15점을 줬지만 영어·장문 기준. 실물 반대 30쌍으로만 재니 표본 흔들림도 크다(1쌍 = 3.3%p) |
| 거짓 지지 ≤3 | **문턱을 쓰면 닿는다. 대신 C 가 늘어난다** | JEV cascade 처럼 확신 낮은 A 를 C 로 돌리면 거짓 지지는 직접 줄일 수 있다. 대가는 「지지인데 C」가 느는 것 |

## 7. 우리 상황에서 가장 유망한 길 3개

### 1위. 교사 증류 + LLM 합성 반대 + 한국어 강한 기반

- **무엇** :
  1. 기반을 `klue/roberta-large`(337M) 로 바꾼다. 먼저 KLUE-NLI(+KorNLI) 로 3갈래 NLI 를 학습한다.
  2. 미니PC Qwen3.6 으로 실물 mem 한 줄마다 **그럴듯한 반대·지지·무관 짝**을 만든다(MiniCheck C2D 꼴). 실물 반대 수십 개를 본보기로 넣는다. 규칙 층이 잡는 꼴(숫자·부정)은 비율을 낮춘다.
  3. 만든 짝을 SemIf 로 다시 판정해 라벨이 맞는 것만 남긴다(여러 심판 거르기). 실물 mem 쌍 수천 개에도 SemIf 라벨을 붙여 함께 넣는다(증류).
  4. ONNX 로 내보내 CPU 서빙. 시험은 실물 game90·K 로만.
- **왜 1위** : 논문들이 작은 판정기를 GPT-4 급으로 끌어올린 방법이 전부 이 꼴이다. 우리 실패 원인(규칙식 합성 + 다국어 약한 기반) 둘을 같이 고친다. 서버는 **학습 때만** 쓴다.
- **걸리는 것** : `klue/roberta-large` 와 KLUE·KorNLI 는 CC BY-SA 4.0(상용은 되나 같은 조건 배포 의무, 확인 필요). 학습에 GPU 가 있으면 빠르다(Laya 노트북은 Kaggle 무료 T4 를 썼다).
- **공수 어림** : 생성 프롬프트·거르기 0.5일 + 미니PC 밤 생성 1판 + NLI 사전학습·미세학습 1~1.5일 + ONNX·Go 연결 0.5일 + 실측 0.5일 = **3~4일**.

### 2위. 확신 문턱·미루기 층 (어느 분류기 위에든)

- **무엇** : 분류기 출력 확률에 온도 보정을 하고, A 는 높은 문턱에서만 내준다. 낮으면 C. 서버가 있으면 그 쌍만 SemIf 로 넘긴다.
- **왜** : 「거짓 지지 ≤3」은 모델 개선만으로 보장하기 어렵다. JEV-as-a-Judge 가 이 꼴로 큰 모델 정확도 98%를 비용 62%로 지켰다. 규칙 층 + 분류기 + 서버(있을 때)의 3단 구조가 된다.
- **공수 어림** : 온도 맞추기·문턱 고르기·Go 연결 **0.5~1일**. 1위와 함께 하면 거의 덤이다.

### 3위. 작은 LLM(1.7B~4B) CPU 판정

- **무엇** : Qwen3 1.7B/4B 같은 작은 모델 GGUF 를 llama.cpp CPU 로 돌려 지금 SemIf 와 같은 첫 토큰 logprob 판정을 한다. contextual calibration 을 붙인다. 약하면 SemIf 라벨로 LoRA 증류.
- **왜 3위** : 지금 코드(SemIf)를 거의 그대로 쓸 수 있어 시험이 가장 싸다. 하지만 1B 급 zero-shot 분류는 약하다는 보고가 많고, 4B 도 CPU 에서 쌍 하나에 수 초가 걸릴 수 있다. 크기도 2~3GB 로 1위(약 0.7GB, 양자화하면 더 작음)보다 크다. 영어용 Granite Guardian 3.3(8B, Apache)·Bespoke-MiniCheck-7B(상용 불가)는 한국어·라이선스 때문에 대안이 못 된다.
- **공수 어림** : zero-shot 시험 **1일**(모델 받기·프롬프트 그대로·K/game90 재기). LoRA 증류까지 가면 +2일.
