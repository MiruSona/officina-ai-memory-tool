## 결론 먼저

1. **1순위 : 미니PC GPU — 이미 있는 podman 이미지를 그대로 쓴다. 새로 깔 것이 없다.**
   ArtTool 이 쓰는 `kyuz0/amd-strix-halo-comfyui` 이미지 안에 **gfx1151 용 ROCm torch 가 들어 있고 GPU 를 잡는다** [실측] :
   `torch 2.14.0a0+rocm7.15.0a20260721` · `torch.version.hip 7.15.0` · `cuda.is_available() True` · `Radeon 8060S` · arch 목록에 `gfx1151`.
   `transformers 5.15.0` · `tokenizers` · `safetensors` 도 있다. `datasets`·`accelerate`·`onnx` 는 없다 → 짧은 torch 학습 고리를 직접 쓰면 된다.
   그래서 앞 조사의 「ROCm torch 설치 승인」은 **필요 없어졌다.** 남는 승인은 모델·자료 내려받기뿐이다.
   - 까닭 : 설치 공수 0, 같은 이미지가 10-07 klein 그림 판을 게임 서버와 같이 돌린 이력이 있다. 1 epoch 어림 20~90분 [추정].
   - 단 GPU **학습(역전파)** 은 이 기계에서 아직 안 돌려 봤다. 첫 판은 **게임 서버 내린 낮 시간, 사람이 깨어 있을 때** 10~20 스텝 벤치부터 (GPU 멎음 이력 · 규칙).
2. **2순위 : 미니PC CPU — 지금 그대로 된다.** 실측 쌍당 **0.13초(seq 64) ~ 0.28초(seq 128)**.
   KLUE 25k + KorNLI 5만 1 epoch = **2.8~5.9시간** [실측 기반 셈]. 3 epoch 면 8~18시간, 밤 한 판이다.
   피크 RSS 10.4GB, 게임 서버 뜬 채 가용 최저 **14.3GB** · 스왑 그대로 [실측] → 게임 서버와 **같이 돈다**.
   KorNLI 95만 전부는 1 epoch **35~74시간**이라 안 된다 (앞 추정 50~80시간과 맞다).
3. **메인 PC 는 1·2순위보다 못하다.** GPU 는 **RTX 3060 Ti 8GB** 다. 속도는 8060S 와 비슷하거나 낫겠지만 [추정],
   torch 가 없어(CUDA torch 설치 승인 필요) · VRAM 8GB 에 roberta-large AdamW 가 빠듯하고 · 지금 데스크톱 앱이 6.8GB 를 쓰고 · C: 여유가 45GB 뿐이다.
4. **base 로 줄이기는 보험이다.** 실측 처리량 base 3.4배 · small 6.8배 빠르다. KLUE 논문 dev 정확도는 large 89.5 · base 86.3 · small 81.0.
   자 0.85·0.75 는 KLUE 정확도가 아니라 우리 실물 쌍 점수라 직접 못 대 보지만, large→base 3.2점 차이는 실물에서 더 벌어질 수 있어 **large 먼저, 안 되면 base**.
5. **바깥 기계(Kaggle·Colab·RunPod)** 는 기반 학습(공개 NLI)만 올릴 수 있고, mem 쌍 덧학습은 로컬이어야 한다. 1순위가 되면 쓸 까닭이 적다. 선택지로만 남긴다.

### 2-2. 웹에서 찾은 것

- **공식 pytorch.org ROCm wheel 은 gfx1151 을 안 담는다.** 장치는 보이지만 계산에서 HIP 오류가 난다는 보고가 여럿이다.
  쓰는 길은 AMD TheRock 야간 판 `pip install --index-url https://rocm.nightlies.amd.com/v2/gfx1151/ --pre torch` 이다. 우리 이미지의 `rocm7.15.0a2026…` 이 바로 이 꼴이다.
  AMD 공식 지원표에 gfx1151 이 정식으로 올랐다는 발표는 못 찾았다.
- **attention** : gfx1151 은 기본으로 flash·메모리 절약 SDPA 가 없어 `math` 길로 간다. `TORCH_ROCM_AOTRITON_ENABLE_EXPERIMENTAL=1` 을 켜면 AOTriton flash 가 붙어 한 attention 측정이 204ms → 12ms 가 됐다는 보고가 있다(fp16 · 길이 4096). 우리는 길이 128~256 이라 attention 몫이 작아 효과도 작다 [추정].
  같은 곳의 직접 짠 커널은 **순전파만** 된다 — 학습에는 못 쓴다.
- **계산 성능** : 8060S 는 fp32 약 7 TFLOPS · bf16 약 31 TFLOPS 라는 보고(2차 자료, 검증 안 됨). **bf16 으로 학습하라**는 권고가 있다.
- **BERT/RoBERTa 급 학습 처리량 실측 공개 자료는 이번에도 못 찾았다.** 찾은 것은 LLM 추론 · Unsloth LoRA · Gemma 1B 전체 미세학습 이야기뿐이다.
- **GTT** : 우리 BIOS 는 VRAM 2GB · GTT 48GB 다. llama `agent` 가 GTT 23GB 를 쓰니 학습 10GB 를 더해도 48GB 안이다. `flashnext`(GTT 41.7GB) 가 떠 있으면 **못 같이 돈다.**

### 2-3. GPU 처리량 어림 [추정]

- CPU 실측(3절) 이 낸 실효 계산량은 약 **0.8 TFLOPS** 다 (학습 계산 6 × 층 파라미터 약 3억 × 128 토큰 ÷ 0.28초).
- 8060S 를 bf16 31 TFLOPS 의 25~50% 로 보면 CPU 의 **10~18배**, fp32 7 TFLOPS 의 50% 면 **4배**.
- 그래서 KLUE 25k + KorNLI 5만 1 epoch(CPU 2.8~5.9시간) → GPU **약 20~90분** [추정]. 넓은 까닭은 bf16 이 제대로 도는지 · attention 이 `math` 길인지를 모르기 때문이다. 첫 벤치로 좁힌다.

## 3. CPU 실측 (미니PC, 10-09 00:34~00:38)

**방법** : 기존 CPU venv(`~/judge-laya/.venv`, `torch 2.14.1+cpu` · transformers 5.18.0)에서 `RobertaConfig` 로 **무작위 초기화**한 모델(가중치 안 받음, vocab 32000) 에 batch 16 · fp32 · AdamW lr 1e-5 학습 스텝을 10~14번 돌리고, 처음 2스텝을 뺀 평균을 썼다.
`systemd-run --user --scope -p MemoryMax=12G -p MemorySwapMax=0 nice -n 19` 로 묶어 게임 서버를 지켰다. 5초마다 가용·스왑을 적었다.
스크립트 `/tmp/cpubench.py` · 감싸개 `/tmp/runbench.sh` · 기록 `/tmp/cpubench.log` (스크래치패드에도 사본).

| 모델 (크기) | seq | 스레드 | 스텝 초 | **쌍당 초** | 피크 RSS |
| --- | --- | --- | --- | --- | --- |
| large (336.7M · 24층 1024) | 128 | 16 | 4.51 | **0.282** | 10.4GB |
| large | 128 | 32 | 4.58 | 0.286 | 10.3GB |
| large | 64 | 16 | 2.15 | **0.134** | 7.5GB |
| base (110.6M · 12층 768) | 128 | 16 | 1.31 | 0.082 | 4.0GB |
| small (68.1M · 6층 768) | 128 | 16 | 0.66 | 0.041 | 2.5GB |

- **32스레드는 16스레드보다 안 빠르다** (SMT 몫 없음). 16스레드로 쓴다.
- 메모리 : 시작 가용 24.9GB · large seq 128 판 중 **최저 14.3GB** · 스왑 77MB 그대로 · 판마다 끝나고 24.1~24.9GB 로 돌아옴 [실측]. 게임 서버는 내내 떠 있었다.
- 앞 조사 추정(쌍당 0.2~0.3초 · 메모리 8~12GB)은 **seq 128 에서 맞았다.**

**1 epoch 시간 셈** (large · 16스레드)

NLI 쌍은 짧아(KLUE 전제 한 문장 + 가설 한 문장) 길이별 묶음 패딩이면 실제 길이는 64 가까이가 많을 것이다 [추정]. 그래서 **seq 64 = 낙관, seq 128 = 보수** 로 둘 다 적는다.

| 판 | 쌍 수 | seq 64 (0.134초) | seq 128 (0.282초) |
| --- | --- | --- | --- |
| KLUE-NLI | 24,998 | 0.9시간 | 2.0시간 |
| KorNLI 5만 | 50,000 | 1.9시간 | 3.9시간 |
| KorNLI 10만 | 100,000 | 3.7시간 | 7.8시간 |
| KorNLI 전부 | 942,854 | 35시간 | 74시간 |
| **KLUE + KorNLI 5만** | 75,000 | **2.8시간** | **5.9시간** |
| KLUE + KorNLI 10만 | 125,000 | 4.7시간 | 9.8시간 |
| mem 덧학습 (max_len 256) | 1,230 | — | 약 12분 [추정 : 쌍당 0.6초] |

- 보통 2~3 epoch 를 도니 「KLUE + 5만」 은 **6~18시간**, 밤 한 판이다.
- 실제 KLUE·KorNLI 토큰 길이는 klue 토크나이저로 재지 않았다(모델 안 받음). 받은 뒤 첫 일로 잰다.

- **자에 닿을 전망** : 자 0.85·0.75 는 우리 실물 쌍(K 48 · game90) 점수라 KLUE 정확도와 바로 이어지지 않는다. 근거 있는 것은 「크기 차이가 공개 벤치에서 3.2점(large→base) · 8.5점(large→small)」 이라는 것뿐이다.
  실물 쌍은 공개 자료보다 어렵고 길어(근거 p95 560자) 차이가 더 벌어질 가능성이 크다 [추정]. small 은 자 0.85 에 못 닿을 쪽으로 본다.
- 그래서 **large 로 시작하고, base 는 빠른 되풀이(하이퍼파라미터 고르기 · 파이프라인 시험)용과 GPU 길이 막힐 때 보험** 으로 둔다.

## 6. 길별 비교

기준 : KLUE 25k + KorNLI 5만 = 7만 5천 쌍 1 epoch.

**권장**

1. **1순위 — 미니PC GPU, 있는 ComfyUI 이미지로.** 깔 것이 없고, 가장 빠를 것이며, 덧학습·측정까지 한 기계에서 끝난다.
   차례 : ① 게임 서버 내린 낮에 무작위 초기화 large 로 10~20 스텝 벤치(bf16 · fp32 둘, `TORCH_ROCM_AOTRITON_ENABLE_EXPERIMENTAL=1` 켠 판·끈 판) — 이번 `cpubench.py` 를 장치 인자 `cuda` 로 그대로 쓴다 ② 멀쩡하면 klue/roberta-large 로 진짜 판.
2. **2순위 — 미니PC CPU, KLUE + KorNLI 5만.** GPU 벤치가 멎거나 이상하면 바로 이 길로 간다. 실측으로 게임 서버와 같이 돈다는 것이 확인됐고 밤 한 판(6~18시간)이면 3 epoch 가 끝난다.
- 메인 PC 와 바깥 기계는 위 둘이 다 막힐 때만 꺼낸다.
