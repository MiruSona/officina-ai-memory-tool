## 깨진 것

### 높음

#### H-1. `mem index` 가 어떤 기억 글에서 통째로 죽는다 (panic · 고루틴이라 recover 못 함)

```
panic: runtime error: slice bounds out of range [1423:1417]
github.com/sugarme/tokenizer/normalizer.(*NormalizedString).TransformRange(…)
  normalizer/normalized.go:768
github.com/sugarme/tokenizer/pretokenizer.(*Metaspace).PreTokenize.func1(…)
  pretokenizer/metaspace.go:81
<모듈>/internal/embed.(*Model).tokenize.func1(…)
  internal/embed/model.go:337
created by …embed.(*Model).tokenize in goroutine 1
  internal/embed/model.go:334
```

**재현 (차례를 지켜야 한다)**

```bash
# 1. 임베딩이 켜진 저장소를 만든다 (install --bundle --apply → index --full → vectors.bin 생김)
# 2. 재현 파일을 놓는다
cp <스크래치패드>/sec/panic-repro.md Memory/store/2026/08/20260823-cc001111.md
# 3. vectors.bin 을 지워 그 파일이 새로 임베딩되게 만든다  ★ 이 단계를 빼면 안 터진다
rm Memory/vectors.bin
mem index --full        # → panic · 3/3 재현
```

파일은 **머리말 요약에 제로폭·방향뒤집기 글자 + 백틱 + 마크다운 기호**가 있고 **본문에 400자짜리 한글 한 줄 + ANSI + BEL + NUL** 이 있다. 둘 중 하나만으로는 안 터진다 — **둘이 같이 있어야** 터졌다(각각 따로는 12꼴을 시험해 전부 통과).

**왜 나쁜가**

- 고루틴 안에서 터지므로 `internal/embed/model.go:334` 위쪽의 `recover` 로 **못 잡는다.** 프로세스가 통째로 죽는다.
- 죽으면 **그 뒤 승격·색인이 통째로 안 돈다.** 새 기억이 조용히 안 들어간다.
- 종료 코드가 Go 의 panic 기본값 **2** 라 「검사 실패」와 구분이 안 된다. 사람이 스택을 봐야 안다.
- `mem lint`·`mem search`·**훅은 안 죽는다**(훅은 모델을 안 싣는다 — 결정 15가 여기서 값을 했다). 그래서 **세션은 멀쩡한데 색인만 멎는다** — 가장 늦게 들키는 꼴이다.

**고치는 법(제안)** : `tokenize` 안의 고루틴에 `defer recover()` 를 두고, 걸린 기억 하나는 **벡터 없이 건너뛰고 나머지를 계속** 간다. 3자 라이브러리를 못 고치니 여기서 막는 것이 유일한 자리다. `internal/embed/model.go:334`.

### 중간

#### M-1. `migrate` 가 `sources` 칸은 안 훑는다 (I4)

`cmd/mem/cmd_migrate.go:507~512` 가 훑는 것은 **본문 · summary · title 셋뿐**이다.
`add`·승격·`lint` 는 `secret.MemoryText(Title, Summary, Sources, Body)` 로 **`sources` 까지** 훑는다 — 자리가 어긋나 있다.

```bash
# sources: ["note:ghp_…"] 를 가진 옛 규격 md 를 놓고
mem migrate --apply     # → exit 0 · 그 파일을 새 규격으로 다시 씀 (열쇠가 살아 남는다)
```

번지는 범위는 좁다 — 다시 쓴 그 파일을 `mem index` 가 **자기 검사로 잡아 색인에서 뺀다**(`search`·훅에는 안 샌다). 그래도 **git 에는 들어간다.** 설계 7절이 「칸 이름을 손으로 적어 두면 뒤에 늘어난 칸이 검사 없이 지나간다」고 못 박은 그 실수 그대로다.

#### M-2. 비밀정보로 막았는데 종료 코드가 4가 아니다

| 자리 | 지금 | 설계 |
| --- | --- | --- |
| 승격(`index`) 이 큐 JSON 을 `inbox/bad/` 로 보냄 | **exit 0** | 4 |
| `index` 가 손으로 고친 `store/` md 를 색인에서 뺌 | **exit 2** | 4 |

막기는 확실히 막는다(값도 안 찍고 `store/` 에 안 들어간다). **자동화가 종료 코드로만 보면 「아무 일 없었다」로 읽는다**는 것이 문제다. CI 나 스크립트가 이걸로 갈린다.

#### M-3. 규격을 벗어난 md 에도 벡터를 만든다 (I7)

### T1 — auto 모드에서 승인 창이 뜨나 (1분)

> **(2026-08-24 실측으로 고침) auto 모드가 아니라 manual(기본) 모드에서 잰다.** auto 모드는 분류기가 allow 밖 명령도
> 안전하다고 보면 그냥 통과시켜, allow 규칙이 실제로 사는지 알 수 없다. Claude Code 화면 표시가 `manual mode` 인
> 상태(Shift+Tab 으로 바꾼다)에서 아래를 시킨다. 근거 : `../History/2026-08-24-사용자실측.md` 3절.
> **Windows 준비 한 줄** : Windows 의 Claude Code 는 `Bash` 도구가 아니라 `PowerShell` 도구로 명령을 돌리므로,
> allow 규칙은 `PowerShell(mem …)` 꼴이어야 산다(`Bash(mem …)` 꼴은 안 맞는다). 갈래 A 가 `init` 을 고치는 중이다.

```powershell
cd C:\temp\memtest
mem init      # 훅 + allow 11개 + 규칙 블록
mem add --type decision --title "티원 시험용 결정 하나다" --summary "auto 모드에서 승인 창이 뜨는지 재려고 넣는 결정 한 건이다." --tags test,build --scope aimemorytool --sources note:T1 --body "첫 줄에 결론을 스무 자 넘게 적는다.`n무엇이 보였나 : 승인 창이 안 떴다.`n무엇을 고쳤나 : 표에 적었다."
mem index
```

1. 이 폴더에서 Claude Code 를 연다. **폴더 신뢰(trust)를 누른다.** ★ 안 누르면 `allow` 가 안 산다.
2. **manual(기본) 모드 그대로 둔다.** (2026-08-24 실측으로 고침 : auto 모드는 allow 밖 명령도 분류기가 통과시켜 재지 못한다)
3. 아래를 하나씩 시키고 **승인 창이 뜨는지** 표에 적는다.

| 시킬 말 | 기대 |
| --- | --- |
| `mem search 시험 을 돌려서 보여줘` | **안 뜬다** |
| `mem show <id> 해 줘` | **안 뜬다** |
| `mem add …` 한 건 넣어 줘 | **안 뜬다** |
| `mem index` 돌려 줘 | **안 뜬다** (인자 없는 꼴만 allow) |
| `mem index --full` 돌려 줘 | **뜬다** (정상) |
| `mem status` 보여 줘 | **안 뜬다** |
| `mem lint` 돌려 줘 | **안 뜬다** |
| `mem review` 보여 줘 | **안 뜬다** |
| `mem review --kind conflict` 보여 줘 | **안 뜬다** (2026-08-24 실측으로 고침 : 원래 `--kind dup` 이라 적혀 있었으나 없는 갈래다. 실제 갈래는 `expired`·`conflict`·`stale`·`value`·`cold`·`link`·`title`·`held`) |
| **`mem review --promote <id>`** 해 줘 | **뜬다** ★ 여기가 결정 60 의 핵심 — `review` 를 두 줄로 가른 이유다. (2026-08-24 실측으로 고침 : `--promote` 는 머리말 `review: true` 인 기억에만 된다. 여기 T1 절차의 `mem add …` 시험 기억으로는 「승격을 기다리는 중이 아니다」로 실패하니, 승인 창 시험으로 쓰려면 `mem add --hold` 로 넣은 기억을 쓴다 — `mem add --hold` 가 `review: true` 로 들어가는 것은 `mem add --help` 로 확인함) |

| `mem eval` 돌려 줘 | **안 뜬다** |
| `mem gc` 돌려 줘 | **뜬다** (일부러 뺐다) |
| `mem install` 돌려 줘 | **뜬다** (일부러 뺐다) |
| `mem init` 돌려 줘 | **뜬다** (일부러 뺐다) |

## 못 한 것과 이유

- **T1 · T3 · T2 는 못 했다.** 진짜 Claude Code 세션과 PATH 를 건드리는 `install --apply` 가 필요하다.
  위에 v0.3 판 절차서를 적어 두었다. **auto 모드 승인 0회는 아직 아무도 안 쟀다** (v0.2 도 못 쟀다).
- **심볼릭 링크는 못 만들었다** — 관리자 권한이 필요하다. **정션만** 시험했다(막혔다). T18 절차서로 남겼다.
- **H-1 을 더 작게 못 줄였다.** 「요약의 위험 글자 + 긴 본문」 둘이 같이 있어야 터진다는 데까지만 좁혔고,
  12꼴을 따로 시험했지만 어느 글자 하나가 방아쇠인지는 못 짚었다. 라이브러리 안쪽이라 시간이 더 든다.
- **`tags --suggest` · `status --embed` 의 살균은 못 봤다** — 살균할 자료(동의어 후보·모델 이름)를 만들 길이
  이번 저장소에 없었다. 「자리가 같은 함수를 쓴다」는 코드로만 봤고 결과는 못 봤다.
- **훅이 색인을 2회 넘게 여는지** 못 쟀다 — 밖에서 셀 방법이 없다. 내부 시험(`internal/hook`)이 통과하는 것만 봤다.
- **`migrate --restore` 왕복은 못 했다** — 비밀정보 시험 뒤 저장소를 되돌려서 아카이브가 안 남았다.
- 실데이터·대량(수천 건) 저장소에서는 안 돌렸다 — 다른 에이전트 영역이다.
- 라이선스(T12)는 이번에 안 봤다 — v0.2 에서 12개를 확인했고 `THIRD-PARTY.md` 가 이미 있다.
