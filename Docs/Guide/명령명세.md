# 명령 명세 (v0.4)

> 이 문서는 **명세**다. **무엇**만 적는다. **왜 그렇게 정했는지**는 `../Design/2026-08-24-v0.4설계.md` 가 맡는다.
> v0.3 판을 베껴 **v0.4 가 바꾼 자리만** 고쳤다. v0.3 문서는 그대로 둔다.
> 옵션은 **코드가 정답**이다. 아래 표는 코드가 실제로 받는 옵션이다.
> **`mem help install` 과 `mem help status` 의 도움말 글은 아직 v0.2 판이라 v0.3 옵션이 빠져 있다** —
> `install --bundle/--no-embed/--check/--model` 과 `status --embed` 는 도움말에 안 뜨지만 동작한다. 도움말 글 고치기는 다음 판 몫이다.

명령은 **17개**다.

---

## 1. 공통 규칙

| 규칙 | 값 |
| --- | --- |
| 출력 | 사람이 읽는 Markdown. `--json` 은 한 줄 JSON. **0건도 `null` 이 아니라 `[]`** |
| 언어 | 메시지·도움말 전부 한글. 오류는 stderr |
| 저장소 | **프로젝트 저장소 하나뿐이다.** cwd 에서 위로 `Memory/mem.toml` 을 찾되 `.git` 이 있는 폴더에서 멈춘다. `--repo <폴더>` 로 직접 가리킨다 |
| 전역 저장소 | **없다.** `--global`·`--no-global` 은 코드에서 걷어 냈다. 개인 기억은 Claude 내장 기억이 맡는다 |
| 색인 따라잡기 | 읽기 명령은 시작할 때 **락을 기다리지 않고 한 번만** 따라잡는다. `--no-index` 로 끈다 |
| 모르는 옵션 | **바로 실패한다.** 다음 인자를 값으로 삼키지 않는다 |
| 도움말 | `mem help <명령>` 과 `mem <명령> --help` 가 같은 문장을 쓴다 |

### 종료 코드

| 코드 | 뜻 |
| --- | --- |
| `0` | 정상 |
| `1` | 사용법 잘못 |
| `2` | 검사 실패 (품질 관문 거절 · lint 오류 · eval 미달 · 낡은 exe) |
| `3` | 저장소 없음 · **`eval` 은 「골든셋이 없어 잴 것이 없다」도 3** (v0.4 결정 17) |
| `4` | 보안 차단 (비밀정보 · 그림자 exe · **`migrate` 가 옮길 기억에서 비밀정보를 봄**) |
| `5` | 파일·권한·DB 손상 |
| `6` | 락을 못 얻음 |

**`mem hook` 만 무슨 일이 있어도 `0` 이다.**

## 2. 명령 17개

### `mem install` — 기계마다 한 번, 사람이

exe 를 `%USERPROFILE%\.aimemory\bin\` 에 복사(있으면 `.bak` 로 밀어냄)하고 **사용자 PATH 맨 앞**에 그 폴더를 넣는다.
**v0.3 부터 의미 검색 파일(모델·토크나이저·`onnxruntime.dll`)도 같이 놓는다.**

| 옵션 | 뜻 |
| --- | --- |
| `--apply` | **실제로 적용한다.** 안 주면 계획 표만 보여주고 아무것도 안 고친다 |
| `--dry-run` | 무엇을 할지만 보여준다 (`--apply` 없을 때가 기본이라 안 줘도 같다) |
| `--no-path` | PATH 는 안 건드린다 (`--apply` 와 같이 써야 뜻이 있다) |
| `--no-embed` | **의미 검색을 빼고** 설치한다. 낱말 검색만 돈다 |
| `--bundle <폴더>` | 인터넷 대신 그 폴더에서 가져온다 (오프라인 꾸러미) |
| `--model <이름>` | 쓸 모델. 기본은 `multilingual-e5-small-ko-v2` |
| `--check` | 아무것도 안 고치고 **무엇이 깔렸고 해시가 맞는지만** 말한다 |

종료 코드 `0` · `1` (`--check` 는 못 갖췄으면 `2`). PATH 는 **새 터미널부터** 잡힌다.
원래 PATH 는 `~/.aimemory/path-backup.txt` 에 남는다.

**의미 검색 파일 자리** (전부 `~/.aimemory/` 안이다. 네 번째 경로를 만들지 않는다)

| 무엇 | 자리 | 크기 |
| --- | --- | --- |
| 모델 | `~/.aimemory/models/<모델이름>/model_int8.onnx` | 113MB |
| 어휘 | 같은 폴더 `tokenizer.json` (+ 우리가 굽는 캐시 `tokenizer.bin` 4.1MB) | 16.3MB |
| 런타임 | `~/.aimemory/bin/onnxruntime.dll` | 15.4MB |

- **받은 파일은 exe 안에 박아 둔 SHA-256 과 맞아야만 쓴다.** 안 맞으면 지우고 낱말 모드로 설치를 끝낸다.
- **DLL 은 언제나 절대경로로 로드한다.** 이름만 넘기면 System32 의 옛 `onnxruntime.dll` 이 잡혀 죽는다.
- **못 받아도 설치는 성공한다** (오프라인·해시 불일치). 경고 한 줄을 남기고 낱말 검색만으로 끝낸다.
- 라이선스 전문은 파일 옆에 같이 놓는다 (`THIRD-PARTY.md` 「같이 놓는 파일」).

```
mem install                            계획 표만
mem install --apply                    exe · PATH · 모델까지
mem install --bundle <폴더> --apply    인터넷 없이
mem install --no-embed --apply         낱말 검색만
mem install --check                    무엇이 깔렸나
```

### `mem init` — 이 프로젝트에 저장소를 붙인다 (여러 번 돌려도 안전)

멱등으로 여덟 가지 : `Memory/` 뼈대 · `mem.toml`(있으면 **빠진 키만** 채움) · `vocab.toml` · `log.md` ·
`사용법.md`(있으면 **안 덮음**) · `.gitignore`/`.gitattributes` 줄 · `.claude/settings.json` 훅 둘 + allow 규칙 ·
`AGENTS.md`(없으면 `CLAUDE.md`) 끝의 규칙 블록.

| 옵션 | 뜻 |
| --- | --- |
| `--repo <폴더>` | 저장소를 만들 자리를 직접 가리킨다 |
| `--dry-run` | 무엇을 할지만 보여준다 |
| `--no-hook` | `settings.json` 훅은 안 붙인다 (`SessionStart`·`SubagentStart` 둘 다) |
| `--no-subagent-hook` | `SubagentStart` 훅만 뺀다. `SessionStart` 는 그대로 붙인다 |
| `--gemini` | `GEMINI.md`·`.gemini/settings.json` 에도 붙인다 |
| `--solo` | 혼자 쓰는 사람이다. 내장 auto memory 를 끄자고 **권하기만** 한다 |
| `--undo` | init 이 붙인 것을 떼어낸다. **`Memory/` 와 `.gitignore` 는 그대로 둔다** |

종료 코드 `0` · `1`.

**allow 규칙은 명령 11개 × 두 꼴 = 22줄이다 (v0.4).** Windows 의 Claude Code 는 명령을 `Bash` 도구가 아니라
`PowerShell` 도구로 돌려서, `Bash(mem search:*)` 만 넣으면 **하나도 안 맞고** `mem search` 마다 승인 창이 뜬다
(2026-08-24 사용자 실측 3절). 그래서 명령마다 `Bash(mem search:*)` 와 `PowerShell(mem search *)` 를 짝으로 넣는다.
인자 글로브는 Bash 가 `:*`, PowerShell 이 ` *` 다.

| 명령 | Bash 꼴 | PowerShell 꼴 |
| --- | --- | --- |
| `search` `show` `add` `set` `lint` `tags` `eval` | `Bash(mem <명령>:*)` | `PowerShell(mem <명령> *)` |
| `review` | `Bash(mem review)` + `Bash(mem review --kind:*)` | `PowerShell(mem review)` + `PowerShell(mem review --kind *)` |
| `index` | `Bash(mem index)` (정확 일치) | `PowerShell(mem index)` |
| `status` | `Bash(mem status:*)` | `PowerShell(mem status *)` |

`index` 만 정확 일치다 — `--full` 은 색인을 통째로 다시 만드니 승인 창이 떠야 한다. `status` 는 읽기 전용이라
넓혔다 (v0.4 U4). 그 전의 `Bash(mem status)` 는 폐기 목록에 넣어 `--undo` 가 같이 뺀다.
`gc` · `install` · `uninstall` 은 **안 넣는다** — 지우거나 기계를 건드리는 것은 사람이 본다.

`mem status --doctor` 의 「auto 모드 allow 규칙」은 **두 꼴이 다 있어야 O** 다. Bash 꼴만 있으면
「PowerShell 꼴이 없다」고 알려 준다.

**`mem.toml` 의 `[embed] model`** (v0.4) — 의미 검색이 쓸 모델 이름이다. **비면 exe 가 아는 기본 모델**이다.
어느 것이 이기나 : `MEM_EMBED_MODEL`(재기용 뒷문) → `[embed] model` → exe 기본값.
**`mem install --model` 은 모델을 깔 뿐이고 어느 것을 쓸지는 안 정한다.**
옛 `mem.toml` 에는 이 키가 없으니 `init` 이 **빠진 키만** 채운다 (있던 값은 안 덮는다).

### `mem add` — 기억 한 건을 관문에 걸고 통과하면 저장한다

`inbox/new/` 에 넣은 뒤 **쓰기 락을 잡으면 제 큐 파일만 그 자리에서 승격하고 증분 색인한다**
(2026-09-26 · `../Design/2026-09-23-id굳히기·inbox정리·fixture줄끝설계.md` 2장).
그래서 stdout 의 id 가 **실제로 남은 id** 고, 바로 `show`·검색에 보인다. 남의 큐 파일 · gc · 벡터 ·
이웃 링크는 안 한다 — 벡터와 이웃 링크는 다음 `mem index` 가 채운다.
락은 50ms 간격으로 최대 1초 기다린다. 그래도 못 잡으면 큐에 둔 채 큐 id 를 찍는다 (예전 동작).

| 승격 결과 | stdout | 끝줄 (stderr) | 종료 |
| --- | --- | --- | --- |
| 새 파일 | 새 id | `저장됨 : <id>` | 0 |
| 완전중복 | 쌍둥이 id | `저장됨 : <id> — 같은 본문이 이미 있어 그 기억을 가리킨다` | 0 |
| 닮은 기억 뒤에 붙음 | 닮은 기억 id | `저장됨 : <id> — 닮은 기억 뒤에 한 절로 붙였다` | 0 |
| bad (규격·비밀정보) | 없음 | `저장 안 됨 — <까닭>. inbox/bad 에 뒀다 (mem index --bad)` | 2 · 4 |
| 락 못 잡음 | 큐 id | `저장됨 : <id> — 색인 대기다. mem index 뒤에 …` | 0 |
| 색인을 새로 세울 판 | 큐 id | `저장됨 : <id> — 색인을 새로 세워야 하는 판이라 큐에 뒀다 …` | 0 |
| 기다리는 사이 남이 먼저 승격 | 남이 남긴 실제 id | 위 세 줄 중 하나 (새 파일 · 쌍둥이 · 붙음) | 0 |
| 남이 먼저 승격 · id 모름 | 없음 | `이미 승격됨 — … id 는 mem index 뒤 mem search 로 확인한다` | 0 |

- **색인을 새로 세울 판**은 색인 방식이 바뀌었거나 index.db 가 깨졌거나, 새로 받은 저장소처럼
  색인이 store/ 를 한 번도 안 본 때다. 빈 색인에 대고 승격하면 쌍둥이·닮은 기억을 못 보고,
  add 한 번이 store 전체 재색인을 떠안는다. 그래서 큐에 두고 다음 `mem index` 에 맡긴다.
- **남이 먼저 승격**: 락을 기다리는 사이 `mem index`·훅·다른 add 가 이 큐 파일을 먼저 먹을 수 있다.
  승격하는 쪽은 `index.db` 의 영수증 표(`promoted`, 10분 보관)에 「큐 파일 → 실제 id」 를 남기고,
  늦게 온 add 는 거기서 실제 id 를 읽는다. 영수증이 없으면(색인을 새로 세웠다) 틀릴 수 있는 큐 id 를
  찍지 않고 stdout 을 비운다.

| 옵션 | 뜻 |
| --- | --- |
| `--type <종류>` | `todo` `history` `issue` `caution` `decision` `howto` `fact` (**필수**) |
| `--title <제목>` | 6~40자 한 줄 (**필수**). 요약 앞머리를 그대로 베끼면 거절 |
| `--summary <한 줄>` | 30~120자 (**필수**) |
| `--tags a,b` | 표준 목록 안의 소문자 태그 2~5개 (**필수**). 별칭은 자동으로 바뀐다 |
| `--scope <범위>` | 표준 목록 안의 툴·부품 이름 통째 하나 (**필수**) |
| `--sources a,b` | 근거. `file:` `commit:` `url:` `mem:` `note:` 로 시작 (`decision`·`issue`·`caution` 은 1개 이상) |
| `--author <누가>` | `human:<아이디>` · `<도구>/<버전>` · `hook:<이름>` (안 주면 `mem/<판>`) |
| `--body <본문>` | 본문. 안 주면 표준입력을 읽는다 |
| `--stdin` | 본문을 표준입력에서 읽는다 |
| `--date <날짜>` | 기억의 날짜 (기본 오늘) |
| `--invalid-at <날짜>` | 이 날부터 이 기억은 무효다 |
| `--todo-status <값>` | `todo` 의 칸 : `open` `doing` `done`. **안 주면 `open` 이다** |
| `--severity <세기>` | `issue`·`caution` 일 때 필수 : `low` `mid` `high` (`medium`·`middle` 은 `mid` 로 바꿔 받는다) |
| `--by <옛id>` | 그 결정을 이 기억이 덮는다 (옛 기억에 덮임 표시를 단다) |
| `--new` | 닮은 기억이 있어도 정말 다른 주제다 |
| `--hold` | **보류로 넣는다** — 머리말에 `review: true` 가 붙는다. 검색·훅에 안 뜨고 `mem review --promote <id>` 로 사람이 연다 (결정 6) |
| `--importance <1~5>` | 중요도 (기본 3) |
| `--stale-after <날짜>` | 이 날 지나면 다시 보자고 예약한다 |
| `--link a,b` | 이어지는 기억 id |
| `--pin` | 접기·정리에서 뺀다 |
| `--check` | **미리보기.** 관문만 돌리고 무슨 일이 있어도 저장하지 않는다 |
| `--json` | 판정을 한 줄 JSON 으로 준다. 저장했으면 `promote`(new · duplicate · appended · bad · left · gone)와 `id` 칸이 붙고, 둘째 줄은 id 다 |
| `--jsonl` | 여러 건을 표준입력에서 한 줄에 하나씩 받는다 (**관문에서 걸리면 전부 취소**, 승격에서 bad 로 간 줄은 그 줄만 빠진다 · 종료 2·4) |
| `--repo <폴더>` | 저장소를 직접 가리킨다 |

- **경고는 저장을 막지 않는다.** 경고가 뜨고 id 가 찍혔으면 들어간 것이다.
- **`--by` 로 넣은 기억은 색인 때 닮은 기억에 합쳐지지 않는다** (2026-09-23 고침).
  add 와 덮임 표시를 **한 락 안에서 같이 먹어서** 옛 기억은 늘 파일이 있는 id 를 가리킨다.
  옛 id 가 없는 등으로 덮기만 실패하면 add 는 들어가고 끝줄이 「덮기는 실패했다」 이며 종료 `1` 이다.
  덮임 표시만 아직 안 먹혔으면(파일 계층 실패) 「덮었다」 대신 「덮임 표시는 색인 대기」 를 알리고 종료 `0` 이다.
- `--jsonl` 은 락을 묶음 전체에 한 번 잡고 줄 차례대로 승격한다. 끝줄은 `N 건을 저장했다.` 다.
  **관문**에서 한 줄이라도 걸리면 하나도 안 넣는다(I4). 관문을 다 지난 뒤 **승격**에서 bad 로 간 줄은
  그 줄만 빠지고, 번호와 까닭을 찍고 종료 `2`(비밀정보면 `4`)다. 큐에 쓰다가 넘어지면 그 앞 줄까지는
  승격하고 id 를 찍은 뒤 멈춘다. 묶음 줄끼리는 관문이 서로를 못 본다 — 한 건씩 치는 add 와 다르다.
- 관문이 **바로 앞 add 를 색인에서 본다.** 그래서 같은 scope 결정·같은 본문을 잇달아 넣으면 두 번째가 관문(`decision-gate` 등)에 걸린다. 일부러 새로 두려면 `--new` 를 붙인다 (2026-09-26 부터).
- 표준 scope 를 하나도 안 정한 저장소에서는 목록 밖 태그·scope 를 경고로만 알린다.
- 종료 코드 `0` · `1` · `2`(품질 관문 거절) · `3` · `4`(보안 차단).

#### `vocab.toml` 의 `[type.<이름>]` — 종류별 취급 표

`--type` 마다 다른 취급(필수 칸·본문 꼴·낡음 일수·검색 반감기·가산·gc 접기 면제·훅 절 이름·값 검사)은
코드 안 기본표(7종)로 돌되, `Memory/vocab.toml` 의 `[type.<이름>]` 절로 칸 단위로 덮어쓸 수 있다.
안 적은 종류·안 적은 칸은 기본값 그대로다. 기본 7종은 못 지운다. 모르는 칸·값은 경고만 찍고 무시한다.
종류를 늘리는 명령은 없다 — 파일을 직접 고친다.

### `mem set` — 있는 기억의 도구 칸을 고친다

본문·요약을 손으로 바꾸려면 파일을 고치고 `mem index` 를 돌린다.

| 옵션 | 뜻 |
| --- | --- |
| `--by <새id>` | 이 기억을 그 기억이 덮었다 (`superseded_by` 와 `invalid_at` 을 같이 채운다). 덮은 뒤 **이 기억을 근거로 삼은 기억이 몇 건인지 한 줄 알려준다** — 파일에는 아무것도 안 쓴다. **자기 자신은 못 준다** — 그러면 살아 있는 기억이 검색에서 사라진다 |
| `--by-new` | 덮을 새 기억이 아직 없다. 오늘부터 검토 큐에 올리고 다음 명령을 알려준다 |
| `--todo-status <값>` | `open` `doing` `done` |
| `--stale-after <날짜>` | 다시 볼 날을 예약한다 |
| `--pin` / `--unpin` | 고정을 켜고 끈다 |
| `--done` | `todo_status` 를 `done` 으로 |
| `--summary` `--title` `--tags` `--scope` `--severity` `--importance` `--invalid-at` | 그 칸을 바꾼다 |
| `--links a,b` | 이어지는 기억 id 를 **통째로 갈아 끼운다** |
| `--link <id>` | 이어지는 기억 id 를 **하나 더한다.** 있던 것은 그대로고, 같은 id 를 또 줘도 두 벌이 안 된다 (v0.4) |
| `--body <본문>` / `--stdin` | 본문을 통째로 갈아 끼운다 |

- **`--by` 뒤의 알림은 세기만 한다.** 판정은 `mem review --kind basis` 에서 사람이 한다.
  - **셈은 검토 큐와 같은 규칙이다.** 이미 죽었거나 `stale_after` 로 다시 볼 날을 미뤄 둔 참조자는
    큐에 안 오르니 건수에서 뺀다. 참조자가 있는데 하나도 큐에 안 오르면 그 사실만 말하고
    `mem review` 로 보내지 않는다 — 「N건 있다」 해 놓고 큐가 비면 안 된다.
  - **id 는 6개까지만 찍고 나머지는 「… 외 N건」이다** (`mem review` 의 「같이 볼 것」 줄과 같은 자).
  - 0건이면 안 찍는다. **못 셌으면 0건이라고 말하지 않는다** — 색인이 없을 때 · 판이 낮아 색인을
    통째로 다시 만들었을 때 · `--no-index` 일 때는 저마다 왜 못 셌는지를 말한다.
- **값을 그 자리에서 검사한다.** 규격에 안 맞으면 큐에 넣지 않고 바로 거절한다.
- **`--body` 에도 비밀정보 검사가 걸린다.** 본문 검사가 아카이브 쓰기보다 먼저다.
- **`--link` 는 사람이 적은 `links` 만 건드린다.** `auto_links` 는 색인이 만드는 파생 표라 안 만진다.
  둘을 같이 주면 `--links` 로 갈아 끼운 뒤 그 뒤에 `--link` 를 더한다.
- 종료 코드 `0` · `1` · `2` · `4`.

### `mem search` — 찾는다

질의가 없으면 조건에 맞는 목록만 준다.

| 옵션 | 뜻 |
| --- | --- |
| `--type` `--scope` `--tag` `--status` `--severity` | 조건을 좁힌다 |
| `--pinned` | 고정한 것만 |
| `--since <날짜>` | 이 날 뒤의 것만. `YYYY-MM-DD` 또는 `30d` 꼴 |
| `--limit <수>` | 몇 건까지. **최대 100** — 더 크게 주면 100 으로 깎고 알린다 |
| `--budget <토큰>` | 토큰 예산에 맞춰 자른다 |
| `--all` | 낡은 것까지 다 본다. `[무효]` 꼬리표가 붙고 점수가 절반으로 깎인다 |
| `--include-held` | 보류 기억(`add --hold`)까지 같이 본다. 기본은 뺀다 (결정 6) |
| `--facet scope\|tag` | 종류·범위별 건수를 같이 준다 |
| `--explain` | 점수가 어떻게 나왔는지 보여준다 |
| `--json` | 한 줄 JSON (0건이면 `[]`) |
| `--no-index` | 시작할 때 색인을 안 따라잡는다 |

**의미 검색을 끄는 옵션은 없다.** `Memory/vectors.bin` 과 모델이 있으면 켜지고 없으면 낱말 모드다 (결정 16).
아예 빼려면 `mem install --no-embed` 로 깔거나 `vectors.bin` 을 지운다.

답은 **MMR(λ=0.7)로 다양화**하고, 그 뒤에 **1-hop 링크 가산**을 얹는다 (결정 44).
1-hop 은 **가산으로만** 쓴다 — 이웃이라는 이유로 새 문서를 후보에 넣지 않고, 자기를 끌어올린 이웃보다 위로도 못 간다.
같은 주제로 묶인 답에는 **묶음 번호**가 붙는다 — 표는 `[묶음1]` 꼬리표, `--json` 은 `group` 칸(묶음이 없으면 칸이 없다)과 `groups`(묶음 수)다.
훅 주입은 이 자리를 안 지난다 (결정 15).

질의 안에 `#태그` · `scope:이름` · 시간 표현(`어제` `지난주` `최근 7일` `2026-08`)을 섞어 쓸 수 있다.
**시간 표현만 있는 질의**는 그 기간의 목록을 준다. 종료 코드 `0` · `3`.

### `mem show` — id 로 기억 한 건의 본문을 꺼낸다

| 옵션 | 뜻 |
| --- | --- |
| `--head <수>` | 앞에서 몇 줄만 |
| `--raw` | 중화 없이 원문 그대로 (**기본은 주입용 중화를 거친다**) |
| `--from-archive` | 아카이브에서 찾는다 |
| `--json` | 한 줄 JSON |

**조회수를 올리는 유일한 명령이다.** 종료 코드 `0` · `1`.

**「나를 근거로 삼은 기억」 절이 붙는다.** 이 기억을 `sources` 의 `mem:` 이나 `links` 로 가리킨 기억을
`id · 근거/링크 · 종류 · 날짜 · 제목` 으로 찍는다. **0건이면 절을 통째로 안 찍고**, 색인이 없거나
`--no-index` · `--from-archive` 면 안 찍는다 (곁다리라 못 찍어도 명령이 실패하지 않는다).
`--json` 은 최상위에 `used_by[]` 를 더한다 — `id` `by`(`source`/`link`) `type` `date` `title` `live`
(`snoozed` 는 참일 때만 붙는다 — `stale_after` 가 아직 안 와 검토 큐가 건너뛴다는 뜻이다).
**기억 파일에는 안 들어간다.** 색인이 만든 파생값이다.
**`used_by: []` 와 키 없음은 다르다** — 앞엣것은 「세어 봤는데 0건」이고, 뒤엣것은 「못 셌다」다
(색인을 안 봤거나 판이 낮아 방금 다시 만들었을 때).

**살아 있나 죽었나는 한 기준이다** — `superseded_by` 가 있거나 `invalid_at` 이 오늘까지 지났으면
죽음이다. 검색의 기본 걸러내기 · 역참조의 `live` · 검토 큐(C14)가 다 같은 자를 쓴다.

### `mem hook` — 훅 진입점

`mem hook <이벤트> [--dry-run] [--json] [--budget <토큰>]`. 훅 JSON 을 표준입력으로 받는다.

| 옵션 | 뜻 |
| --- | --- |
| `--json` | 주입 대신 잰 값(바이트·토큰·밀리초)을 찍는다 |
| `--budget <토큰>` | 이 한 번만 쓸 토큰 예산 (안 주면 계기별 기본값) |
| `--dry-run` | 훅 JSON 으로 감싸지 않고 블록 글월만 찍는다 |

**이벤트는 둘이다.**

| 이벤트 | 언제 | 예산 · 상한 | 출력의 `hookEventName` |
| --- | --- | --- | --- |
| `session-start` | 세션이 열릴 때 (`startup`·`resume`·`clear`·`compact`·`fork`) | `[budget]` 계기별 · `[hook] max_bytes` | `SessionStart` |
| `subagent-start` | 서브에이전트가 뜰 때 | `[budget] subagent` · `[hook] subagent_max_bytes` | `SubagentStart` |

`subagent-start` 는 세션 블록과 **같은 요약**(같은 절 고르기·살균·잘라내기)에 맨 위 세 줄을 얹는다 :
일을 `mem search` 로 시작한다는 줄 · 끝낼 때 `mem add` 로 남기고 보고에 id 를 적는다는 줄 ·
`vocab.toml` 이 아는 scope 목록 줄. 세 줄은 자료 표시(guard) **바깥**이라 잘려도 남는다.
`[hook] subagent_skip` 에 `agent_type` 을 적으면 그 종류에는 아무것도 안 넣고,
`[hook] subagent_start = false` 면 통째로 끈다.

`SubagentStop` 은 **안 다룬다.** 걸어 놔도 조용히 종료 0 이다
(까닭은 `../Design/2026-08-30-서브에이전트훅설계.md` 5절).

**종료 코드는 늘 `0`** (사람이 이벤트 이름을 잘못 친 것만 `1`).

### `mem index` — 새 기억을 승격하고 바뀐 파일을 색인한다

| 옵션 | 뜻 |
| --- | --- |
| `--full` | 처음부터 다시 만든다 |
| `--bad` | `inbox/bad` 를 **보여주기만** 한다. 락도 안 잡고 아무것도 안 바꾼다 |
| `--clear-bad` | `inbox/bad` 에 쌓인 실패 파일을 **보여주고** 지운다 |
| `--gc` / `--no-gc` | 정리도 같이 한다 / 정리 조건 검사도 건너뛴다 |
| `--quiet` | 아무 말도 안 한다 |
| `--verify` | 색인이 파일과 맞는지 검사한다 |
| `--json` | 한 줄 JSON. **사람 글을 한 줄도 안 섞는다** (v0.4) |

색인이 다 선 뒤 **이웃 링크를 기계가 찾아 `auto_links` 표에 담는다** (결정 42).
**머리말은 안 고친다** — `index.db` 와 같은 파생물이라 색인할 때마다 통째로 다시 만든다.
바뀐 파일이 하나도 없는 회차와 **훅이 부른 회차**는 건너뛴다 (벽시계 1초 안에 안 들어간다).

락을 못 잡으면 조용히 건너뛴다. 종료 코드 `0` · `2`(색인 못 한 파일) · `3` · `4`(비밀정보로 막힌 것).

`--bad` 는 한 줄에 `이름 · 종류 · 까닭 · 푸는 길` 을 찍는다. 종류는 큐 파일의 `op` 다
(`add` · `patch` · `body`, 못 읽으면 `깨짐`). 푸는 길은 `add` 면 「고쳐서 다시 mem add」,
나머지는 「치워도 된다」 다. 까닭 파일(`local/bad-reasons/`)이 없는 옛 항목은 「까닭 기록 없음」 이다.
줄은 다 중화를 지나고 본문·값은 안 찍는다. bad 를 큐로 되돌리는 명령은 없다 — 같은 까닭으로 또 걸린다.

`add` 즉시 승격이 미룬 이웃 링크는 `index.db` 의 `links_pending` 에 id 로 남고,
다음 `mem index` 가 바뀐 파일이 없어도 그 둘레를 다시 잰 뒤 비운다.
**`--json` 도 종료 코드가 사람 화면과 똑같다.**

### `mem migrate` — 옛 규격(v0.1) 기억을 지금 규격으로 옮긴다

| 옵션 | 뜻 |
| --- | --- |
| (기본) | `--dry-run`. 무엇을 고칠지만 보여주고 아무것도 안 고친다 |
| `--apply` | 진짜로 고친다. 고치기 전에 원본을 `archive/<날짜>-migrate` 에 통째로 남긴다 |
| `--restore` | 그 아카이브에서 되돌린다 |
| `--author <아이디>` | 옛 `source` 가 `user` 인 기억의 사람 아이디 (기본은 `git user.name`) |
| `--json` | 한 줄 JSON |

자동으로 못 채우는 것은 표로 찍고 `mem review` 로 넘긴다.

**칸별 부분 이전 (v0.3).** 한 칸이 막혀도 나머지 칸은 옮긴다. 옛 판은 태그<2 에서 바로 되돌아가며 이미 만든
`author`·`sources`·`todo_status` 를 통째로 버렸다 (실기억 206건에서 **49건**이 이렇게 사라졌다).
막힌 칸은 「칸별로만 옮길 것」 표에 `남은 칸` 으로 적는다. 막힌 칸이 있으면 **`migrated` 를 안 켠다** —
켜면 v0.2 자로 검사해서 승격이 통째로 거절된다(불변조건 I7). 그래서 옛 규격 파일에 못 쓰는 `author` 도 같이 남는다.

**출처 태그는 떼면 하한(2개)을 못 채울 때 안 뗀다.** 떼면 이전이 통째로 막히고, 붙어 있는 출처 태그는 F10 이
따로 말해 사람이 `mem tags --rename` 으로 고칠 수 있다.

**비밀정보 검사.** 이전은 기억 파일을 통째로 다시 쓴다. 옮길 기억에 비밀정보가 보이면 **한 건도 안 옮기고**
종료 코드 `4` 로 멈춘다. 값은 안 찍고 어느 기억의 어느 칸인지와 규칙 이름만 말한다.

실기억 206건 : 이전 대상 206 → **자동 191 · 칸별 15 · 사람 손 0** (v0.2 는 자동 157 · 사람 손 49).

종료 코드 `0` · `1` · `2`(되돌릴 것 없음) · `3` · `4`(비밀정보) · `6`.

### `mem gc` — 오래된 기억을 접고 아카이브로 옮긴다

| 옵션 | 뜻 |
| --- | --- |
| `--fold <id>` | 그 기억 하나를 손으로 접는다 (쉼표로 여러 개). **`--dry-run` 없이 바로 접는다** |
| `--restore <id>` | 접은 본문을 아카이브에서 되돌린다 (쉼표로 여러 개) |
| `--dry-run` | 무엇을 옮길지만 보여준다 (`--fold` 에도 붙일 수 있다) |
| `--json` | 한 줄 JSON |

`--fold`·`--restore` 를 주면 나이로 고르는 자동 정리는 안 돈다. **파일은 하나도 안 지운다.** 종료 코드는 늘 `0`.

| 단계 | 조건 | 하는 일 |
| --- | --- | --- |
| 뜨거움 `hot` | 기본 | 그대로 |
| 따뜻함 `warm` | 1,000건 초과 **AND** 90일 초과 | 본문을 규칙으로 줄이고(LLM 0) 원본을 아카이브에 |
| 차가움 `cold` | 20,000건 초과 **AND** 180일 초과 | 본문을 빼고 요약만 남긴다. **파일은 남긴다** |
| 삭제 | **기본 끔** (`[gc] archive_days = 0`) | |

한 번 상한은 **`max(200건, 전체의 2%)`**. `mem index` 뒤에 기회주의적으로 돌고 24시간 쿨다운이 걸린다. **훅 안에서는 절대 안 돈다.**

### `mem lint` — 기억 문서의 품질을 검사한다

| 옵션 | 뜻 |
| --- | --- |
| `--fix` | 고칠 수 있는 것은 고친다 |
| `--json` | 한 줄 JSON |

`--fix` 는 **되돌릴 수 있는 것만** 한다 — 태그 소문자화·별칭 치환 · 줄끝 LF · BOM 제거 · cp949 재기록.
머리말에 `#` 주석이 있으면 건너뛰고 이유를 「건너뜀」 목록에 적는다. 비밀정보는 **손대지 않고 값도 안 찍는다.**
오류가 하나라도 있으면 종료 코드 `2`.

### `mem review` — 사람이 판정할 것만 모아 보여준다

| 옵션 | 뜻 |
| --- | --- |
| `--kind <갈래>` | `held`(승격 대기) · `expired`(다시 볼 날 지남) · `basis`(근거가 죽음) · `conflict`(모순 후보) · `stale`(낡음 후보) · `value`(남길 값이 있나) · `cold`(차가움) · `link`(링크 후보) · `title`(제목 없음). 쉼표로 여러 개 |
| `--limit <수>` | 갈래마다 몇 줄까지 (기본 20) |
| `--promote <id>` | 자동으로 만들어진 기억(머리말 `review: true`)을 사람이 승격한다 |
| `--json` | 한 줄 JSON |

**도구는 판정하지 않는다.** 종료 코드 `0` · `1`(사용법 잘못) · `3`.

**`basis` 는 근거가 죽은 것이다 (C14).** 덮였거나 무효 날짜가 지난 기억을 `sources` 의 `mem:` 이나
`links` 로 가리킨 기억이 온다. **1단만 본다** — 사람이 한 칸 판정하면 그다음 칸이 다음 판 큐에 온다.
「그대로 둠」은 `mem set <id> --stale-after <날짜>` 다. 그날까지 큐에서 빠지고 그날 `expired` 로 온다.
이 큐는 md 를 훑어 **매번 계산한다.** `index.db` 를 지워도 그대로 나온다.

`value` 는 「남길 값이 있나」(B12), `link` 는 기계가 찾은 링크 후보(D04)다.
자동 링크는 파생 표에만 있고 머리말 `links` 로 올리는 것은 사람이 한다 (결정 42 고침).
낡음 큐에는 나이 임계(C12) · 모순 쌍(C13) · 표기 흔들림(C11) · **근거 표류(D02·D03)** 도 온다.

**건수는 규칙 수가 아니라 기억 수다 (N4).** C09·C10 처럼 규칙 둘이 같은 기억에 걸려 206건 저장소가
`cold 337건` 으로 찍혔다. 실기억 206건 : `cold` **337 → 170** · `conflict` **140 → 74**.

**`--promote` 만 auto 모드 allow 규칙 밖이다 (결정 60).** `Bash(mem review:*)` 한 줄이면 AI 가 승인 없이
승격할 수 있어 「승격은 사람이 한다」(결정 6)가 첫날 무너진다. 그래서 규칙을 `Bash(mem review)` +
`Bash(mem review --kind:*)` 두 줄로 갈랐고, 옛 넓은 규칙은 `--undo` 때 같이 빠지게 폐기 목록에 넣었다.
PowerShell 꼴(`PowerShell(mem review)` + `PowerShell(mem review --kind *)`)도 같은 식으로 갈라져 있다.

`--promote` 는 머리말에 `review: true` 가 있는 기억만 받는다. 승격은 `store/` 를 직접 안 고치고
inbox 큐로만 간다(불변조건 2) — `mem index` 가 반영한다. `log.md` 에 `승격` 한 줄이 남는다.

**넣는 쪽은 `mem add --hold` 다.** 모든 `add` 를 보류로 만들지 않는다 — 그러면 저장이 사실상 멈춘다.
AI 가 **확신 없이 자동 저장할 때만** `--hold` 를 준다. 보류 기억은 색인 `memories.review = 1` 이 되어
`search`·`hook` 에서 빠지고, `show`·`lint`·`review` 큐에는 그대로 보인다(사람이 판정할 것이라서).
`search --include-held` 로 같이 볼 수 있다. `log.md` 의 `들어옴` 줄 끝에 `--hold` 표시가 붙는다.
**보류는 닮은 기존 기억에도 안 붙는다.** 완전중복·근사중복 합치기를 다 건너뛰고 늘 새 파일로 간다 —
합쳐지면 그 글이 검토 없이 기존 기억을 통해 뜨는 구멍이 생긴다(뒷정리-3). 검색이 0건일 때 그 낱말이
보류에만 있으면 「보류 N건은 뺐다 — `--include-held`」 한 줄이 붙는다(`--json` 은 `why.held`).

**출력은 전부 `internal/safe` 를 지난다 (결정 59 · 불변조건 I3).** 제목뿐 아니라 `why`·`related`·`notes`
도 씻는다. 셋 다 기억의 요약·근거 글을 그대로 물고 오고, review 출력은 백틱 안에 찍혀 AI 가 자주 읽는다.

### `mem tags` — 태그·scope 표준 목록을 손본다

**목록 보기 `--list` 를 뒤늦게 만들었다** (2026-09-21). 6-1 은 「`mem search --facet` 이 이미 한다」고
안 만들기로 했는데, facet 은 **쓰인** 태그만 센다 — 표준 목록에 있지만 아직 한 번도 안 쓴 태그가 안 보인다.
표준 밖 태그로 거절당한 사람이 고를 것을 못 찾아 `vocab.toml` 을 직접 여는 일이 굳어져 뒤집었다.

| 옵션 | 뜻 |
| --- | --- |
| `--list` | 표준 태그를 상위→하위로, 표준 scope 를 한 줄로 보여준다. 기억 파일은 안 읽는다. `--json` 도 받는다 |
| `--add <태그[=상위]>` | 표준 태그 목록에 넣는다 |
| `--add-scope <이름>` | 표준 scope 목록에 넣는다 |
| `--alias <별칭=표준>` | 태그 별칭을 넣는다. `add`·`lint` 가 조용히 바꿔 준다 |
| `--alias-scope <별칭=표준>` | scope 별칭을 넣는다 |
| `--rename <옛=새>` | 기억 파일의 태그를 바꾼다. **미리보기가 기본**이고 `--apply` 를 줘야 고친다 |
| `--check` | 표준 밖·못 쓰는 태그와 scope 를 세고 늘리는 명령을 알려준다. `vocab.toml` 의 `[type.*]` 표에 없는 `type` 을 쓴 기억 개수도 센다 |
| `--suggest` | 동의어·대표말 후보를 **제안만** 한다 (결정 40). 아무것도 안 고친다 |

**옵션 없이 치면 `--list` 와 같다** (2026-09-23).

**`--suggest` 는 두 자리에서 후보를 뽑는다** — ① 괄호 표기(`색인(indexing)`) ② 흔들린 태그(표준 태그와
앞머리가 겹치거나 한 글자 차이). 0건 질의로 뽑는 후보는 `mem lint --synonym` 이 이미 한다.
결정 40 의 「곁은 닮았는데 내용만 안 닮은 쌍」은 **안 넣었다** — 태그·scope 만으로 고른 쌍의 드문 낱말을
곱하면 잡음이 잡음을 낳는다(실기억에서 `poc03 → 30개는` 같은 짝이 나왔다). 뜻 닮음을 재는 자가 붙은 뒤에 한다.

**`--add-scope` 로 첫 이름을 정하는 순간 그때부터 목록 밖은 거절이다** — 그 전에 목록을 다듬는다.

**`vocab.toml` 의 `[scope]` 키는 이름 규격을 지나야 목록에 앉는다** (영어 소문자·숫자·하이픈 30자까지 —
기억 머리말의 `scope` 와 같은 자). 규격 밖 키는 경고 한 줄을 내고 버린다. 그 목록이 서브에이전트 훅의
신뢰 구역에 그대로 실리기 때문이다 — 개행이 든 키 하나면 거기에 지시문 한 줄이 생긴다.
종료 코드 `0` · `1` · `2`(표준 밖 태그·scope 가 있다) · `6`.

### `mem eval` — 골든셋으로 검색 품질과 문서 품질을 잰다

| 옵션 | 뜻 |
| --- | --- |
| `--quality` | 품질 규칙이 실제로 듣는지 잰다 (정밀도·재현율·G6 판정) |
| `--tune-dup` | 중복 문턱 곡선을 그리고 권장값을 고른다 |
| `--json` | 한 줄 JSON |
| `--hard-only` | 어려운 문제만 돌린다 |
| `--golden <파일>` | 골든셋을 직접 가리킨다 |

골든셋은 둘이다 — 검색 `Memory/golden/goldenset.yaml`, 품질 `Memory/golden/quality.yaml`. 합격선 미달이면 종료 코드 `2`.
**골든셋 파일이 아예 없으면 종료 코드 `3`** 이고 「골든셋이 없어 잴 것이 없다 — 아무것도 안 쟀다」를 말한다.
0 으로 끝내면 부르는 쪽이 「다 통과했다」로 읽는다 (v0.4 결정 17).

| 합격선 | 값 |
| --- | --- |
| G1 찾으면 나온다 | recall@5 ≥ **0.85** · recall@10 ≥ 0.90 · MRR ≥ **0.70** · 한/영 격차 ≤ 0.15 |
| G2 없으면 없다고 한다 | abstain **1.000** · 오배제 ≤ 0.05 |
| G6 문서 품질 | 기계 규칙군 재현율 ≥ **0.90** · 대조군 거짓 경보 **0건** · 규칙 정밀도 ≥ **0.80** |

- **strict 가 공식이고 wide 는 참고다.** strict 는 사다리 0·1·2·5번 칸에서 얻은 답만 정답으로 친다.
- 정밀도가 **0.80 미만인 규칙은 자동으로 경고로 내려가고**, 0.60 미만이면 꺼진다.
- `unreachable: true` 는 합격선 분모에서 빼고 따로 한 줄로 보고한다. **사람이 손으로만** 표시한다.
- 도움말에 없는 옵션 : `--search`(검색만) · `--no-index`.
- **`eval` 은 `mem search` 와 같은 손잡이로 돈다** — `mem.toml [search]`(`field_weights`·`k1`·`b`·`rerank_top`·`syn_weight`)를
  통째로 넘긴다. 자가 다른 값으로 돌면 잰 수치가 실제 검색과 다르다 (v0.4).

## 3. `add` 관문 — 넣기 전에 거른다

`add` 는 저장하기 전에 규칙 카탈로그(**62개** · 물결 2 확정 61 + `tag-shape` · 설계 18-7 W3)를 돌린다. `lint` 와 **같은 검사 함수**를 쓴다.

| 등급 | 하는 일 |
| --- | --- |
| `reject` | 저장을 막는다. 종료 코드 `2`, 보안(E 계열)이면 `4` |
| `warn` | 넣되 알린다. **저장은 된다** |
| `candidate` | 사람이 판정할 자리만 좁힌다 (`mem review` 큐) |
| `off` | 꺼진 규칙 |

- 규칙 이름은 `--json` · 골든셋 · lint 보고가 **다 같은 이름**을 쓴다 (`front-matter` `duplicate-hard` …).
- `decision` 은 M01·M02 가 경고가 아니라 **거절**이다 — 결정 묶음은 하나가 낡으면 나머지도 못 믿는다.
- **(v0.4) 등급은 `relative-date`(B09) 하나만 올렸다.** 올린 조건은 셋을 다 재고 나서다 —
  그 규칙의 정밀도 1.000 · 좋은 10 오거절 0 · 대조군 거짓 경보 0.
  **`summary-body-match`(B08) 는 한때 올렸다가 되돌렸다** (아래 표).

| 규칙 | 전 | 후 | 왜 |
| --- | --- | --- | --- |
| `relative-date` (B09) | 경고 | **거절**(종류 안 가림) | 「어제」·「지난주」는 반년 뒤에 그냥 거짓말이 된다. 고치는 값도 싸다(날짜 한 줄). 골든셋 정밀도 1.000 · 좋은 10 에 0건 · 실데이터 40건에 0건.<br>**「최근」은 조사가 바로 붙은 시점 꼴(`최근에`·`최근까지`)에서만 잡는다** — 「최근 결정」·「최근 이슈」·「최근 조회」 같은 **갈래 이름**은 안 막는다 (리뷰 B) |
| `summary-body-match` (B08) | 경고 | **경고 그대로 (되돌렸다)** | 결정에서만 거절로 올렸다가 **되돌렸다.** 실기억 206건에서 결정 거절 5건 중 **둘이 오탐**이었고 둘 다 사람이 확정해 `pinned` 로 박은 결정이었다 — 이름씨 대조가 **같은 말의 다른 표기**(「색인 · SQLite」 ↔ `index.db` · 「UI·메시지·도움말」 ↔ 「모든 출력」)를 못 본다.<br>**다음 판 후보 : norm/canon 을 태운 이름씨 대조로 오탐을 없앤 뒤 다시 올린다.** |

> **`no-value`(B12)는 안 올렸다.** 골든셋 130건에서 **한 번도 안 울어** 정밀도를 못 재고, 좋은 10 중 다섯(G01·G03·G05·G06·G10)에 운다. 「울되 경고로만」이 이 규칙의 최종형이다.
- 보안(E 계열)은 정밀도가 낮아도 **등급을 못 내린다.** `--force` 는 없다.
- **거절하면 다음에 칠 명령을 반드시 같이 준다** (`Next`).

### 닮음 점수 S 와 중복

```
S = 0.45·J3(요약) + 0.35·J3(본문) + 0.15·J(태그) + 0.05·[scope 같음]
```

| 규칙 | 문턱 (`[quality]` 기본값) | 판정 |
| --- | --- | --- |
| `duplicate-hard` (C01) | `dup_reject = 0.08` | 거절 |
| `duplicate-soft` (C02) | `dup_warn = 0.06` | 경고 + 닮은 것 목록 |
| `same-body` (C03) | 본문 정규화 후 완전 일치 | 거절 |

후보 좁히기는 simhash 64비트 · 해밍 `simhash_hamming = 8` 밴딩이다. **simhash 는 판정자가 아니다.**
문턱은 `mem eval --tune-dup` 곡선이 정한다. `--new` 를 주면 닮아도 다른 주제로 본다.

통째 자카드는 **긴 글 안에 같은 한 줄이 박힌** 중복을 못 잡는다. 그래서 두 단으로 간다.

**1단 (후보 뽑기 · 재현율)** — 아래 넷의 합집합이다. 넓게 뽑는 자리라 여기서 정하는 것은 없다.

| 후보원 | 무엇 |
| --- | --- |
| 지문 밴드 | 요약+본문을 합쳐 뜬 simhash (v0.2 부터) |
| 태그 · scope | 겹치면 후보 (v0.2 부터) |
| **요약 지문 밴드** | 요약만 따로 뜬 simhash. 같은 말을 짧게·길게 쓴 짝을 데려온다 |
| **문장 조각 겹침** | 기억을 문장·표 줄로 쪼개 조각마다 대표 지문 8개를 든다. 그중 하나라도 겹치면 후보 |
| (임베딩) | 셋째 신호 자리. **기본 꺼짐** — `[quality] dup_vectors = true` 라야 붙는다 (`internal/quality/vectors.go`) |

> **벡터 항은 기본 꺼짐이다 (`[quality] dup_vectors` · 설계 18-7).** 켜면 닮음 점수에 `β·max(0, cos−c0)` 가 얹히고 벡터가 후보도 데려오는데, 재측정에서 대조군 거짓 경보 3건 · 실데이터 40건 오거절 15% 가 나왔다. **검색 재정렬의 벡터와는 상관없다.**

**2단 (확정 · 정밀도)** — 통째 점수 S 로 안 걸린 쌍은 **문장 최대 정렬**로 다시 본다.
짝 문장의 자카드가 `0.18` 을 넘고, 그런 짝이 **둘 이상**이고, 그 짝들이 **같은 숫자·경로·이름을 나눠 가지며**,
**어느 짝도 숫자·경로·이름이 어긋나지 않으면** `duplicate-soft`(경고)다. 새 사실이 같이 든 경우가 많아 막지는 않는다.

> **(v0.4) 「어긋난다」의 자가 경고와 거절에서 다르다.**
>
> | 어디 | 자 | 뜻 |
> | --- | --- | --- |
> | 거절(`duplicate-hard`) | 엄한 자 | 양쪽이 서로 없는 값을 하나씩 가지면 어긋남 (v0.3 과 같다) |
> | 경고(`duplicate-soft` 부분 중복) | 느슨한 자 | 거기에 더해 **나눠 갖는 값이 하나도 없을 때만** 어긋남 |
>
> 엄한 자는 「같은 사실을 자세히 쓴 쪽과 줄여 쓴 쪽」을 어긋남으로 셌다 — 한쪽이 곁수치를
> 하나 더 적으면 그것만으로 어긋남이었다. 느슨한 자를 **거절에까지 쓰면** 실데이터 40건
> `duplicate-hard` 가 1 → 5건(2.5% → 12.5%)으로 자(5%)를 넘어서, 경고 쪽에만 쓴다.
> 골든셋 130건 : DUP 재현율 0.750 → **0.778** · 기계 규칙군 0.904 → **0.913** ·
> 대조군 거짓 경보 **0** · 가장 낮은 정밀도 **1.000** · T11 오거절 0 → **1/20**(허용 1).
> 문턱 `dup_reject 0.08` · `dup_warn 0.06` · 정렬 문턱 `0.18` · 띠 하한 `0.15` 는 **다시 재서 그대로 뒀다**.

경고선과 거절선 **사이**(경고만 뜨는 띠)에도 「같은 문장이 조금이라도(`0.15`) 겹칠 것」을 요구한다.
넓혀서 데려온 후보는 **거절선을 넘을 때만** 통째 점수로 잡는다.

> 이 값 넷은 골든셋 130건 스윕으로 뽑았다 (`TestSweepFine`). 설계에 숫자를 안 박는다는 결정 32 대로다.
> **IDF 가중(결정 34)은 셈법만 넣고 꺼 뒀다** — 재 보니 거짓 경보 0 자리에서 재현율이 떨어졌다 (`TestSweepIDF`).

## 5. 검색 — 완화 사다리 일곱 칸

**1건 나왔다고 멈추지 않는다.** `limit` 이 찰 때까지 다음 칸을 계속 밟고, 이미 나온 문서는 **처음 나온 칸**으로 기록한다.

| 칸 | 무엇 | 신뢰 계수 | strict |
| --- | --- | --- | --- |
| 0 | 있는 그대로 (구절은 가산) | ×1.0 | O |
| 1 | 낱말 AND (불용어 뺀 것) | ×1.0 | O |
| 2 | 저장소에 아예 없는 낱말부터 빼고 AND | ×0.85 | O |
| 3 | 낱말 OR | ×0.85 | X |
| 4 | 동의어 확장 | ×0.7 | X |
| 5 | 접두 + 띄어쓰기 지운 꼴 + 어휘 기반 쪼개기 | ×0.6 | O |
| 6 | 제목·요약 부분 문자열(LIKE) | ×0.5 | X |

**strict 는 「정확히 찾았다」로 세는 칸이다.** 동의어(4)와 LIKE(6)는 뜻이 바뀔 수 있어 빼고, OR(3)은 낱말 하나만 맞아도 앉는 칸이라 뺐다. 훅과 eval 은 이 하나만 본다.

### 0·1번 칸에 앉을 자격 — 관문 둘

| 관문 | 내용 |
| --- | --- |
| ① 질의 쪽 | 질의 낱말(불용어 뺀 것)의 **과반이 저장소에 있어야** 한다 |
| ② 문서 쪽 | 그 문서가 질의 낱말의 **과반을 맞춰야** 한다 |
| 과반의 뜻 | **진짜 과반.** 낱말이 둘이면 둘 다 맞아야 한다 |
| 한글 1글자 | **단독으로는 자격을 못 준다.** 접두 매칭이라 `방` 이 `방식`·`방지` 를 물어 온다 |

관문은 0·1번 칸에만 건다. 2번 칸부터는 넓히는 자리다.

## 6. 점수식

```
점수(d) = rrf(d) × 가산(d) × 감쇠바닥(d) × 신뢰계수(칸)     단, d 는 RRF 후보 안에 있어야 한다

rrf(d) = Σ_i  w_i / (k + rank_i(d))          k = [search] rrf_k (기본 10)

가산(d) = min( bonus_cap ,  1
        + 0.5·[고정]  + 0.3·[type 이 표의 search_bonus 켜짐]  + 0.2·[severity=high]
        + 0.2·log(1+조회수)  + 0.2·[scope 일치]  + 0.1·[지목됨]
        + 0.1·(importance − 3)  + 0.3·[질의 구절이 본문에 통째로] )   bonus_cap 기본 1.5

감쇠바닥(d) = 0.3 + 0.7 · 0.5^(나이/반감기)
```

- **가산 고삐 둘** : ① RRF 순위에 없으면 결과에 못 들어온다 ② 가산 합이 `bonus_cap` 을 못 넘는다.
- 무효가 된 기억은 신뢰계수 ×0.5, gc 가 접은(`cold`) 기억은 ×0.7.
- 반감기 : `history` 90일 · `decision`·`howto` 720일 · `issue`·`caution`·열린 `todo`·`fact` **감쇠 없음**.
- 필드 가중은 `bm25` 열 순서로 **16 / 6 / 1** (head · summary · body).
- 재순위 : FTS5 bm25 는 k1·b 를 못 바꿔서 상위 **200건**을 우리 bm25(`k1=1.2` · `b=0.4`)로 다시 매겨 한 표를 더 얹는다.
- 랭킹 가중 : 한글 1.0 · 영문 1.0 · 재순위 1.0 · **정규화(norm) 1.5** · 조사 뗀 꼴 0.8 · 태그·scope 정확일치 0.6 · LIKE 0.5 · 동의어 0.5 · 낱말 하나짜리 0.4 · **임베딩 코사인 `[embed] rrf_weight`**. 한글 1글자 접두는 여기 다시 ×0.5. 랭킹 하나는 **50위까지** 읽는다.
- **정규화 랭킹(v0.3 · 결정 21·46)** : 질의를 색인과 **같은 정규화 함수**(소문자·조사 떼기·`[canon]` 대표말 치환)에 태운 식을 `fts_norm` 과 `fts_ko` **두 표에** 던진다. `fts_norm` 은 정규화가 글자를 바꾼 열만 담으므로, 안 바뀐 열은 `fts_ko` 가 같은 글자로 잡는다. 정규화가 아무것도 안 바꾸면 이 랭킹은 아예 안 붙는다.
  가중 1.5 는 골든셋 세 벌 스윕값이다 — v2 80건 r@5 0.5/1.0/1.2 → 0.701, **1.5 → 0.716**(2.0 이상은 더 안 는다) · 손 30건 0.708 → 0.750 · 42건 0.688 → 0.719.
- **`rrf_k` 재측정(결정 47)** : 신호 둘을 더한 뒤 다시 쟀다. v2 80건 r@5 — **k=10 → 0.716** · k=20 → 0.687 · k=60 → 0.672. **10 을 그대로 쓴다.**
- **모드 표시(결정 16)** : 결과 머리에 `[낱말]` / `[낱말+의미]` 가 붙고 `--json` 에 `mode`(`word` / `word+meaning`) 칸이 온다. 임베딩이 **실제로 한 표라도 던졌을 때만** 의미 모드다 — 켜 놓고 모델이 없으면 낱말 모드라고 적는다.

## 7. 0건 설명 (불변조건 I8)

**0건일 때는 반드시 네 가지를 말한다.**

```
검색 : "타일맵 셰이더"  → 0건
  · 저장소에 "셰이더" 가 들어간 기억이 하나도 없다.   ← ① 어느 낱말이 아예 없나
  · "타일맵" 은 3건 있다.                             ← ② 있는 낱말은 몇 건인가
  · 비슷한 낱말 : 셰이더그래프(1) · 셰도우(2)          ← ③ 닮은 낱말
  · 다시 해 보기 : mem search 타일맵                   ← ④ 바로 칠 수 있는 다음 명령
```

`--json` 이면 같은 내용이 `why` 로 오고 **`hits` 는 `null` 이 아니라 `[]`** 다.
0건이 난 질의는 `local/miss.jsonl` 에 쌓이고, 3회 넘게 0건이 난 낱말은 `mem lint` 가 동의어 후보로 알려준다.
**이 설명은 훅 안에서는 안 나온다** (불변조건 I3 — 훅은 침묵).

| `MEM_DUP_ONEWAY` | 값이 있으면 **한쪽만** 가까워도 친다 | 없음 (서로 가까울 때만) |

**뒷문이 아닌 것 셋** — 아래는 재기용이 아니라 평소에도 쓰는 값이다.

| 환경변수 | 무엇 |
| --- | --- |
| `CLAUDE_PROJECT_DIR` | 훅이 받는 프로젝트 폴더. **Claude Code 가 준다** |
| `MEM_DEBUG` | `1` 이면 훅이 왜 조용한지 stderr 한 줄로 알린다 (훅 stdout 은 그대로 침묵) |
| `MEM_INSTALL_NO_PATH` | `mem install` 이 PATH 를 안 건드리게 한다 (시험 HOME 에서 쓴다) |
