# 설계 개요 (v0.3)

> 이 문서는 **명세**다. **무엇**만 적는다. **왜 그렇게 정했는지**(근거·비교·측정값·위험)는 `mem search` 와
> `../Design/2026-08-24-v0.4설계.md` 가 맡는다. 규칙 수는 **62개**다 (v0.2 57 + 물결 2 의 `link-missing`·`no-value`·`stale-age`·`stale-conflict-pair` 넷 + `tag-shape` · 18-7 W3).
> **v0.1~v0.3 설계서와 등급표는 2026-09-03 에 회차 폴더를 걷어내면서 사라졌다** — 규칙 등급의 정본은 이제 `internal/quality/` 코드다.

`mem` 은 Go CLI 하나다. 기억 원본은 프로젝트 안 `Memory/store/` 의 작은 Markdown 파일들이고,
`Memory/index.db`(SQLite FTS5)와 `Memory/vectors.bin`(문서 벡터)은 언제든 다시 만들 수 있는 파생물이다.
의미 검색은 **선택 설치**다 — `onnxruntime.dll` 과 모델을 `mem install` 이 놓고, 없으면 낱말 검색만 돈다.
Claude Code 와는 **`SessionStart` 훅 1개 + 규칙 블록 + Bash 로 부르는 CLI** 로만 붙는다.
**MCP 없음 · 스킬 없음 · 서버·데몬 없음 · LLM 호출 0.**

**우선순위** : 문서의 품질 > 검색의 품질. 아무리 잘 찾아도 들어 있는 것이 엉망이면 답이 엉망이다.

| **색인 스키마** | 2 | **3** — `fts_norm` · `memories.review` · `auto_links` |

| **allow 규칙** | 10개 (`Bash(mem review:*)` 한 줄) | **11개.** `review` 를 두 줄로 갈라 **`--promote` 만 승인 창** |

## 5. "영어 지원" 의 뜻

UI·메시지·문서는 **전부 한글**이다. 영어 지원은 둘을 뜻한다.

1. **영문 기억이 한글 기억과 같은 품질로 검색된다.**
2. **영문 질의가 통한다.** 골든셋에 `lang: en` 문항을 넣어 같은 자로 재고, **한/영 격차 0.15 이하**를 합격선에 둔다.

한/영을 섞어 쓰는 팀에 실제로 듣는 장치는 `mem.toml` 의 **표 둘**이다 (결정 22·25).

| 표 | 어디 | 무엇 | 언제 듣나 |
| --- | --- | --- | --- |
| **`[canon]`** | `mem.toml` | 「같은 것을 다르게 쓴 것」을 **대표말 하나로** 모은다 (`인덱싱` → `색인`, `index` → `색인`). 1:1 방향성 있는 표 | **색인·질의 둘 다.** 같은 글자가 되므로 재색인이 필요하다 |
| **`[synonym]`** | `mem.toml` | **1:다·외래어** (`유니티` ↔ `Unity`). 양방향 | **질의 때만.** 완화 사다리 4번 칸 · 랭킹 가중 ×0.5 |

`[canon]` 은 **비어서 시작한다.** 비면 정규화가 항등이고 아무것도 안 거절한다 (vocab 의 「배우는 중」과 같다).
`mem init` 은 빈 `[canon]` 절과 예시 주석만 쓰고 낱말을 도로 안 넣는다.
치환은 어절이 아니라 **최장 일치 문자열 치환**이라 `기억 수정` 같은 여러 낱말 구도 잡는다.
**다만 라틴 키는 어절 단위**다 — `index` 를 문자열로 바꾸면 `indexer` 가 `색인er` 이 된다.
순환(`인덱싱`→`색인`, `색인`→`index`)·빈 값은 `mem.toml` 을 읽을 때 바로 거절한다.
