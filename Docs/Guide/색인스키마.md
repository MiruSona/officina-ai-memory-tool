## `Memory/vectors.bin` — 문서 벡터 (v0.3 신설 · 결정 12·13)

`index.db` 와 **똑같은 파생물**이다. 지우면 `mem index` 가 다시 만들고, `.gitignore` 에 들어간다.
`index.db` 안에 안 넣는 이유는 60MB 상한에 여유가 2.7MB 뿐이라서다.

| 값 | |
| --- | --- |
| 파일 자리 | **`Memory/vectors.bin`**. `.gitignore` 에 들어간다 |
| 꼴 | `"MEMVEC01"` · 판(4) · 차원(4) · 건수(4) · 모델이름(2+글자) · 모델판(2+글자) |

| 다시 만드는 때 | 머리말(모델 이름·판·차원)이 지금 모델과 다르면 **통째로**. 아니면 `file_hash` 가 바뀐 건만 |

**훅은 이 길로 오지 않는다** — 훅은 모델을 절대 안 싣는다 (결정 15).

`Memory/index.db` 는 **파생물**이다. 지워도 `mem index --full` 로 완전히 복구된다(불변조건 I2).
그러니 스키마가 바뀌어도 잃는 것이 없다 — 다시 만들면 된다.

## 1. 표

| --- | --- |

| `files` | 파일마다 `(mtime, size, hash, indexed_at)`. 증분 색인이 여기를 보고 **안 바뀐 파일은 열지도 않는다** |

| `meta` | 살림값 — `tokenizer` · `stems` · `last_index_at` · `last_gc_at` · `store_dirs` |

## 2. `memories` 열

| 열 | 무엇 |
| --- | --- |
| `docid` | FTS 의 rowid 와 짝이다 |
| `id` · `path` | 둘 다 UNIQUE. `path` 는 저장소 뿌리 기준 상대 경로 |
| `type` · `scope` · `todo_status` · `severity` · `author` | 머리말 그대로 |
| `title` · `summary` · `tags` | 머리말 그대로 |
| `pinned` · `importance` | 점수 가산과 gc 면제 |
| `created_at` · `updated_at` · `invalid_at` · `stale_after` · `superseded_by` | 시간과 무효화 |
| `hit_count` · `last_hit_at` | 조회수. **`mem show` 만 올린다** |
| `body_hash` · `simhash` | 같은 본문 판정과 닮음 후보 좁히기 |
| `state` · `archived` | `hot`/`warm`/`cold` — gc 단계 |
| `spec` | 이 기억이 어느 규격으로 읽혔나 (1 = v0.1 · 2 = v0.2 이후). 기본값 2 |
| `review` | 머리말 `review: true` — 사람이 아직 승격 안 한 보류 기억 (결정 6). **`search`·`hook` 이 기본으로 뺀다** (`search --include-held` 로 포함). `show`·`lint`·`review` 큐는 그대로 본다 |
| `n_title` · `n_meta` · `n_sum` · `n_body` | 열별 조각 수. 우리 bm25 재순위가 쓴다 |
| `mtime` · `size` · `sha` | 증분 색인 판정 재료 |

### `body` 열은 없다

**본문은 DB 에 안 담는다.** md 가 정본이고 index.db 는 지워도 되는 파생물인데, v0.1 은 본문을 DB 에 한 벌 더 들고 있었고 20k 에서 그것만 DB 의 3할이었다. 검색·랭킹은 본문 원문이 아니라 FTS 조각과 요약만 본다.
본문이 정말 필요한 자리(구절 가산 · `mem show`)에서 **그때 상위 몇 건만** 파일에서 읽는다.
읽기는 `store` 를 지난다 — 경로 감옥·cp949 폴백·재시도가 거기 한 곳에 있다. 파일이 없어졌으면 빈 본문이다.

### `stems` 열도 없다

색인용 조각은 FTS 표에만 넣는다. `memories` 에 한 벌 더 두지 않는다.

### `head` 열은 없다 (v0.4 에서 뺐다)

v0.3 까지는 `title + tags + scope` 를 이어 붙인 `head` 열이 있었다. `tags:` 에만 있는 낱말을 못 찾는 일이 없게 한 자리인데, **태그가 많은 기억은 그 열 안에서 제목 낱말이 묽어져 열 가중 16/6/1 이 「제목이 무겁다」가 아니라 「제목+태그+scope 덩어리가 무겁다」로 들렸다.**

**v0.4 는 그것을 제목 열과 메타 열 둘로 가른다.** 태그는 `tags` 열, scope 는 `scope` 열에 이미 따로 있으므로 색인 글은 그 둘에서 그때 만든다 — `head` 열은 같은 글을 두 번 담는 것이라 뺐다 (206건 실측으로 `memories` 가 144KB → 120KB).

```
title 열 = title
meta  열 = tags.join(" ") + " " + scope
```

## 3. 인덱스 아홉

| 이름 | 열 |
| --- | --- |
| `ix_mem_type` | `(type, updated_at DESC)` |
| `ix_mem_scope` | `(scope, updated_at DESC)` |
| `ix_mem_live` | `(invalid_at, state, updated_at DESC)` |
| `ix_mem_hash` | `(body_hash)` |
| `ix_mem_pinned` | `(updated_at DESC) WHERE pinned = 1` |
| `ix_mem_gate` | `(scope, type) WHERE invalid_at IS NULL` — `decision-gate`(C04) 용 |
| `ix_mem_stale` | `(stale_after) WHERE stale_after IS NOT NULL` — `mem review` 용 |
| `ix_links_dst` | `links(dst)` — 역참조용. 기본키가 `(src, dst)` 라 `dst` 로 찾으면 훑기다 |
| `ix_src_mem` | `sources(value) WHERE kind = 'mem'` — 역참조용. 기억 근거만 담아 옛 `ix_src_kind` 보다 작다 |

**일부러 안 붙인 것** : `simhash` 인덱스. 그것으로 걸러 오는 질의가 없고(닮음 후보는 메모리에서 밴딩으로 좁힌다) 20k 에서 352KB 를 먹었다.
`sources` 인덱스는 「읽는 질의가 생기면 그때 붙인다」고 적어 뒀던 자리다 — 역참조 질의가 생겨 `kind = 'mem'` 부분 인덱스로 다시 붙였다.

### 역참조 질의 (`UsedBy`)

`mem show <id>` 의 「나를 근거로 삼은 기억」 절과 `mem set <id> --by` 의 알림 한 줄이 쓴다.
`sources` 의 `mem:` 과 `links` 를 UNION 으로 모으고, 같은 기억이 둘 다면 근거 쪽만 남긴다.
`superseded_by` 는 안 본다 — 그것은 「덮은 것」이지 근거가 아니다.
**`mem review --kind basis` 는 이 질의를 안 쓴다.** 검토 큐는 md 를 훑어 매번 계산하므로 `index.db` 를 지워도 그대로 나온다.

## 4. FTS 표와 가중

```sql
CREATE VIRTUAL TABLE fts_ko   USING fts5(title_s, meta_s, summary_s, body_s,
       tokenize='unicode61', content='', contentless_delete=1);
CREATE VIRTUAL TABLE fts_en   USING fts5(title_e, meta_e, summary_e, body_e,
       tokenize='unicode61', content='', contentless_delete=1);
CREATE VIRTUAL TABLE fts_norm USING fts5(title_n, meta_n, summary_n, body_n,
       tokenize='unicode61', content='', contentless_delete=1);
CREATE VIRTUAL TABLE vocab_ko USING fts5vocab(fts_ko, 'row');
```

**가중은 `bm25(fts, 12.0, 3.0, 4.0, 1.0)`** — title 12 > summary 4 > meta 3 > body 1. 세 FTS 표가 같은 가중을 쓴다.
`mem.toml [search] field_weights` 가 덮는다. **값이 셋뿐인 옛 `mem.toml` 은 제목·요약·본문 자리에 그대로 옮기고 메타 자리만 기본값으로 채운 뒤 경고 한 줄을 남긴다** — 조용히 안 넘긴다.
`SetFieldWeights` 는 **0 이하가 하나라도 섞이면 통째로 안 받는다** (bm25 가 그 열을 버린다).
**`fts_norm` 도 contentless 라 고칠 때 `UPDATE` 가 아니라 `DELETE` + 재삽입**이다 (결정 58).
표가 하나 늘었으므로 gc·재색인이 지우는 자리도 셋이다 — 하나만 빠뜨리면 지운 기억이 그 표에만 남는다.

### `detail` 은 기본값(`detail=full`)이다

`detail=column` 도 `detail=none` 도 안 쓴다. **contentless(`content=''`) 표에 `detail=column` 을 붙이면 `bm25()` 가 어느 행이든 0 을 낸다 — 열 가중이 통째로 죽는다.** 부피는 fts 조각이 −41% 지만 DB 전체로는 −15% 뿐이라 바꿀 값어치가 없다 (수치는 `../History/2026-08-23-파도C-검색측정.md` 와 최종 측정 문서).

### contentless 인 이유

| | |
| --- | --- |
| 부피 | 보통 표는 토큰에 더해 원문까지 한 벌 더 들고 있어 DB 가 두 배로 부푼다 |
| 지우기 | **`contentless_delete=1`** 이 있어 contentless 에서도 `DELETE` 가 된다. gc·재색인이 매번 지우므로 이 옵션이 없으면 못 쓴다 |
| 안전 | 원문은 md 파일에 있다. FTS 는 **찾기만** 하면 되고 되돌려 줄 필요가 없다 |

대가는 FTS 쪽에서 원문을 못 읽는 것이다 — `snippet()`·`highlight()` 를 쓸 수 없다. 미리보기는 `memories` 표와 md 에서 꺼낸다.

## 5. 토큰화 — 색인용과 질의용을 반드시 나눈다

### 색인용 `ForIndex` (문서당 한 번)

| 입력 | 하는 일 | 결과 |
| --- | --- | --- |
| `바이트로` | 한글 덩어리를 **글자 바이그램**으로 미끄러뜨림 | `바이 이트 트로` |
| `훅` | 한글 1글자는 그대로 | `훅` |
| `unity빌드` | **글자종 경계에서 쪼갬** | `unity` + `빌 드` |
| `MyClassName` | camelCase 쪼갬 (원형도 남김) | `myclassname my class name` |
| `dotnet-format` | 기호에서 쪼갬 (원형도 남김) | `dotnet-format dotnet format` |
| `5,000건` | 숫자 구분기호 제거 + 단위 분리 (원형도 남김) | `5000건 5000 건` |

### 질의용 `ForQuery` (검색할 때만)

| 입력 | 하는 일 |
| --- | --- |
| `"훅 왜 느렸지"` | 따옴표를 벗기고 **구절은 필터가 아니라 가산으로** |
| `기억저장소` | 그대로 바이그램 + 띄어쓰기 지운 꼴도 같이 |
| `기억 저장소` | 낱말별 바이그램 + 붙인 꼴도 같이 |
| `훅` | 한글 1글자 → **접두 매칭 `훅*`**, 제목·메타·요약 열에서만 |
| `hook 예산` | 글자종으로 갈라 영문은 `fts_en`, 한글은 `fts_ko` 로 |
| `5000건` | `5000건` · `5000` · `건` 세 꼴 |
| `결정을` | **조사를 떼고** 뗀 꼴과 원래 꼴을 둘 다 (뗀 쪽 가중 ×0.8). 뗀 결과가 1글자면 안 뗀다 |

**색인용과 질의용은 짝이 맞아야 한다** — 색인용이 만든 조각 안에 질의용 조각이 반드시 들어 있어야 하고, 단위 시험이 이것을 못 박는다.
**조사 떼기는 질의 쪽에서만 한다.** 색인에서 떼면 원문에 진짜로 있던 글자를 잃는다.

### 붙은 낱말 쪼개기 — 색인 어휘로 가장 긴 것부터

사전을 새로 들이지 않고 `vocab_ko` 어휘표를 그대로 쓴다.

| 순서 | 하는 일 |
| --- | --- |
| 1 | 붙은 한글 덩어리를 왼쪽부터 본다 |
| 2 | **가장 긴 것부터** 어휘표에 있는지 물어본다 |
| 3 | 맞은 만큼 떼고 나머지를 같은 방법으로 |
| 4 | 어디서도 못 맞으면 한 글자 앞으로 밀고 다시. 그래도 안 되면 통째 바이그램으로 두고 포기 |

가운데를 무조건 자르면 안 된다 — `바이그램검색` → `바이그` + `램검색` 으로 잘라 0건이 났던 자리다.

## 6. 임베딩 손잡이 (`[embed]`)

| 키 | 기본값 | 무엇 |
| --- | --- | --- |
| `enabled` | `false` | **v0.2 의 정적 표 쪽 손잡이다.** v0.3 의 ONNX 경로는 이 값을 안 본다 — `vectors.bin` 과 모델이 있으면 저절로 켜진다 |
| `path` | `~/.aimemory/model/ko.bin` | 옛 정적 표 자리. ONNX 모델 자리는 `~/.aimemory/models/` 이고 **`mem.toml` 칸이 아직 없다**(`mem install --model` 로만 고른다) |
| `floor` | `0.35` | 이 코사인 아래는 아예 안 센다 |
| `rrf_weight` | `1.5` | 임베딩 순위표를 RRF 에 얹을 때의 무게 |

섞는 법은 **RRF 합**(`blend = rrf`)이 기본이다. `mix`·`flat` 갈래와 환경변수 뒷문
(`MEM_EMBED_BLEND`·`ALPHA`·`TOPN`·`FLATGAP`·`MEM_EMBED_MODEL`)은 **시험용**으로만 남아 있다 —
다음 판이 다른 모델로 다시 재 볼 자리다. 벡터 파일은 `index.db` 안에 안 들어간다(위 `vectors.bin` 절).

`tools/embed/` 의 정적 표 굽는 도구와 `../History/2026-08-23-임베딩실측.md` 는 **v0.2 기록**이다. 이번 판은 안 쓴다.

## 7. 자동 재색인

**`meta.tokenizer` 나 `meta.stems` 가 지금 exe 가 쓰는 값과 다르면 전체를 자동으로 다시 만든다.**
디스크에 있는 조각을 새 코드가 못 읽기 때문이다.

`meta.store_dirs` 는 마지막 색인 때 본 `store/` 폴더들의 자리표다. 읽기 명령이 이 값 하나로 「따라잡을 것이 없다」를 싸게 가른다.

## 8. 판이 안 맞을 때

| 상황 | 하는 일 |
| --- | --- |
| `user_version` 이 0 | 새로 만든다 |
| `user_version` 이 **5** 이고 우리 표(`vocab_ko`·`tagmap`·**`fts_norm`**)가 다 있다 | 그대로 쓴다 |
| `user_version` 이 **5 인데 그 표가 없다** | **딴 스키마다. 통째로 다시 만든다** |
| `user_version` 이 5보다 크고 우리 표가 다 있다 | 더 새 exe 가 쓴 DB 다. **건드리지 않고 종료 코드 2** |
| `user_version` 이 5보다 큰데 그 표가 없다 | 딴 스키마다. 파생물이니 **통째로 다시 만든다** |
| `user_version` 이 1~4 | 옮길 게 없다. **통째로 다시 만든다** — 색인은 파생물이다. 사용자가 칠 명령은 없고 다음 `mem` 명령이 알아서 만든다 |
| SQLite 가 파일을 아예 못 읽는다 | 같음 — 다시 만든다. 락을 못 잡으면 「못 읽는다」고 말한다 (종료 코드 2) |
| 저장소는 있는데 읽을 색인이 없다 | 「저장소 없음(3)」 과 갈라서 **종료 코드 5** 로 말한다 |

**다시 만드는 것도 쓰기라서 락을 잡은 쪽만 한다.**

## 9. 색인은 프로세스당 두 번만 연다

`index.Open` 은 `internal/index` 밖에서 못 부른다. `cmd/mem` 이 시작할 때 저장소 하나를 열어 핸들을 아래로 넘기고, `search`·`hook`·`gc`·`lint`·`eval` 은 넘겨받은 것만 쓴다. "잠깐 열었다 닫기" 를 만들지 않는다.

`index.OpenCount()` 가 연 횟수를 세고, **훅 한 번에 2회를 넘으면 시험이 실패한다.**
쓰기 트랜잭션은 `BEGIN IMMEDIATE` 로 시작한다 — 읽다가 쓰기로 커지면 `busy_timeout` 이 안 통한다.
