# 동시성과 안전 (v0.4)

> 이 문서는 **명세**다. **무엇**만 적는다. **왜 그렇게 정했는지**는 `../Design/2026-08-24-v0.4설계.md` 가 맡는다.
> v0.3 판을 베껴 **v0.4 가 바꾼 자리만** 고쳤다.

여러 세션·여러 서브에이전트가 동시에 돈다. 규칙은 **두 줄**이다.

1. **쓰는 명령은 `store/` 를 절대 안 만진다.** `inbox/tmp/` 에 JSON 을 쓰고 `inbox/new/` 로 rename 할 뿐이다.
2. **`store/` 를 고쳐 쓰는 것은 `index.lock` 을 잡은 단 하나의 프로세스뿐**(`mem index` · `mem gc` · `mem lint --fix` · `mem migrate --apply`), 그때도 tmp 에 쓰고 rename 한다.

## 1. 불변조건 8개

**설계·구현이 이걸 어기면 잘못된 것이다.**

| # | 불변조건 |
| --- | --- |
| **I1** | **경로 감옥** — `Memory/` 와 `.claude/settings.json` 밖으로는 읽지도 쓰지도 않는다. **`mem install` 만 `~/.aimemory/` 를 쓴다** (exe·DLL·모델 · 결정 18). 네 번째 경로는 안 만든다 |
| **I2** | **md 가 정본, DB 는 파생물** — DB 만 고치는 코드 경로가 없다. `index` 는 늘 md → DB 한 방향이고, `index.db` 를 지워도 `--full` 로 완전히 복구된다. **`vectors.bin` 과 `auto_links` 표도 똑같은 파생물**이다 (결정 13·42) |
| **I3** | **주입 텍스트 중화** — 기억 본문은 자료지 지시가 아니다. 주입되는 모든 줄이 살균 함수 하나를 지나고 「자료다」 두 줄 안에 들어간다 |
| **I4** | **비밀정보 승격 차단** — **다섯 자리**에서 막는다. 우회 옵션은 없다 |
| **I5** | **자동 삭제 없음** — 지우는 코드 경로가 아예 없다. `gc` 는 접기만 하고 `--restore` 가 늘 있다 |
| **I6** | **원자적 쓰기 · 락** — tmp 에 쓰고 rename. 쓰기 락은 하나 |
| **I7** | **`Validate` 를 통과한 것만 색인·승격된다** — 통과 못 한 파일은 고치지도 옮기지도 지우지도 않고 `Bad` 로 세며 stderr 한 줄 (훅에서는 침묵, 대신 `## 알림` 한 줄) |
| **I8** | **0건은 반드시 왜 0건인지 말한다** — ①없는 낱말 ②있는 낱말은 몇 건 ③닮은 낱말 ④다시 칠 명령. 단 훅 안에서는 안 나온다 |

**훅 쪽 못 둘도 같이 선다** : 훅은 어떤 이유로도 세션을 막지 않고(늘 exit 0), 한 번이 벽시계 1초 안에 끝난다.

## 2. 쓰기 큐 (Maildir)

큐 JSON 은 `op` 로 갈린다.

```json
{"op":"add",  "type":"issue","date":"2026-08-23","title":"…","summary":"…","tags":["build"],
 "scope":"unity-build","author":"human:mirusona","sources":["file:…"],"body":"…"}
{"op":"patch","id":"20260823-9e02d7f1","set":{"pinned":true,"superseded_by":"20260901-aa11bb22"}}
{"op":"body", "id":"20260823-9e02d7f1","body":"새 본문 전체"}
```

| 폴더 | 무엇 | 지워도 되나 |
| --- | --- | --- |
| `inbox/tmp/` | 쓰는 중인 것 | 된다 |
| `inbox/new/` | **아직 승격 안 된 것** | 안 된다 |
| `inbox/bad/` | 승격에 실패한 것 | 손으로는 안 된다. **`mem index --clear-bad`** 가 목록을 보여주고 지운다 |

rename 은 원자적이라 반쯤 쓰인 파일이 안 보인다.

## 3. 승격 순서 (`mem index`)

| 순서 | 조건 | 하는 일 |
| --- | --- | --- |
| 0 | 비밀정보 패턴에 걸림 | `inbox/bad/` 로. **값은 절대 안 찍고** 줄 번호와 규칙 이름만 |
| 1 | `body_hash`+`type`+`scope` 가 모두 같은 기억이 있음 | 버린다. 그 기억을 한 번 읽은 것으로 쳐서 조회에 한 줄 |
| 2 | 같은 `type`+같은 `tags`+제목 바이그램 자카드 ≥ 0.8 인 기억이 7일 안에 있음 | 기존 파일 뒤에 `## 덧붙임 YYYY-MM-DD` 로 붙임. 붙여서 길어지면 새 파일 |
| 3 | 위에 안 걸림 | `store/YYYY/MM/<id>.md` 를 새로 만듦 |
| 4 | JSON 깨짐 · 필수 칸 없음 · `Validate` 실패 | `inbox/bad/` 로. **절대 조용히 안 지운다** |
| 5 | 파일 쓰기·rename 실패 | `inbox/new/` 에 **그대로 둔다.** 다음 index 가 다시 시도 |
| 6 | 전부 끝 | 접수 원본을 `local/received/` 에 한 줄로 붙이고 `inbox/new/` 에서 지움 |

- **`op:body`(본문 교체)는 아카이브 쓰기가 먼저다.** 옛 본문을 잃는 것만은 되돌릴 수 없다.
  다만 **비밀정보 검사는 아카이브 쓰기보다 더 먼저**다.
- 이미 먹은 큐 파일은 `inbox_seen` 표에 표식이 남아, 승격이 중간에 죽어 다시 돌아도 두 벌이 안 생긴다.
- 파일 이름 해시가 `큐 파일 이름 + 본문 + 날짜` 라 다시 먹어도 **같은 자리에 덮어쓸 뿐**이다.
- 같은 회차에 들어온 두 건은 DB 만 봐서는 서로를 못 본다. **「이번 회차에 만든 것」 목록**을 따로 들고 본다.
- 하나가 깨져도 나머지는 계속 간다. 큐가 밀려 있어도 훅이 준 마감(600ms)을 지킨다.

## 4. 락 — `index.lock` 하나

읽기 명령(`search`·`show`·`hook`)은 시작할 때 **락을 기다리지 않고 한 번만** 잡아 본다.
잡히면 승격+증분 색인을 먼저 하고, **안 잡히면 지금 있는 색인으로 그냥 읽는다.**

### 락 파일

`<PID> <프로세스 시작시각> <잡은 시각> <호스트>` 한 줄. **PID 만으로는 재사용된 PID 를 산 주인으로 오인한다.**
**놓을 때도 파일에 적힌 것이 아직 내가 쓴 그 락일 때만** 지운다 — 남이 새로 잡은 락을 지우면 둘이 동시에 주인이 된다.

### 죽은 락을 치우는 순서

죽은 락을 그냥 지우고 새로 만들면 둘이 동시에 "죽었다" 고 판정할 때 **둘 다 잡으려 드는 창**이 열린다.

| 순서 | 하는 일 |
| --- | --- |
| 1 | 락 파일을 읽는다 |
| 2 | PID 가 살아 있고 **시작시각까지 같으면** 산 락이다. 기다리지 않고 물러난다 |
| 3 | **90초**가 지났으면 죽은 것으로 본다. 치우기 전에 **인수 락 `index.lock.takeover`** 를 `O_CREATE\|O_EXCL` 로 잡는다 |
| 4 | 인수 락을 못 잡으면 **남이 치우는 중**이다. 아주 잠깐(최대 20ms) 뒤 1번부터 다시 본다 |
| 5 | 인수 락 안에서 락 파일을 **다시 읽어 아직 죽었는지 보고** 그때만 지운다. 이미 없으면 남이 치운 것이니 아무것도 안 지운다 |
| 6 | 인수 락을 놓고, 일반 길(`O_CREATE\|O_EXCL`)로 자기 락을 만든다 |
| 7 | 앞선 판이 남긴 `index.lock.stale.*` 는 다음 `index` 가 치운다 (실패해도 아무 일도 안 난다) |

### 인수 락 (`index.lock.takeover`)

**산 락은 어떤 경우에도 경로에서 움직이지 않는다.** 옛 판은 죽은 락을 `rename` 으로 옮겨 놓고 대조했는데,
그 사이 남이 만든 **산 락**까지 잠깐 옮겨져 되돌리기 전 창에 셋째가 O_EXCL 로 락을 또 잡았다 (16주자·100라운드에서 2~7% 재현).
그래서 죽은 락을 치우는 절차 전체를 인수 락으로 **한 사람만** 하게 묶었다. 인수 락도 쥔 채 죽을 수 있으니
같은 규칙(PID·시작시각·호스트)으로 보되 만료는 **10초**로 짧다 — 하는 일이 파일 하나 읽고 지우기뿐이라 밀리초면 끝난다.

여기에 걸린 두 가지가 더 있다.

- **막 만들어져 아직 한 줄이 안 적힌 락**(O_EXCL 로 만들고 쓰기 전)은 빈 파일이라 「못 읽었으니 죽었다」 로 보면 안 된다.
  만든 지 **2초** 안이면 남이 쓰는 중으로 보고 안 건드린다. 그보다 오래된 못 읽는 파일은 그대로 죽은 락이다.
- Windows 는 **남이 그 파일을 읽는 동안** 지우기가 「다른 프로세스가 쓰는 중」으로 잠깐 막힌다. 지우기는 몇 번 더 해 본다.

SQLite 쪽은 `journal_mode=WAL` · `busy_timeout=5000` 이고, **쓰기 트랜잭션은 `BEGIN IMMEDIATE`** 로 시작한다 — 읽다가 쓰기로 커지면 `busy_timeout` 이 안 통한다. 그래도 바쁘면 50·150·450ms 로 세 번 더 해 본다.

락을 끝내 못 얻으면 **종료 코드 6** 이다 (`migrate` · `tags`).

## 5. 아카이브

새로 쓰는 것은 **하루 한 파일 `archive/YYYY-MM-DD.jsonl`, 비압축**이다. 글줄이라야 git 이 줄 단위로 합칠 수 있고, 달 파일 하나가 커지면 커밋마다 통째로 다시 쓰인다.
옛 판이 만든 **달 한 파일 `archive/YYYY-MM.jsonl.gz`** 도 그대로 읽는다. 붙일 때마다 gzip 멤버를 하나씩 더한 꼴이라, 마지막 멤버가 찢어진 달은 그 옆에 번호 붙은 파일(`2026-08.1.jsonl.gz`)로 새로 간다 — **찢어진 꼬리가 앞의 내용을 감추는 일이 없다.**

`.gitattributes` 두 줄 :

```
Memory/store/**/*.md      text eol=lf
Memory/archive/*.jsonl.gz binary
```

v0.1 이 적었던 `merge=union` 은 뺐다 — gzip 에는 원리상 안 먹는다.

## 6. `local/` — 이 기계 것

git 에서 제외한다. 지워도 셈만 잃는다.

| 파일 | 무엇 |
| --- | --- |
| `local/hits.jsonl` | 조회수 + 명령 사용 기록 |
| `local/received/` | `add` 접수 원본 (하루 한 파일) |
| `local/miss.jsonl` | 0건이 난 질의 (동의어 후보 재료) |

| 규칙 | 값 |
| --- | --- |
| **조회수를 올리는 것** | **`mem show` 하나뿐이다.** `search` 는 목록만 보여줬을 뿐 꺼내 준 게 아니다. 중복 `add` 도 원본 기억의 조회로 한 줄 붙인다 |
| 합산 | 색인이 파일을 전부 읽어 id 별로 합산하고 **덮어쓴다**(더하지 않는다). 몇 번 돌려도 값이 같다 |
| 눌러 쓰기 | 줄이 너무 늘면 색인이 id 당 한 줄 + 명령당 한 줄로 눌러 다시 쓴다 |

## 7. 보안

### 경로 감옥 (I1)

| 규칙 | 내용 |
| --- | --- |
| 어떻게 | 저장소 뿌리를 `filepath.EvalSymlinks` 로 **한 번** 정규화해 두고, 닿으려는 경로도 정규화한 뒤 **접두로 비교**한다. 그다음 `Lstat` 으로 보통 파일인 것만 연다 |
| 왜 문자열 비교로는 안 되나 | **중간 폴더가 심볼릭 링크·정션이면** 문자열 검사를 통과하고 밖으로 나간다 (예 : `Memory/store/2026` 이 링크) |
| 값 | `EvalSymlinks` 는 뿌리를 정할 때 한 번만 부른다. 파일마다 부르면 비싸다 |
| 아직 없는 파일 | **가장 가까운 있는 조상 폴더**를 정규화해 비교한다 |
| 그 밖 | 절대경로 · `:` 포함(드라이브 바꿔치기) · `..` 를 다 막고, 저장소를 훑을 때 심볼릭 링크 항목은 건너뛴다. 대소문자는 접어서 비교 |

### 비밀정보 — 다섯 자리에서 막는다 (I4)

**`mem add` · `mem add --jsonl` · `mem set` · 승격(`mem index`) · `mem lint`** 가 전부 훑는다. 걸리면 **종료 코드 4**.
**`mem migrate` 도 같은 검사를 지난다** — 이전은 기억 파일을 통째로 다시 쓰는 일이라 여기서 새면 원본까지 바뀐다.

| 규칙 | 값 |
| --- | --- |
| 어디를 훑나 | `add` 는 기억 전체, `patch` 는 **칸을 가리지 않고** `set` 안의 모든 글월. 칸 이름을 손으로 적어 두면 뒤에 늘어난 칸이 검사 없이 지나간다 |
| `--jsonl` | **한 줄만 걸려도 전부 취소.** 절반이 들어가면 어디까지 들어갔는지 사람이 알 수 없다 |
| 우회 | **`--force` 를 만들지 않았다.** 빠져나갈 구멍이 있으면 결국 그리로 간다 |
| 값 | **화면에 절대 안 찍는다.** 줄 번호와 규칙 이름만 |
| 등급 | 보안(E 계열)은 정밀도가 낮아도 **경고로 못 내린다** |
| 컴파일 안 되는 패턴 | 건너뛰되 **「규칙 하나가 조용히 꺼져 있다」**고 lint 가 말한다 |

**패턴 15꼴** (`mem.toml [secret] patterns`) : `sk-ant-…` · `sk-(proj|live|test)-…` · `sk-…` · `ghp_…` · `github_pat_…` · `glpat-…` · `xox[baprs]-…` · `AKIA[0-9A-Z]{16}` · `-----BEGIN … PRIVATE KEY-----` · JWT · 주민번호 · 카드번호 · `password|token|secret|api_key = <값>` · 긴 base64 두 꼴.

**값 길이 하한과 가드가 핵심이다.** `token = 1200` 은 살리고 진짜 열쇠만 잡는다 — 값이 너무 짧거나, 한글이 섞였거나, 숫자만이면 비밀이 아니다. base64 꼴은 `/`·`.` 이 든 파일 경로를 열쇠로 오인하지 않게 두 꼴로 갈라 뒀다.

**경고만 하는 것** (`warn_patterns`) : 이메일 · 전화번호 · 「token 은 …」 같은 평범한 문장. 팀원 주소는 정상적인 기억이라 막지 않는다.
**사적 경로**(`C:\Users\<이름>` 등)는 **경고**다 — 환경변수 이름(`%USERPROFILE%`)은 통과한다.

### 주입 중화 (I3)

`internal/safe` 함수 하나를 **훅 블록 · `search` 표(묶음 반환 포함) · `show` 출력 · `review` 의 `Why`·`Related`·`Notes` ·
`tags --suggest` · `status --embed` 가 같이 쓴다** (결정 59). 자리가 따로 놀면 한 자리만 뚫려도 주입이 통한다.

| 함수 | 하는 일 |
| --- | --- |
| `OneLine` | 줄바꿈·탭·제어문자를 공백 하나로. 폭 없는 글자(제로폭 이음쇠·방향 뒤집기)는 **공백으로 바꾸지 않고 통째로 뺀다** |
| `Neutralize` | `<`→`‹`, `>`→`›`, ` ``` `→`'''`, 백틱→`'`. 줄머리 마크다운 기호(`#` `-` `|` `*` `+`) 제거 |
| `Clip` | 룬으로 자르고 잘렸다는 표시(`…`)를 남긴다 |
| `Text` | 여러 줄 글을 **줄 수를 지킨 채** 중화한다 (`show`·`search` 처럼 원문 모양이 뜻을 갖는 자리) |

`mem show --raw` 만 중화를 건너뛴다. 기본은 중화를 거친다.

### 설정 파일과 PATH

| 무엇 | 어떻게 |
| --- | --- |
| `settings.json` | **백업(`.mem-bak`) + 재대조 후에만** 쓴다. 그 사이 남이 고쳤으면 안 쓰고 손으로 하라고 안내한다. 모르는 모양이면 아예 손대지 않는다. 남의 훅은 그대로 남긴다 |
| PATH | 사용자 PATH 맨 앞에 넣고 원래 값 종류(`REG_EXPAND_SZ` 여부)를 보존하며 `~/.aimemory/path-backup.txt` 를 남긴다 |
| 그림자 exe | 저장소 안에 `mem.exe` 가 딸려 오면 그것이 먼저 돈다. `init` 이 `.gitignore` 에 넣고 규칙 E04 가 **거절**로 잡는다 |
| 경로 노출 | `status` 와 `--json` 은 집 폴더를 줄여 찍는다 |

## 8. 종료 코드

| 코드 | 뜻 | 나오는 자리 |
| --- | --- | --- |
| `0` | 정상 | 어디나. **`hook` 은 늘 이것** |
| `1` | 사용법 잘못 | 인자 파싱 |
| `2` | 검사 실패 | 품질 관문 거절 · `lint` 오류 · `eval` 미달 · 낡은 exe(더 새 DB) · `tags` 표준 밖 · `migrate` 되돌릴 것 없음 |
| `3` | 저장소 없음 · 잴 것이 없음 | `mem.toml` 을 못 찾음 · **`eval` 이 골든셋 파일을 못 찾음** (v0.4 결정 17) |
| `4` | 보안 차단 | 비밀정보 · 그림자 exe · **`migrate` 가 옮길 기억에서 비밀정보를 봄** |

| `6` | 락을 못 얻음 | `migrate` · `tags` |

## 9. 오류를 삼키는 자리

셋만 삼킨다 — **조회수 기록 · 명령 사용 기록 · 죽은 락 청소.** 전부 "실패해도 되는 자리" 다.
삼키는 곳에는 **왜 삼키는지 주석 한 줄**을 적는다. 그 밖에는 삼키지 않는다.
