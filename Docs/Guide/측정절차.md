# 측정 절차 — G1~G6 을 어떻게 재는가

> v0.4 판이다 — v0.3 판을 베껴 **바꾼 자리만** 고쳤다(종료 코드 전수 표).
> 이 문서는 **재는 법**만 담는다. 잰 값은 `../History/2026-08-24-최종측정.md` 에 있다.
> 근거 : 설계 18-6 ⑤ · 최종측정 1~7절 · 실데이터시험 · 스트레스시험.
> **절차를 틀리면 값이 통째로 달라진다.** 뒷정리-1 의 「G6 불합격」은 저장소를 잘못 골라 생긴 착오였다.

## 0. 다섯 가지 못

| 못 | 안 지키면 |
| --- | --- |
| **동결 exe 하나로 다 잰다** — 크기·SHA-256 을 재서 문서 머리에 적고, 그 뒤로 코드를 한 줄도 안 고친다 | 「고치고 다시 안 쟀다」가 남는다 |
| **스크래치패드 사본에서만 돈다** — 모든 호출에 `--repo <절대 경로>` | 실수로 이 저장소 `Memory/` 를 고친다 |
| **시험 HOME 을 따로 판다** — `USERPROFILE`·`HOME` 을 스크래치 폴더로 돌리고 `MEM_INSTALL_NO_PATH=1` | 진짜 `~/.aimemory` 와 HKCU `Path` 가 더러워진다 |
| **`--golden` 을 늘 명시한다** — `--repo` 는 골든셋의 `meta.store` 를 덮어쓴다 | 어느 저장소를 쟀는지 알 수 없다 |
| **전/후를 나란히 적는다** — v0.1 자와 새 자, 낱말과 의미, 이전 전과 이전 후 | 개선을 증명 못 한다 |

끝나고 반드시 확인한다 : `git status .` 가 **비어 있어야** 한다.

## 1. 준비 — 동결 exe 와 사본

```sh
F=<스크래치패드>/<이번 벌>
cp bin/mem.exe $F/mem.exe
sha256sum $F/mem.exe ; stat -c %s $F/mem.exe        # 크기·SHA 를 문서 머리에 적는다
```

| 사본 | 무엇 | 건수 |
| --- | --- | --- |
| `repoA` / `repoM` | 이 저장소 `Memory/` 사본 — 이전 전 / `migrate --apply` 뒤 | 206 |
| `qrepo` | **`testdata/quality/store` 130건 + `testdata/quality/vocab.toml`** | 130 |
| ~~`projB`~~ | ~~외부 말뭉치 사본 40건~~ — **2026-09-03 에 시험 자료를 정리하면서 걷어냈다.** 이 줄로 잰 값은 옛 측정 기록에만 남는다 | — |
| `gate` | `init` → scope → 태그 → 좋은 10 → `index` → 나쁜 21 | 10 |
| `t16` | 새 빈 프로젝트 · 서로 아주 다른 기억 3건 | 3 |

**`testdata/*/store` 의 md 는 이제 `store/2026/08/` 자리에 있다**(v0.4 리뷰 A R8 에서 옮겼다).
**통째로 복사하고 바로 색인하면 130건·40건이 다 들어온다** — 손으로 옮기는 단계는 없어졌다.
모든 사본은 `index.db`·`vectors.bin` 을 지우고 `index --full` 을 다시 돌린 뒤에 잰다.

## 2. 두 모드 가르기 — 모델이 시험 HOME 에 있느냐로만

```sh
export MEM_INSTALL_NO_PATH=1
export USERPROFILE="$F/home"  HOME="$F/home"     # 의미 모드
$F/mem.exe install --bundle "<꾸러미 폴더>" --apply
# 낱말 모드는 모델을 안 깐 다른 HOME (`$F/home2`) 을 쓴다
```

저장소도 모드마다 따로 뜬다(`vectors.bin` 이 섞이면 안 된다).
`mem.toml` 의 `[embed] enabled` 가 `false` 면 **모델이 깔려 있어도 낱말 모드로 돈다** —
`status --embed` 의 「지금 모드 [낱말] / [낱말+의미]」로 확인하고 시작한다.

## 3. G2 를 먼저 잰다

**G2(abstain 1.000 · 오배제 ≤ 2%)는 깨면 안 되는 자다**(결정 2). 재현율을 올리는 어떤 변경도
**G2 를 먼저 재고** 나서 채택한다. 도구가 찍는 「합격」을 믿지 말고 **설계 1절 자(2%)로 손으로 본다**.

## 4. G1·G2 — 검색 골든셋 4벌 × 두 모드

```sh
$F/mem.exe index --full --repo "$F/repoA/Memory"
$F/mem.exe eval --repo "$F/repoA/Memory" --golden "$F/gold/hand30.yaml"                 # 손 30
$F/mem.exe eval --repo "$F/repoA/Memory" --golden "<AIMemoryTool>/testdata/golden/goldenset.yaml"       # 42
$F/mem.exe eval --repo "$F/repoA/Memory" --golden "<AIMemoryTool>/testdata/golden/goldenset-v2.yaml"    # v2 80 (공식)
# 외부 말뭉치 15건 줄은 시험 자료를 정리하면서 없앴다 (2026-09-03)
```

- **공식 판정은 `v2 80건`** 이다(설계 1절). 규격이 가장 크고 유형·질의꼴 분포를 갖췄다.
- **자를 갈아치우지 않는다.** 실기억 골든셋은 참고 자로만 나란히 적는다(결정 3).
- 손 30건(`Memory/golden/goldenset.yaml`)은 `expect_mode: all` 이 없어 그대로는 **exit 2** 다 —
  **스크래치 사본에만 한 줄 넣어** 잰다(R5 · 원본은 사용자 몫).
- 이전 전(`repoA`)·이전 후(`repoM`)를 둘 다 잰다. `migrate` 가 검색을 나쁘게 하는지가 여기서 보인다.

## 5. G6 — 문서 품질

```sh
$F/mem.exe eval --quality --repo "$F/qrepo/Memory" --golden "<AIMemoryTool>/testdata/golden/quality.yaml"
```

**반드시 `testdata/quality` 통째 사본**(store 130 + `vocab.toml`)에 돌린다.
실기억 206건 사본에 돌리면 값이 이렇게 갈린다 — 골든셋에 없는 기억 76건에도 규칙이 울고,
`vocab.toml` 이 없어 `scope-standard` 가 대조군 전부에 운다.

| 저장소 | 재현율 | 거짓 경보 | 최저 정밀도 | DUP |
| --- | --- | --- | --- | --- |
| **품질 저장소 130건 (맞는 절차)** | 0.904 | **0** | 1.000 | 0.750 |
| 실기억 206건 사본 (틀린 절차) | 0.885 | **20** | 0.355 | 0.694 |

문턱 곡선은 `eval --tune-dup` 으로 본다. **재현율만 보지 말고 「대조군 잡음」 열을 같이 본다** —
거짓 경보 0 을 지키는 자리가 어디까지인지가 진짜 천장이다.

## 6. 오거절 3벌 — 채택 조건은 「실데이터 hard ≤ 5%」

`lint --json` 을 세 저장소에 돌려 `duplicate-hard` 건수와 비율을 적는다.

| 저장소 | 건수 | 조건 |
| --- | --- | --- |
| 실기억 206건 | 206 | 참고 |
| **실데이터 40건** | 40 | **≤ 5%** (리뷰 C 가 못 박은 채택 조건) |
| 새 빈 프로젝트 3건 (T16) | 3 | 오류 0 · exit 0 |

## 7. `add` 관문 — 차례가 결과를 바꾼다

**`good → index → bad`** 다. 좋은 10건을 `--check` 로 재고 **진짜로 넣고 `index` 한 뒤** 나쁜 21건을 잰다.

```sh
$F/mem.exe init --repo <gate> --no-hook
$F/mem.exe tags --add-scope <scope> --repo <gate>/Memory      # scope 2개
for t in <태그 12개>; do $F/mem.exe tags --add $t --repo <gate>/Memory; done
sh <AIMemoryTool>/testdata/gate/gate-demo.sh $F/mem.exe <gate>/Memory
```

**태그 12개를 미리 안 넣으면 좋은 것이 오거절당한다** — 관문 탓이 아니라 준비 탓이다.
`add` 는 본문을 **표준입력**에서 기다린다(`--body` 를 안 주면 멈춘 것처럼 보인다).
태그는 **영어 소문자·숫자·하이픈**만 받는다(`tag-shape` · 규격 밖은 exit 2).

## 8. G4 — 20k 스트레스

가데이터 20k·5k 저장소는 **한 번 만든 벌을 계속 다시 쓴다**(씨앗 고정). 파생물만 지우고 새 exe 로 처음부터 만든다.

```sh
S=<스크래치패드>/stress
rm $S/p20k/Memory/index.db $S/p20k/Memory/vectors.bin
$S/mem.exe index --full --repo $S/p20k/Memory     # 20k 색인 ≤ 15초
$S/mem.exe index --repo $S/p20k/Memory            # 증분 무변경 ≤ 500ms
# 10건 고침 : store 의 md 10장에 한 줄씩 덧붙인 뒤 index  ≤ 500ms
$S/mem.exe status --db --repo $S/p20k/Memory      # index.db ≤ 60MB · vectors.bin ≤ 20MB
$S/mem.exe lint --repo $S/p20k/Memory --json > lint.json    # ≤ 10초
$S/mem.exe search <질의> --repo $S/p20k/Memory --no-index   # p95 낱말 ≤ 300ms · 의미 ≤ 900ms
```

- **긴 실행은 저장소 벌 단위로 쪼개고 중간 결과를 파일로 남긴다.** 멈춰도 어디까지 됐는지 알 수 있다.
- 검색 p95 는 **표본 200**(질의 20종 × 10회 · 프로세스 시작 포함), 훅은 **표본 50**.
- **찬 캐시 함정** : 파생물을 막 지운 직후 첫판은 몇 배로 튄다(5k `index --full` 첫판 31초 · 2회차 3.3초). **둘 다 적는다.**
- Defender 실시간 검사가 켜진 임시 폴더라 **시간 절대값은 비관적**임을 문서에 한 줄 적는다.

## 9. G3 — 훅 4이벤트

`SessionStart` 의 **`startup` · `clear` · `compact` · `resume`** 네 계기를 각각 50회 돌린다.

```sh
echo '{"hook_event_name":"SessionStart","source":"startup","cwd":"<저장소>"}' | $S/mem.exe hook SessionStart --json
```

잴 것 : p50/p95/max · `bytes`(≤ 8,000) · `tokens`(≤ 1,000) · `truncated` · exit 0 · stderr 0바이트 ·
출력 50벌을 `ms` 만 빼고 견줘 **편차 0%**. **모델을 안 싣는지**는 모델 깐 홈에서 훅 p95 가
의미 검색의 절반 아래인 것으로 본다(DLL 로드를 직접 감시하지는 못한다).
빈 `cwd` 는 **아무 저장소도 안 열고** 빈 출력·exit 0 이어야 한다 — `index.db` 의 크기·고친 시각이 안 바뀐 것으로 확인한다.

## 10. 종료 코드 전수

| 코드 | 뜻 | 자리 |
| --- | --- | --- |
| 0 | 정상 | `hook` 은 **늘 0** |
| 1 | 사용법 | 모르는 옵션 — 16개 중 15개가 1 |
| 2 | 검사 실패 | `add` 관문 거절 · 오류 있는 `lint` |
| 3 | 저장소 없음 · 잴 것이 없음 | 빈 폴더에서 13개 명령 · **골든셋 없는 저장소에서 `mem eval`** (v0.4 결정 17) |
| 4 | 보안 차단 | `add` 비밀정보 · 승격 거절 · 색인 제외 · `migrate` 비밀정보 (값 미출력) |
| 5 | 파일·DB 손상 | `index.db` 를 난수로 덮고 산 락 |
| 6 | 락 실패 | 산 락에 `migrate --apply` · `tags --add-scope` |

세 꼴(모르는 옵션 16 · 빈 폴더 13 · 코드 2/4/5/6 자리)을 다 돌려 **표와 어긋나는 자리 0** 을 확인한다.
`mem help <명령>` 이 16/16 다 나오는 것도 같이 본다.
