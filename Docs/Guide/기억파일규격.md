# 기억 파일 규격 (v0.3)

> 이 문서는 **명세**다. **무엇**만 적는다. **왜 그렇게 정했는지**는 `../Design/2026-08-23-v0.3설계.md` 가 맡는다.
> 규칙 코드(F01…X03)의 전체 표는 `../Design/2026-08-23-v0.2-품질규칙표.md` 에 있다.

기억 한 건 = Markdown 파일 하나 = **YAML 머리말 + 본문**.
`model.Validate` 를 통과한 파일만 승격·색인된다(불변조건 I7). 통과 못 한 파일은 **고치지도 옮기지도 지우지도 않는다.**

---

## 1. 파일 이름과 자리

```
Memory/store/2026/08/20260822-3f9a2c1b.md
                     └─날짜8─┘ └─해시8─┘
```

| 규칙 | 값 |
| --- | --- |
| 글자 | **ASCII 만.** 한글 제목은 안쪽 `title:` 에 넣는다 |
| id 꼴 | `^\d{8}-[0-9a-f]{8}$` — 판정은 `model.IsID` 한 곳뿐이다 |
| 해시 8자 | `큐 파일 이름 + 본문 + 날짜` 의 해시. 승격이 중간에 죽어 다시 먹어도 **같은 자리에 덮어쓸 뿐** 두 벌이 안 생긴다 |
| id 확정 시점 | `mem add` 가 승격 전에 최종 id 를 찍는다. 날짜가 재료에 들어가므로 자정을 넘겨 색인해도 안 바뀐다 |
| 인코딩 | 쓸 때는 **BOM 없는 UTF-8 · LF** |

**예약 이름 `index.md`(v0.3 신설 · 조사 D #47).** `store/` 어느 폴더든 `index.md` 라는 이름은 기억 파일이 아니라
**예약 이름**이다 — OKF 관례(묶어 놓은 링크 목록)를 그대로 따른다. `id` 꼴(`^\d{8}-[0-9a-f]{8}$`)과 안 맞으므로
지금도 `Validate` 가 거절하지만, 거절 문구가 「id 와 이름이 안 맞다」로 나가 **예약 이름이라 일부러 건너뛴 것인지
실수로 잘못 지은 이름인지 구별이 안 된다.** **`internal/store.ListMemories` 가 이 이름을 목록에서 뺀다 (v0.3 · 3B).** 대소문자는 안 가린다.
목록에 아예 안 들어오므로 `lint`·`index`·`review` 가 다 같이 건너뛴다.

## 2. 머리말 칸 — 필수

`type` 에 따라 필수가 더 붙는다.

| 칸 | 값 · 형식 | 검사 규칙 |
| --- | --- | --- |
| `id` | `20260822-3f9a2c1b` (`^\d{8}-[0-9a-f]{8}$`) | F03 |
| `type` | `todo` `history` `issue` `caution` `decision` `howto` 여섯 중 하나 | F04 |
| `title` | 한 줄 **6~40자**. **요약 앞 20자를 그대로 베끼면 거절** | F06 |
| `summary` | 한 줄 **30~120자** | F05 |
| `tags` | 소문자 태그 **2~5개**, 낱말은 `^[a-z0-9][a-z0-9-]{0,29}$` | F08 · F09 · F10 |
| `scope` | 툴·부품 이름 **통째 하나**, `^[a-z0-9][a-z0-9-]{0,29}$` | F12 |
| `date` | `YYYY-MM-DD`. **달력에 있는 날**이라야 하고 미래 날짜는 거절 | F20 |
| `author` | `human:<아이디>` / `<도구>/<버전>` / `hook:<이름>` / `import:<저장소>` | F19 |
| `sources` | `decision`·`issue`·`caution` 은 **1개 이상 필수** | F16 |
| `todo_status` | `open` / `doing` / `done` — **`todo` 에만** | F14 |
| `severity` | `low` / `mid` / `high` — **`issue`·`caution` 에만** | F15 |

> `title` 은 `migrated: true` 인 기억에서만 빠질 수 있다. migrate 가 제목을 지어내는 대신 비워 두고 사람에게 넘기기 때문이다.

## 3. 머리말 칸 — 선택

| 칸 | 값 · 형식 | 비고 |
| --- | --- | --- |
| `sources` | 접두 다섯 중 하나로 시작하는 문자열 배열 (4절) | 위 세 종류가 아니면 선택 |
| `links` | 다른 기억 `id` 배열 | 가리키는 id 가 없으면 D01(거절). **사람이 적은 것만 담는다** — 도구는 이 칸을 안 고친다(결정 42 뒷정리). 기계가 찾은 이웃은 색인의 `auto_links` 파생 표에 따로 있고 검색만 쓴다. 같은 주제인데 비어 있으면 D04(후보)가 뜨고, 사람이 보고 여기에 적는다 |
| `superseded_by` | 이 결정을 덮은 새 기억의 `id` | **`invalid_at` 과 한 짝**이다. 하나만 있으면 거절 |
| `invalid_at` | `YYYY-MM-DD` — 이 날부터 무효 | 위와 같음 |
| `stale_after` | `YYYY-MM-DD` — 이 날 지나면 다시 보자는 예약 | `mem review --kind expired` 가 읽는다 |
| `importance` | `1`~`5` (안 쓰면 3) | 5 는 gc 면제 |
| `pinned` | `true` — 접기 면제 + 훅 주입 1순위 | 저장소 전체 **10건**(`[repo] pin_max`) 안쪽 |
| `migrated` | `true` — migrate 가 옛 규격에서 옮긴 기억 | 첫 판에서 F06 을 안 따지고 결함률(S06)에서 뺀다 |
| `review` | `true` — 자동으로 만들어져 아직 사람이 승격 안 한 기억 (v0.3 신설 · 결정 6) | **도구가 쓴다.** `mem add --hold` 가 달고, 사람이 `mem review --promote <id>` 로 떼면 줄 자체가 사라진다. 달려 있는 동안은 `search`·`hook` 에 안 뜬다 |
| `state` | `hot` / `warm` / `cold` | **도구가 쓴다**(gc). 사람이 쓰지 않는다 |
| `archived` | 접힌 원본이 든 아카이브 경로 | 같음 |

**칸 이름은 영어, 값은 한글.** 머리말은 손으로 조립하지 않고 `yaml.v3` 로 쓴다 — 요약에 `\` 나 `"` 가 들어가면 문자열로 붙인 머리말이 깨지고, 그 기억이 조용히 색인에서 빠진다.

## 4. `sources` — 근거 다섯 꼴

| 접두 | 꼴 |
| --- | --- |
| `file:` | 저장소 안 경로. 빈 값이면 안 된다. 없는 경로면 D02(경고) |
| `commit:` | `^commit:[0-9a-f]{7,40}$` |
| `url:` | `^url:https?://\S+$` |
| `mem:` | 뒤가 기억 id 꼴 |
| `note:` | 아무 글. **`note:` 만 대면 F18 경고** — 기계가 낡았는지 볼 수 없다 |

## 5. 본문 규격

| 규칙 | 값 | 규칙 코드 |
| --- | --- | --- |
| 결론 먼저 | 첫 줄이 결론. 물음표나 「…에 대해」 로 끝나면 경고 | B03 |
| 실질 줄 | **3줄 미만이면 거절** (빈 줄·제목 줄 뺀 것) | B01 |
| 길이 | **120줄 넘으면 경고 · 300줄 넘으면 거절** | B02 · B11 |
| 절 개수 | `##` 이 **8개를 넘으면 경고** | B04 |
| 빈 절 | 제목만 있고 내용이 없으면 거절 | B05 |
| `issue` | `## 증상` · `## 해결` 두 절을 **각 2줄 이상** | B06 |
| `howto` | 번호 목록(`1.` `2.`) 2단계 이상. `①②` 는 번호로 안 친다 | B07 |
| 요약과 본문 | 요약의 낱말이 본문에 거의 안 나오면 경고 | B08 |
| 상대 날짜 | 「어제」「지난주」「최근」「요즘」「이번에」 는 경고 — 반년 뒤 거짓말이 된다 | B09 |
| 한 건에 사실 하나 | 서로 다른 주제의 표·절·요약이 섞이면 경고, **`decision` 은 거절** | M01·M02·M03 |
| 인코딩 | 읽을 때는 BOM·CRLF·cp949 도 받는다 (3단 폴백) | X01·X02·X03 |

읽기 인코딩 3단 폴백 : ① UTF-8 BOM 이면 벗김 ② BOM 없이 유효한 UTF-8 이면 그대로
③ 둘 다 아니면 **cp949 로 해독하고 UTF-8 로 다시 써 준다.** 셋 다 거절이 아니라 자동 고침이고, cp949 로 읽힌 파일만 경고로 센다.

## 6. 무엇을 안 넣나

**이 규칙이 gc 보다 앞에 온다.** 안 들어온 것은 정리할 필요가 없다.

| 안 넣는 것 | 왜 |
| --- | --- |
| 코드를 보면 아는 것 (폴더 구조·의존성·함수 이름) | git 이 안다 |
| 이번 세션에만 쓸 임시 메모 | 다음 세션에 쓸모가 없으면 기억이 아니다 |
| 대화 기록 전문 · 긴 코드 조각 | `파일:줄` 포인터로 대신한다 |
| 비밀값 · 개인정보 | `add` 가 그 자리에서 막는다 (**종료 코드 4**) |
| 이미 있는 기억과 같은 얘기 | 중복 검사가 기본으로 켜져 있다 |
| 「~해라」 꼴 지시문 | 기억은 자료지 지시가 아니다 |

**넣는 기준 한 줄** : *코드에서도 규칙 문서에서도 알 수 없고, 다음 세션에 쓸모 있는 것.*

## 7. 태그 · scope 표준

표준 목록은 `Memory/vocab.toml` 에 있고 git 에 들어간다.

```toml
[tag]          상위 태그 = [하위 태그…]      # 상하위는 한 겹만
[tag.alias]    별칭 = 표준 태그              # add·lint 가 조용히 바꾼다
[tag.deny]     words = [출처 태그…]
[scope]        표준 scope = [메모]
[scope.alias]  별칭 = 표준 scope
```

| 무엇 | 값 |
| --- | --- |
| `mem init` 씨앗 (태그) | 게임 개발 공통 + 구조 태그 17줄 — `build` `engine` `gameplay` `level` `art` `ui` `perf` `platform` `data` `net` `tool` `test` `bug` `security` `design` `doc` `process` 와 그 하위 |
| `mem init` 씨앗 (scope) | **하나도 안 깐다.** 프로젝트 이름은 도구가 못 짐작한다 |
| 태그로 못 쓰는 낱말 | `impl` `poc` `fieldtest` `survey` `decision-table` `wip` `misc` `etc` `note` — 주제가 아니라 출처다 |
| scope 값 규칙 | **툴·부품 이름 통째 하나.** 주제를 붙이지 않는다 (`unity-build` 는 되고 `unity-build-캐시` 는 아니다) |
| 늘리는 법 | `mem tags --add <태그>` · `mem tags --add-scope <이름>` · `mem tags --alias <별칭=표준>` |
| 지금 뭐가 목록 밖인지 | `mem tags --check` |

### 배우는 중 (learning)

**표준 scope 가 하나도 없는 동안은 F09(표준 밖 태그)·F12(표준 밖 scope)를 경고로만 낸다.**
`mem tags --add-scope <이름>` 으로 첫 scope 를 정하는 순간 둘 다 거절로 선다.
첫날부터 다 막히는 도구가 되지 않게 한 장치다 — **첫 scope 를 정하기 전에 목록을 다듬는다.**

## 8. 옛 규격(v0.1)과 다른 것

| 자리 | v0.1 | v0.2 |
| --- | --- | --- |
| 누가 썼나 | `source: user\|ai\|hook\|import` | **`author:`** — `human:<아이디>` / `<도구>/<버전>` / `hook:<이름>` / `import:<저장소>` |
| todo 진행 | `status:` | **`todo_status:`** (OKF 의 `status` 와 뜻이 달라 이름을 비켰다) |
| `title` | 선택 (없으면 요약 앞 40자) | **필수 6~40자.** 요약 베끼기 거절 |
| `sources` | 없음 | **신설.** `decision`·`issue`·`caution` 은 1개 이상 필수 |
| 태그 개수 | 1~5 | **2~5** |
| `stale_after` · `migrated` | 없음 | 신설 |

**옛 파일은 옛 자로 잰다.** `Spec` 이 v0.1 인 기억은 `title`·`author`·`sources` 를 안 따지고 태그 하한이 1이다.
**그래서 `mem migrate` 를 안 돌려도 옛 기억은 이미 다 색인되고 검색에 나온다**(실측으로 확인 — 옛 규격 206건 전부 색인됨).
`migrate` 는 「안 하면 안 보인다」가 아니라 **`author`·`sources`·`title` 같은 새 칸을 채워 품질 규칙(F06 등)의 대상으로 올리는 일**이다 (설계-코드 어긋남 셋 중 하나. `../Design/2026-08-23-v0.3설계.md` 결정 50 참고).

### `mem migrate`

```
mem migrate            # 기본이 --dry-run. 무엇을 고칠지만 보여준다
mem migrate --apply    # 고친다. 고치기 전에 원본을 archive/<날짜>-migrate 에 통째로 남긴다
mem migrate --restore  # 그 아카이브에서 되돌린다
```

- `source` → `author`, `status` → `todo_status` 로 옮기고 `migrated: true` 를 단다.
- `--author <아이디>` 는 옛 `source: user` 인 기억의 사람 아이디다 (기본은 `git user.name`).
- **자동으로 못 채우는 것은 억지로 안 채운다.** 표로 찍고 `mem review` 로 넘긴다.
- 종료 코드 : `0` 정상 · `1` 사용법 잘못 · `2` 되돌릴 것 없음 · `3` 저장소 없음 · `6` 락을 못 얻음.

## 9. 예시

```yaml
---
id: 20260823-1d55e9a0
type: decision
title: 야간 빌드는 CI 기계에서만 돌린다
summary: 야간 전체 빌드는 사람 기계 대신 CI 기계에서만 돌린다. 아침에 결과만 받아 본다
tags: [build, ci]
scope: unity-build
date: 2026-08-23
author: human:mirusona
sources: [file:ProjectSettings/ProjectSettings.asset]
importance: 4
---
결론 : 야간 빌드는 CI 기계에서만 돌린다.

사람 기계에서 돌리면 아침에 그 자리가 잠겨 있다.
CI 기계는 밤에 놀고 있어 같은 일을 공짜로 한다.
```

```yaml
---
id: 20260823-9e02d7f1
type: issue
title: IL2CPP 빌드가 3배 느려짐
summary: 안드로이드 IL2CPP 빌드가 12분에서 36분으로 늘었다. Gradle 캐시가 꺼져 있던 탓이다
tags: [build, engine]
scope: unity-build
date: 2026-08-23
author: claude-code/1
severity: high
sources: [file:ProjectSettings/ProjectSettings.asset]
---
결론 : Gradle 캐시를 켜면 12분으로 돌아온다.

## 증상
빌드 시간이 12분에서 36분으로 늘었다.
오류는 안 나고 조용히 느려지기만 한다.

## 해결
Player Settings 에서 Gradle 캐시를 다시 켰다.
켜고 다시 재니 12분으로 돌아왔다.
```
