> 출발점 : `../Todo/진행상황.md` 4-1 B-05 · 4-2 후보 2, `../History/2026-08-24-코드리뷰-B-품질.md` B-04·B-05, `../History/2026-08-24-최종측정.md` 3-4·4절.

## 0. 결론 먼저

1. **지금 「정밀도」는 대조군(골든셋의 깨끗한 기억)에서 울린 것만 세고, 골든셋이 모르는 기억에서 울린 것은 아예 안 센다.** 그래서 1.000 이 나와도 「울린 것이 다 맞다」는 뜻이 아니다.
2. **B-05 는 정밀도를 둘로 나눈다.** ① 지금 값은 「대조군 정밀도」로 이름만 바꿔 그대로 두고, ② 등급을 올리는 규칙에만 **「실기억 표본 정밀도」**(실기억에서 울린 것을 최대 30건 뽑아 사람이 판정)를 더 잰다. 표본 뽑기·판정 양식·채점기는 AI 가 만든다. **판정은 사용자 몫이다.**
3. **B08 은 요약 이름씨와 본문을 둘 다 `norm`(기본 정규화)·`canon`(대표말 표)에 태운 뒤 견준다.** 거절은 **기본 끔 설정**으로 먼저 넣고, 사용자 표본 판정이 통과선을 넘으면 켠다.
4. **함정 하나** — 실저장소 `Memory/mem.toml` 의 `[canon]` 표가 **지금 비어 있다.** canon 대조를 넣어도 표가 비면 「색인 ↔ index.db」 오탐은 안 사라진다. 표에 줄을 넣는 것은 검색에도 번지므로 사용자 몫으로 둔다 (4절).
5. **색인 판은 안 올린다.** 다만 `[canon]` 에 줄을 넣으면 `index --full` 한 번이 필요할 수 있다 (확인 못 함).

## 1. 지금 어떻게 재고 왜 어긋나나

### 1-1. 재는 곳

`internal/quality/golden.go:362-385` 가 규칙마다 셋을 센다.

| 칸 | 뜻 | 코드 |
| --- | --- | --- |
| 잡음(Fired) | 골든셋 130건 중 규칙이 운 수 | `:369` |
| 진짜(True) | 골든셋이 「이 규칙으로 잡으라」고 적은 것 | `:370-371` |
| 거짓(False) | **대조군(clean)** 에서 운 것 | `:373-380` |
| 정밀도 | 진짜 / (진짜 + 거짓) | `:382-383` |

**잡음 − 진짜 − 거짓 = 아무 데도 안 들어간 울음**이다. 골든셋이 「잡으라」고도 「깨끗하다」고도 안 적은 기억에서 운 것은 버려진다.

### 1-2. 숫자 (원문에서 방향까지 확인)

- 대조군 정밀도 (`최종측정.md` 3-4 표 273·274줄) : `summary-body-match` **잡음 6 · 진짜 2 · 거짓 0 → 1.000**, `relative-date` **잡음 2 · 진짜 2 · 거짓 0 → 1.000**. B08 은 **6번 울어 4번이 안 세어졌다.**
- 실기억 206건 (같은 문서 337~341줄) : 등급을 올린 뒤 오류가 **183 → 191 로 8건 늘었다** (`relative-date` 3 + `summary-body-match` 5).
- 눈검사 (`코드리뷰-B-품질.md` 62~72줄) : `relative-date` **3건 전부 오탐**, `summary-body-match` **5건 중 오탐 2 · 진짜 2 · 경계 1**. **오탐 2건이 둘 다 pinned 사용자 확정 결정**이다.
- 되돌린 뒤 (같은 문서 47줄) : 실기억 오류 **188 → 183 으로 줄었고**, 관문 나쁜 21 거절은 **20 → 19 로 줄었다**(B22 를 다시 못 막는다).

### 1-3. B08 이 오탐을 내는 자리

`internal/quality/checks_body.go:214` `summaryBodyGap` 은 요약 이름씨(`text.go:321` `nounWords`)가 본문 소문자 글에 **글자 그대로** 있는지만 본다(`text.go:375` `containsWord`). 조사 떼기·대표말이 없다. `quality` 패키지는 `token.Normalize`·`Canon` 을 **한 번도 안 부른다** (Grep 0건).

| 오탐 | 왜 못 보나 | canon 으로 풀리나 |
| --- | --- | --- |
| `71e604f3` 「기억·원본·색인·SQLite」 ↔ 본문 「Markdown … index.db … 파생물」 | 같은 것을 다른 이름으로 | **풀린다** — 표에 줄이 있으면 |
| `9a3c1391` 「UI·메시지·도움말·문서」 ↔ 본문 「모든 출력과 문서」 | 본문이 **더 넓은 말**(윗말)로 적었다 | **안 풀린다** — 대표말이 아니다 |

둘째 꼴은 대조로 못 막는다. 그래서 3-3 의 「사용자 확정이면 경고로」 장치가 따로 필요하다.

## 2. B-05 — 정밀도의 새 뜻

### 2-1. 정한 것

| 무엇 | 정한 값 | 까닭 |
| --- | --- | --- |
| 이름 | 지금 값 = **대조군 정밀도**(이름만 바꿈) · 새 값 = **실기억 표본 정밀도** | 옛 값도 쓸모가 있다(대조군 거짓 0 은 여전히 지킬 선). 숫자 하나에 두 뜻을 싣지 않는다 |
| 언제 재나 | **규칙 등급을 올릴 때만** (경고 → 거절, 또는 종류를 넓힐 때) | 경고는 틀려도 막지 않는다. 막는 규칙만 비싸게 잰다 |
| 표본 | 실저장소(`Memory/`)에서 **그 규칙이 거절로 울 기억 전부, 30건이 넘으면 씨앗 고정 무작위 30건** | 206건 때 B08 결정 울음이 5건이었다. 전수가 대개 30 안쪽이다 |
| 최소 수 | **10건 미만이면 「못 잼」** — 올리지 않는다 | 5건으로는 1건 틀림이 20%p 다 |
| 누가 판정 | **사용자** (진짜 / 오탐 / 경계 셋 중 하나) | 「요약과 본문이 같은 말인가」는 글 뜻 판단이다. AI 사전 판정은 참고 칸으로만 둔다 |
| 셈 | 진짜 / (진짜 + 오탐). 경계는 빼고 수만 적는다 | 경계를 어느 쪽에 넣느냐로 값이 흔들리지 않게 |
| 통과선 | **① 표본 정밀도 ≥ 0.95 ② pinned·사용자 확정 기억 오탐 0** ③ 대조군 거짓 0 (옛 선 그대로) | ②가 B-04 의 무게였다 — 사람이 확정한 결정을 막으면 신뢰가 깨진다 |
| `eval --quality` 표 | **「안 셈」 열을 더한다** (잡음 − 진짜 − 거짓). 안 셈이 잡음의 절반을 넘으면 정밀도 옆에 `(표본 적음)` | 1.000 뒤에 6 중 4 가 숨어 있던 것을 표에서 바로 보이게 |

### 2-2. 되풀이할 수 있게 — 명령과 자료 자리

`eval` 에 하위 꼴 둘을 더한다 (새 명령을 안 만든다. `eval` 이 원래 재는 명령이다).

```
mem eval --rule-sample summary-body-match --repo <Memory> --n 30 --seed 7 --out <표본.yaml>
mem eval --rule-score <표본.yaml> --repo <Memory>
```

- `--rule-sample` : 그 규칙을 **거절 등급이라 치고** 실저장소를 돈다. 울린 기억마다 `id · rule · 울린 말 · 본문 해시 · label: ""` 한 줄을 쓴다. 판정 보조로 요약·본문 첫 3줄을 **같은 파일의 `view` 칸**에 넣는다.
- `--rule-score` : `label` 을 세어 2-1 의 셈·통과선 판정 줄을 찍는다. 본문 해시가 바뀐 기억은 「다시 판정」으로 따로 센다.
- **자리** : 판정이 끝난 표본은 **`view` 칸을 지운 꼴**(id·해시·label 만)로 `AIMemoryTool/Docs/History/표본/YYYY-MM-DD-<rule>.yaml` 에 둔다. 기억 내용이 툴 저장소에 안 들어가게 한다 (툴은 공개 예정, 실기억은 비공개). `view` 가 든 판정 중 파일은 스크래치패드나 `.claude/local/` 에 둔다.
- 측정 절차는 `../Guide/측정절차.md` 에 「규칙 등급 올리기」 절 하나를 더한다.

## 3. B08 재상향

### 3-1. 무엇을 바꾸나

| 자리 | 지금 | 바꾼 뒤 |
| --- | --- | --- |
| 견주기 | 요약 이름씨 ↔ 본문 소문자, 글자 그대로 | 이름씨와 본문을 **둘 다 `token.Normalize(text, canon)`** 에 태운 뒤 견준다. 이름씨 하나는 「원래 꼴 **또는** 정규화 꼴이 본문 정규화 글에 있으면」 받친 것으로 친다 |
| 등급 | 모든 종류 경고 (`rules.go:204`) | 경고 그대로 + **결정 종류 · `add` 단계에서만 거절** (설정이 켜졌을 때) |
| 거절 문턱 | 없음 | 받친 비율 **0.25 미만**일 때만 거절. 그 사이는 경고 (경고 문턱 `summaryBackedShare` 는 그대로) |
| 사용자 확정 | 구분 없음 | **`--pin` 으로 넣는 기억은 거절 대신 경고** |
| `lint` | 경고 | **경고 그대로** — 이미 저장된 pinned 결정이 갑자기 「오류」가 되지 않게 |

- **`norm` 의 뜻** : 색인·검색이 같이 타는 기본 정규화(`token/normalize.go:139` `baseNormalize` — 글자 고르기·소문자 + `:161` 조사 떼기). 「색인을」 과 「색인」 을 같게 본다.
- **`canon` 의 뜻** : `mem.toml [canon]` 대표말 표(`token/normalize.go:65` `Apply`). 「SQLite → index.db」 처럼 다른 이름을 한 이름으로 모은다. **검색과 같은 표를 쓴다** — 품질용 동의어 표를 따로 두면 둘이 어긋난다.
- canon 표는 `Options` 로 받는다. `quality.Options`(`gate.go:150` 근처)에 `Canon *token.Canon` 칸을 더하고, `cmd/mem` 이 `config.CanonTable()`(`config/canon.go:10`)로 채운다. 비어 있으면 `norm` 만 탄다.

### 3-2. 기본 끔 설정

`mem.toml` 에 `[quality] summary_body_reject = false` 를 더한다. **꺼져 있으면 지금과 똑같이 경고만**이다. 켜는 것도 끄는 것도 이 한 줄이다 — **되돌리는 길이 설정 한 줄**이고 자료 옮기기가 없다.

### 3-3. 오탐을 막는 장치 넷

1. **norm·canon 대조** — 같은 것을 다른 이름으로 쓴 꼴을 받친 것으로 친다.
2. **거절 문턱을 경고보다 훨씬 낮게(0.25)** — 반쯤 받치는 요약은 경고로만 남는다.
3. **`--pin` 이면 경고로** — 윗말로 적은 꼴(9a3c1391)은 대조로 못 막으니, 사람이 확정한 기억은 막지 않는다.
4. **`lint` 는 경고 그대로** — 거절은 새로 넣을 때만 문다.

### 3-4. 켜는 통과선

아래가 다 맞아야 기본값을 `true` 로 바꾼다.

| # | 선 | 어디서 |
| --- | --- | --- |
| 1 | 실기억 표본 정밀도 ≥ 0.95 · pinned 오탐 0 · 표본 10건 이상 | `eval --rule-score` (2절) |
| 2 | 대조군 거짓 0 · G6 ③ 대조군 정밀도 ≥ 0.80 | `eval --quality` |
| 3 | 좋은 10 오거절 0 | `testdata/gate/gate-demo.sh` |
| 4 | 나쁜 21 에서 **B22 를 다시 막는다** (19 → 20) | 같은 곳 |
| 5 | G6 ① 재현율이 지금보다 안 떨어진다 (norm 대조로 B08 경고가 줄 수 있다) | `eval --quality` |

### 5-2. 색인 판

**안 올린다.** 이 판은 품질 검사와 `eval` 만 고치고 `index.db` 모양을 안 바꾼다. U2 로 `[canon]` 이 바뀌면 `fts_norm` 내용이 옛 표로 남으니 `index --full` 이 필요할 수 있다 — 지금 `index` 가 canon 바뀜을 스스로 알아채는지는 **확인 못 함**(소단계 6 에서 본다).
