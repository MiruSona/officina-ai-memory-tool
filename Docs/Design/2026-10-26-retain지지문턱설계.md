# 2026-10-26 retain 전용 지지 문턱 설계

> 근거 조사 : `Docs/History/JudgeModel/Research/2026-10-26-retain쪼개묻기조사.md` (조사 D) · 실측 : `AIMemoryTool/Docs/Research/2026-10-26-retain지지문턱실측.md`
> 사용자 승인 : 방향(쪼개 묻기 안 넣음 · 전용 문턱 · truncated 기록) 2026-10-26

## 결론 먼저

1. **쪼개 묻기는 넣지 않는다.** retain 근거는 이미 짧은 인용이라 더 자를 데가 없다 (조사 D 결론 1).
2. `llm.toml` 에 **`retain_sure_support`** 칸을 새로 둔다. `retain:*` 후보의 R3 지지 문턱만 이 값을 본다.
   - 칸이 없으면 공용 `nli_sure_support` 값을 쓴다 → **지금 동작 그대로** (하위 호환).
   - 권장 값은 **.85** (실측에서 K 거짓 통과 0).
   - 공용 `nli_sure_support`(.89)는 그대로라 `mem add --nli` · `mem judge` · C04 안내 · review 는 안 바뀐다.
3. 판정 서버 응답의 **`truncated`**(입력을 토큰 상한에서 잘랐나)를 받아 판정 기록과 retain-log 후보 줄에 남긴다. **판정은 안 바꾼다.**

## 1. 어디를 바꾸나

| 자리 | 바꾼 것 |
| --- | --- |
| `internal/config/llm.go` | `LLMConfig.RetainSureSupport`. `readSure(file, "retain_sure_support", 공용 값)` — 범위(.34~.99) 밖이면 공용 값과 문제 한 줄 |
| `cmd/mem/cmd_add_auto.go` `checkAuto` | `retain.IsRetain(origin)` 이면 판정기를 만들기 전에 `settings.NLISureSupport = settings.RetainSureSupport` |
| `internal/llm/nli.go` · `common.go` · `judge.go` | 응답 `truncated` → `Choice.Truncated` → `Verdict.Truncated`(판정 기록 json) → `Judge.Truncated()` |
| `internal/retain/gate.go` · `gate_support.go` | `Result.Truncated` — R3 물음 중 하나라도 잘렸으면 참. `askJudge` 가 표시만 한다 |
| `cmd/mem/retain_child.go` · `retain_session.go` · `retain_log.go` | 자식 JSON 의 `auto.truncated` → `childResult.Truncated` → retain-log `items[].truncated` |
| `cmd/mem/cmd_judge.go` · `internal/i18n/llm.go` | `mem judge config` 에 「retain 지지 0.85」 와 json `retain_sure_support` |

### 왜 판정기 문턱을 통째로 갈아 끼우나

retain:* 의 판정기는 R3 전용으로 `checkAuto` 안에서 새로 만든다. 그 판정기의 지지 선만 바꾸면 다음이 맞아떨어진다.

- 「A 인데 문턱 아래면 모른다 → 거절」 자리(인용별 · 이어 붙임 물음)가 새 값을 본다.
- 제목 검사(`checkTitle`)는 반대 확률 b 와 `nli_sure` 만 보므로 영향이 없다.
- `--origin stop`(느슨판)은 `IsRetain` 이 거짓이라 공용 값을 그대로 쓴다.
- 다른 mem 자리는 각자 `config.LoadLLM` 으로 판정기를 따로 만들어 공용 값을 쓴다.

## 2. 지킨 것

- 비밀 승격 차단 · 꼬리표 떼기 · 판정 기록 자리는 그대로 (`llm.Judge` 를 안 건드림).
- 키 값은 화면 · 기록 어디에도 안 찍는다. 새 칸은 수 하나다.
- 문턱이 범위 밖이거나 NaN 이면 공용 값으로 되돌아간다 (`readSure` 의 참 범위 검사).
- `retain_sure_support` 가 `nli_sure` 보다 낮으면 문제 한 줄을 내고 공용 값으로 되돌린다 (코드 리뷰 2026-10-26). 공용 칸은 알리기만 하지만, retain 은 사람 눈이 없는 길이라 받지 않는다.

## 3. 안 한 것

- 요약 절 검사 · 근거 쪼개기 (조사 D 4절).
- 생성 프롬프트에 「요약은 인용이 말한 것만」 조이기 — 문턱을 내린 값으로 생기는 「덧붙인 말」 통과를 막는 짝이다. 다음 판 후보.
- `truncated` 로 판정을 바꾸기 (예 : 잘렸으면 다시 묻기). 지금은 얼마나 자주 잘리는지만 센다.
