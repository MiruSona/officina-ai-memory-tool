# merge(C20) 2차 거름 : 임베딩 닮음 문턱 설계 (2026-10-11)

> 상태 : **미룸** (2026-10-11 사용자 결정 — JudgeModel 을 범용 판정 모델로 보고 d 를 v1.1 후보로 두기로 해,
> AIMemoryTool 안 임시 땜질인 이 설계는 뒤로 미룸)

## 결론

1. **(다)를 권한다.** 두 곳에서 짝을 건진다.
   - (나) Near 짝인데 낱말 문턱을 못 넘은 것.
   - (가) Near 에 아예 없지만 벡터로 서로 가장 가까운 것.

   두 곳 모두 「코사인 문턱 + 서로 k위 안」을 통과해야 merge 줄에 오른다.
   까닭 문구 앞에 출처를 붙인다(`임베딩 닮음 · ` / `임베딩 닮음(낱말 밖) · `).
2. **까닭 : 놓친 짝이 두 곳에 다 있다.**
   - 「약 5%」는 문턱이 뺀 Near 짝 130개에서 뽑은 표본 20개 중 맞다 1개다 — (나)의 몫.
   - 판정셋 v3 에는 「C20 Near 밖 놓침」 20짝이 따로 있다(라벨 a 5 · b 1 · c 2 · d 12) — (가)의 몫.
   - 비용 차이도 작다. 벡터는 review 가 이미 싣고 있다(`cmd/mem/cmd_review.go:68`).
3. **review 에만 붙인다.** lint 와 `quality` 의 C20 (가)·(나)는 고치지 않는다
   (lint 의 20k 10초 예산과 dup_vectors 기본 꺼짐, 설계 18-7).
4. **문턱 값은 지금 정하지 않는다.** 나갈 때는 `merge_vec_floor = 0`(꺼짐).
   실데이터 분포를 보고 손검사한 뒤 기본값을 박는다.

## 1. 지금 짝이 만들어지는 길 (코드로 확인)

- **Near 짝의 출처는 낱말뿐이다.** `quality/checks_cleanup.go:182-225` `clashAndNear` —
  후보 세션(`Session.Candidates`)에서 문장 정렬값 0.35 이상인 짝 + 중복 판정 soft 짝(C02, `softMatch` :171).
  기억 하나당 3짝(`nearPairMax`, `quality/repo.go:61`). `mergeNearPairs`(:261)에서 한 번만 세어 `RepoReport.Near`(`repo.go:40-59`).
- **C20 (가) 문턱** : `checks_cleanup.go:340-385` — 일반 짝 정렬 0.30 · 닮음 0.07(`mergeAlignMin`, `mergeScoreMin`),
  history 짝 0.75 · 0.10(:354), 옮겨 온 같은 날 짝 0.25(:363). 상수이고 설정 키는 없다.
  큐로 보내는 곳은 `routeNear`(:411), 까닭 문구는 :443.
- **임베딩은 지금 merge 에 쓰이지 않는다.** review 는 `Options.Near` 로 벡터를 넘기지만
  (`review/review.go:172`, `repoOptions` :257) `quality/similar.go:987-996` `newSimilarFor` 는
  `[quality] dup_vectors` 가 참일 때만 꽂는다. 기본값(`config/config.go:373`)·스튜디오 `Memory/mem.toml:101` 모두 false.
  그래서 후보 데려오기(`vectorLimit` 10)와 점수 얹기(`vectorLift`, 서로 1위 · cos−0.50)가 꺼져 있다.
- **임베딩** : `multilingual-e5-small-ko-v2`(`embed/assets.go:26`), 384차원 int8.
  `Memory/vectors.bin`(`embed/vectors.go:3-35`), 스튜디오 약 467KB · 약 1,150건.
  `Vectors.Near` 는 3,000건 이하면 모두 재고, 넘으면 LSH 밴드(:123-170). `Cos` 는 짝 하나에 한 번.
  모델을 다시 싣지 않고 만든 벡터끼리만 견준다(`cmd/mem/embed.go:96-108`).
- d 가 하려던 「보탬」 자리는 (지워진) `review/fold.go` 의 `--nli` 보탬이었고 후보는 Near 짝뿐이었다 — d 는 (나)만 메웠을 것이다.

### 거르는 조건 (두 원천 공통)

- 같은 scope · 같은 종류. 둘 다 history 이면 안 낸다(`mergeAddable` 재사용 — 「이어진 단계」 함정).
- 살아 있고 observation·todo 가 아니다.
- 이미 걸린 짝은 뺀다 : merge 줄 있는 짝(`mergeIndex`), 모순 짝(`clashSet`),
  `pairSet(found.ByID, StaleConflictPair, CitedNotSuperseded, NewerSibling, DecisionConflictLive, SupersedeMissing)`.
- 서로 k위 안이어야 한다(`Near(left,k)` 에 right 가 있고 거꾸로도). 절대 cos 하나로는 못 가른다(결정 33).
- 기억 하나의 merge 줄은 기존 포함 3짝까지, 한 판 보탬은 10줄까지(`vecMergeMax`, `--all` 이면 풀림).
- `addFolds` 자리(지금은 없음) 다음에 돈다. 모순·접기에 걸린 짝은 `dropShadowed` 가 지운다.

### 설정 키 (`[quality]`)

- `merge_vec_floor`(실수, 기본 0 = 꺼짐) · `merge_vec_rank`(정수, 기본 1 — `DefaultDupRankK` 와 같음) · `merge_vec_wide`(참/거짓, 기본 거짓).
- 잴 때 쓰는 환경변수 뒷문 : `MEM_MERGE_VEC_FLOOR` · `MEM_MERGE_VEC_RANK` · `MEM_MERGE_VEC_WIDE`(`MEM_DUP_C0` 꼴, `similar.go:286-303`).
- 벡터 파일이 없는데 켜져 있으면 「못 본 것」에 「벡터 없음 — 임베딩 닮음 안 봄」을 적는다.

### 큐 줄 까닭 문구

앞에 붙인다 — 뒤에 붙이면 whyRoom 에 잘린다(설계 :305).

- (나) `임베딩 닮음 · ` + "`<id>` 와 뜻이 닮았다 (코사인 0.91 · 서로 1위 · 정렬 0.24 · 닮음 0.170). 하나로 합칠지 본다"
- (가) `임베딩 닮음(낱말 밖) · ` + "`<id>` 와 뜻이 닮았다 (코사인 0.93 · 서로 1위). 하나로 합칠지 본다"

규칙은 그대로 `merge-candidate`, 큐도 merge, 다음 명령 줄도 C20 과 같다.

## 4. 기본 문턱 고르는 절차 (값은 손검사 뒤)

1. 분포 덤프 시험 `TestVecMergeRealDump`(`MEM_REAL_DIR` 없으면 Skip, 본문 없이 id 와 숫자만).
   묶음 ① 지금 C20 줄 11짝(맞다 9 · 애매 2) ② (나) 원천 전부 ③ (가) 원천 중 서로 3위 안 ④ 같은 scope·종류 무작위 300.
   묶음마다 cos 분위수(10·50·90·99)와 서로 순위를 낸다.
2. 첫 문턱 : ① 맞다 9짝 최소 cos 근처이고 ④ 무작위 99분위보다 위. 겹치면 rank 1 고정하고 cos 를 올린다.
3. `MEM_MERGE_VEC_FLOOR=<값> mem review --kind merge --all --json` 을 원천별(WIDE 끔/켬) 한 번씩 돌려 새로 오른 줄 수를 본다.
   목표는 스튜디오 원천별 10줄 안쪽.
4. 손검사 : 원천마다 10~20줄(맞다/애매/틀리다). (나)는 맞다 절반 이상이면 통과.
   (가)는 못 넘으면 `merge_vec_wide` 끈 채 둔다. 「Near 밖 놓침」 자료가 있으면 거기서 몇 짝 올라오는지 본다.
5. 최대 3바퀴. 바퀴마다 이 문서 표에 적고, 정한 값은 `config.go` 기본값에 박는다.

## 5. 시험

## 7. 남은 걱정

- e5 코사인이 뭉쳐서 「서로 1위」를 빼면 문턱이 뜻을 잃는다 — rank 2 이상은 손검사로 뒷받침될 때만 쓴다.
- (가)의 20k 소요 시간은 안 쟀다 — 덤프 시험에서 같이 재고, 느리면 `--scope` 기억만 원천으로 삼는다.
- 판정셋 v3 「Near 밖 놓침」 라벨은 NLI 라벨(a/d)이라 「합칠 만함」과 같은 뜻이 아니고, d 에는 「이어진 단계」 짝도 섞여 있다.
