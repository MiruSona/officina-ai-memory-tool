## 0. 결론 먼저

- **뜻 답** = C2(뜻 후보 섞기)가 켜졌을 때 **낱말 검색에는 안 걸리고 임베딩(뜻)으로만 올라온 기억**이다. 화면에 `[뜻]` 칸(`RungMeaning`)으로 앉고 **strict 답(「정확히 찾았다」)으로 센다.**
- 지금 이 답을 거르는 것은 **코사인 바닥(0.58) + 뜻 순위(3위 안)** 둘뿐이다. 바닥을 0.60 으로 올려도 헛답(없는 것을 있다고 답함)이 남아 C2 를 껐다.
- **정한 안 : 「도드라짐」 문턱을 하나 더 단다.** 뜻 답의 코사인이 **그 질문의 뜻 후보 20개 가운데값보다 `mix_gap` 이상 높을 때만** 답으로 받는다. 기본값은 측정으로 고른다(후보 0.04~0.10).
- 관문은 **C2 가 켜졌을 때만** 돈다. 기본 `mix = false` 는 그대로라 지금 사용자 화면은 안 바뀐다. **색인 판은 안 올린다.**
- 측정은 **이 PC 에서 임베딩 모델(ko-v2 int8 · onnxruntime)만** 있으면 된다. **로컬 LLM · 미니PC 는 필요 없다.**

## 1. 문제 — 지금 무엇이 안 되나

### 1-1. 코드 경로

| 자리 | 하는 일 |
| --- | --- |
| `internal/search/mix.go:139` `mixMeaning` | 섞기가 켜졌고 벡터가 있으면 뜻 후보를 데려와 `fuse` 로 섞는다 |
| `internal/search/mix.go:162` `meaningPicks` | `scanner.Nearest(…, mix_top=20)` 으로 뜻 가까운 20개를 받고, 좁히기(종류·날짜 등)를 지난 것만 남긴다 |
| `internal/search/mix.go:211` `counts` | **유일한 관문** : `cos >= mix_floor && place <= mix_rank` |
| `internal/search/mix.go:228~244` | 낱말 목록에 없던 뜻 후보가 관문을 넘으면 `Rung = RungMeaning` · `Meaning = true` 로 새 답이 된다 |
| `internal/search/ladder.go:23~25` · `wave3c_test.go:26` | `RungMeaning`(7)은 사다리 밖 자리지만 **strict 로 센다** (C2 · 2026-10-05) |
| `internal/config/config.go:290~296` | `DefaultEmbedMix = false` · `MixFloor 0.58` · `MixRank 3` · `MixTop 20` |

낱말 쪽에는 「없으면 없다고 한다」(G2) 관문 `abstain_floor`(`config.go:185` · 기본 0.15)가 있지만, **뜻으로만 온 답은 이 관문과 상관없이 바로 strict 가 된다.** 그래서 낱말 쪽이 「없다」고 판정한 질문에도 뜻 답 하나가 끼면 헛답이 된다.

### 1-2. 숫자 (측정 문서 9-2 원문 · 의미 모드 · 방향 확인함)

| 판 | v3 r@5 (/69) | fresh-B r@5 (/34) | probe 헛답 (/29, **낮을수록 좋음**) | fresh-B 답 없음 abstain (/9, **높을수록 좋음**) |
| --- | --- | --- | --- | --- |
| 끔 | 51 | 25 | 15 | 2 |
| 0.58 켬 | 53 | 27 | 18 (↑ 나빠짐) | 0 (↓ 나빠짐) |
| 0.60 켬 | 52 | 27 | 16 (↑ 나빠짐) | 0 (↓ 나빠짐) |

- 0.60 판의 기준 넷 중 「probe 헛답 ≤ 끔」 「fresh-B abstain ≥ 끔」 둘을 못 채워 껐다 (측정 9-1).
- 새 헛답은 모두 `[뜻]` 칸 답이다 : `서버 권위 넷코드 롤백` · `iOS 앱스토어 심사 거절` · `아랍어 RTL 텍스트` (probe), `pre-commit hooks …` · `유니티 멀티플레이 넷코드 …` (fresh-B).
- **fresh-B 의 두 헛답은 코사인이 0.60 위다** (측정 9-2). 바닥만 올리면 진짜 뜻 답(살아남)부터 먼저 잃는다 — 0.60 에서 v2~v4 살아남이 둘 → 하나로 줄었다.

### 1-3. 왜 바닥만으로는 안 되나

ko-v2 int8 코사인은 **0.5~0.75 에 몰린다** (측정 5절). 게임 개발 기억이 가득한 저장소에 「넷코드」처럼 **주제는 맞고 내용은 없는** 질문을 하면, 기억 여럿이 고르게 0.6 언저리로 올라온다. 바닥 하나로는 「고르게 다 비슷한 판」과 「하나만 뚜렷하게 가까운 판」을 못 가른다.

## 2. 관문의 뜻

### 2-1. 어떤 답에만 걸리나

- **뜻으로만 온 답**(`mix.go:228` 고리, `seen` 이 아닌 뜻 후보)에만 건다.
- 낱말 답이 뜻 덕에 순위가 오르는 몫(`mix.go:217~221`)에는 **안 건다.** C2 의 r@5 오름 중 이 몫은 헛답을 안 만들기 때문이다.

### 2-2. 무엇으로 판정하나 — 「도드라짐」

```
도드라짐 = 그 뜻 후보의 cos − (Nearest 20개 cos 의 가운데값)
뜻 답으로 받는다 ⇔ cos ≥ mix_floor  그리고  place ≤ mix_rank  그리고  도드라짐 ≥ mix_gap
```

- 가운데값은 **좁히기 전 `near` 20개 전체**로 잰다. 좁히기 뒤로 재면 `--type` 같은 거르개에 따라 같은 질문의 문턱이 흔들린다.
- 평균이 아니라 가운데값을 쓰는 까닭 : 모음기억 카드와 원본처럼 거의 같은 기억이 둘씩 있으면 평균이 끌려 올라간다.

| 버린 안 | 버린 까닭 |
| --- | --- |
| 바닥만 더 올리기 (0.62~) | 1-2 대로 헛답보다 진짜 뜻 답이 먼저 빠진다 |
| 1위와 2위의 차 | 카드·원본 쌍이 1·2위를 같이 차지하면 차가 0 에 가까워 진짜 답도 막힌다 |
| 낱말 쪽이 「없다」고 했으면 뜻 답 금지 | C2 가 살리려던 「다른 이름으로 부른 것」이 바로 낱말 쪽이 없다고 하는 질문이다 — 살아남이 0 이 된다 |
| 문턱 학습(작은 분류기) | 판정 자료가 probe 29 · fresh 9 로 너무 적어 바로 외워 버린다. 숫자 하나 문턱이 먼저다 |
| 실패한 뜻 답을 「참고」 칸으로 낮춰 보이기 | 화면·`format.go` 칸 셈이 바뀌어 일이 커진다. 문턱이 실패하면 다음 판 후보로 둔다 (5-3) |

### 2-3. 기본값 · 설정 칸 · 되돌리는 길

| 항목 | 값 |
| --- | --- |
| 설정 칸 | `mem.toml [embed] mix_gap = <값>` (새 칸) · `EmbedConfig.MixGap` · `DefaultEmbedMixGap` |
| 기본 | **`mix = false` 는 그대로.** `mix_gap` 기본값은 측정으로 고른 값. 섞기가 꺼져 있으면 아무 일도 안 한다 |
| `mix_gap = 0` | 도드라짐 관문을 끈다 → 오늘 동작과 건마다 같아야 한다 (시험으로 묶음) |
| 시험 뒷문 | `MEM_MIX_GAP` (다른 `MEM_MIX_*` 와 같은 꼴, `mix.go:48` 근처) |
| 보기 | 뜻 답의 `Parts.From` 꼬리에 도드라짐을 붙인다 : `뜻(2위 · 0.641 · 도드라짐 0.083)`. 왜 들어왔나·왜 빠졌나를 로그로 바로 본다 |
| 되돌리기 | `mix_gap = 0` 또는 `mix = false`. 색인·저장 꼴은 안 바뀐다 |

## 3. 통과선과 재는 법

### 3-1. 미리 못 박는 통과선 (`mix = true` · 고른 `mix_gap` 판을 `끔` 판과 비교)

| # | 기준 | 지금 0.60 판 |
| --- | --- | --- |
| 1 | probe strict 헛답 ≤ 끔 (15/29) | 16 — 못 채움 |
| 2 | **새 눈가림 셋 fresh-C** 답 없음 abstain ≥ 끔 · fresh-B abstain ≥ 2 (개발용 확인) | 0 — 못 채움 |
| 3 | v2 · v3 · v4 · fresh-A · fresh-B · fresh-C r@5 가 끔보다 안 낮음 · 낱말 정답 밀림 0 | 채움 |
| 4 | v3 r@5 +2 이상 **그리고** fresh-C r@5 +1 이상 · v3 MRR ≥ 끔(0.568) | — |
| 5 | p95 ≤ 900ms (CLI 벽시계) | 채움 |
| 6 | `mix = false` · 낱말 모드 · `mix_gap = 0` 이 각각 전과 0건 다름 | — |

**4번을 옛 자 ①·②의 +3 이 아니라 +2 로 둔 까닭** : 관문은 오름을 깎기만 한다. 사용자가 10-05 에 「0.60 으로 조여 헛답이 안 늘면 켠다」고 정했을 때 오름은 +1~2 였다 — 막힌 것은 헛답이지 오름 폭이 아니었다(측정 9절 머리). 이 기준대로 정한다.

### 3-2. C2 를 다시 재는 절차

1. **사본 준비** : 830건 의미 모드 사본을 새 자리로 복사하고 새 exe 로 `index --full` (벡터는 그대로 쓰여야 한다 — 「0건 새로」 확인). 홈에 ko-v2 + onnxruntime. 법은 측정 문서 9-3 · `../Guide/측정절차.md`.
2. **고르기 (개발 셋만)** : `MEM_MIX=1 MEM_MIX_RANK=3 MEM_MIX_KEEP=0 MEM_MIX_FLOOR=0.58` 에 `MEM_MIX_GAP` = 0 · 0.04 · 0.06 · 0.08 · 0.10 다섯 판. v2 · v3 · v4 · probe · fresh-A · fresh-B 로만 고른다. **먼저 헛답 다섯 건과 살아남 건의 도드라짐을 표로 뽑아 갈리는지 본다** — 안 갈리면 여기서 멈춘다 (5-3).
3. **fresh-C 만들기** : 측정절차 81줄 법 그대로 (씨앗 뽑기 · 검색을 못 보는 판이 본문만 보고 씀). 답 없는 질문을 10건 이상 넣는다 — fresh-B 는 9건이라 한 건에 판정이 뒤집혔다.
4. **판정 한 번** : 끔 / 고른 값 두 판을 같은 exe 로. fresh-C 는 이때 한 번만 본다.
5. **회귀** : 6번 기준을 `same.py` 꼴로 건마다 비교.
6. 결과를 측정 문서 10절로 붙인다. 켤지는 사용자에게 묻는다 (기본값 바꾸기라서).

### 5-2. 색인 판

**안 올린다.** 도드라짐은 검색할 때 `Nearest` 가 주는 코사인으로만 계산한다. 색인·벡터 파일 꼴은 그대로다. 새 설정 칸은 `mem.toml` 에만 생기고, 없으면 기본값을 쓴다.

### 5-3. 위험

| 위험 | 대응 |
| --- | --- |
| 헛답도 도드라짐이 크다 (fresh-B 두 건은 cos 가 이미 0.60 위) | 3-2 의 2에서 **코드 판정 전에** 표로 먼저 본다. 안 갈리면 C2 는 끈 채 두고, 다음 판 후보를 「참고 칸으로 낮추기」로 옮긴다 |
| 질문 수가 적다 (probe 29 · 답 없음 9) | fresh-C 에 답 없는 질문 10건 이상. 결과는 「한 건에 뒤집힌다」고 같이 적는다 |
| 개발 셋에 맞춘 값이 새 셋에 안 옮겨 감 (1차 판에서 겪음) | 값 후보를 다섯으로 묶고 fresh-C 는 판정에 한 번만 |
