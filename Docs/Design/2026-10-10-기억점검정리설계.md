## 1. 흐름 (사람 또는 AI 세션)

1. `mem review --kind retired,gone,conflict,contradict,merge,value --table` : scope·종류별 표를 본다.
2. AI 세션이 처리할 때는 `mem review --kind … --ids --all` : 한 줄에 `종류<TAB>규칙<TAB>id<TAB>같이 볼 id` 꼴로 받는다.
3. 한 건씩 `mem show` 로 읽고 판단한다. 처리는 다섯 가지다.
   - 합쳐 새로 쓰고 옛 것을 덮는다 : 새 기억을 쓴 뒤 `mem set <옛 id> --by <새 id>`
   - 근거를 고친다 : `mem set --sources`
   - 본문을 고친다 : `mem set --body`
   - 그대로 둔다 : `mem set --stale-after <날짜>` 로 다음에 다시 볼 날을 적는다
4. 덮이거나 무효가 된 것은 `mem gc --retired` 로 미리 보고, `mem gc --retired --apply` 로 접는다.

### ② 본문 경로 대조 규칙 (D05)

오탐을 줄이려고 네 겹으로 거른다. 걸러진 것이 많아 놓치는 경로가 있어도 괜찮다. 이 검사는 후보만 올린다.

1. **경로로 보는 낱말** : `/` 를 하나 이상 품은 연속 글자. 끝에 붙은 `.,)」·` 와 한글 조사는 첫 비경로 글자에서 자른다.
2. **확장자가 있어야 한다** : `.go` `.md` `.cs` `.json` `.toml` `.ps1` `.yaml` 등. 확장자가 없는 폴더 경로(`internal/install`)는 안 본다.
3. **첫 마디가 실재해야 한다** : 경로의 첫 마디가 프로젝트 뿌리나 scope 폴더 아래에 실제로 있어야 본다. 없으면(예 : `Assets/…`, 게임 저장소 경로) 남의 저장소로 치고 「있다」고 본다. `anyKnown` 의 「밖이면 있다」와 같은 생각이다.
4. **세 기준 중 하나에서라도 있으면 멀쩡하다** : 프로젝트 뿌리 · 저장소 폴더 · **scope 폴더**. scope 폴더는 뿌리 바로 아래 폴더 중 이름을 소문자로 바꿨을 때 scope 와 같은 것이다(`aimemorytool` → `AIMemoryTool/`). 이 셋 모두에서 없을 때만 D05 를 낸다.

경로 집합은 `pathSet` 이 한 번 만든 것을 그대로 쓴다. 200,000개를 넘으면 지금처럼 이 검사를 건너뛰고 「못 본 것」에 적는다.

### ⑤ 모순 후보 고르기와 상한 (C19)

- **짝을 고르는 법** : 중복 판정 후보 세션에서 정렬값이 0.35 이상인데 C13 도 중복도 아닌 짝을, 기억 하나당 3쌍까지 받는다. 같은 scope 이고, 둘 다 살아 있고, 종류가 decision·caution·fact·howto 안이어야 한다. 짝 순서를 정해 (작은 id, 큰 id) 로 한 번만 센다.
- **NLI 에 보내는 글** : 기억 본문 전체가 아니라 정렬된 **두 문장**만 보낸다. 근거 = 옛 기억 쪽 문장, 주장 = 새 기억 쪽 문장. 짧아서 빠르다.
- **판정 사다리** : `llm.Judge{NLI: llm.NewNLI(settings)}` 를 쓰고 Client 는 nil 로 둔다 — SemIf 는 안 부른다. 비밀 꼴 거절과 판정 기록 캐시(`Memory/local/judge/`)는 기존 것을 그대로 쓴다. 두 번째 실행은 캐시에서 바로 나온다.
- **상한** : NLI 짝은 scope 당 20, 전체 100이 기본이다(`--nli-pairs` 로 바꿈). p95 414ms 로 치면 최악 약 41초다. 처음 시작할 때 `/health` 를 한 번만 묻고(1초), 실패하면 「NLI 를 못 써서 규칙 층만 봤다」를 「못 본 것」에 적는다.
- **규칙 층** : RuleJudge 는 상한 없이 모든 짝에 돈다. 프로세스 안의 계산이라 비용이 거의 없다.

### ⑥ 합치기 후보 (C20)

**합칠 만한 짝**을 `merge` 큐에 올린다. 합치는 글은 사람·AI 가 쓴다. 처리는 기억 쓰기 규칙 넷 ① 과 같다 — 둘을 합쳐 새로 쓰고, 옛 둘을 각각 `mem set <옛 id> --by <새 id>` 로 덮는다(`mem set` 은 id 를 하나씩 받는다).

`internal/consolidate` 의 모음 카드(observation)와는 다른 일이다. 모음 카드는 원본을 **남긴 채** 위에 요약을 하나 더 얹는다. 합치기는 원본 둘을 **덮고** 한 기억으로 바꾼다. 모음 카드는 C20 의 짝에서 뺀다.

**공통 조건** : 두 기억이 같은 scope·같은 종류이고, 둘 다 살아 있으며(`quality.Live`), 어느 쪽도 observation·todo 가 아니다. decision 짝이 이미 C05·C08 에 걸렸으면 C20 을 안 낸다 — 같은 짝을 conflict 큐가 맡는다.

| 갈래 | 고르는 법 | 자리 |
| --- | --- | --- |
| (가) 중복으로 써 둔 것 | 중복 판정이 경고 자(`DupWarn`) 이상이거나 부분 중복(`Partial`)으로 C02 를 낸 짝. C01(거절)·C03(본문 같음)은 뺀다 — 그건 add 가 이미 막았어야 하고 lint 가 거절로 말한다. 즉 C02 의 짝을 review 큐로 보내는 것이다 | `findDuplicates` 가 채우는 `NearPair.Soft` |
| (나) 쪼개진 것 | 아래 넷을 다 만족한다.<br>① `file:`·`commit:` 근거를 하나 이상 같이 단다(`file:` 의 줄 번호는 떼고 견준다)<br>② 날짜가 7일 안이다<br>③ 제목 낱말(두 글자 이상, `text.go` 의 낱말 자르기)이 둘 이상 겹친다<br>④ 본문은 서로 다른 부분을 말한다 — 문장 정렬값이 0.35(C13·C17 의 자) 아래이고 본문이 같지 않다 | `quality/checks_merge.go`. 근거 문자열로 묶어 묶음 안에서만 짝을 본다(O(n²) 을 안 만든다). 한 근거를 단 기억이 20건을 넘으면 그 근거는 묶음에서 뺀다 — README 처럼 흔한 근거는 쪼개짐 신호가 아니다 |

- **짝은 한 번만** : (작은 id, 큰 id) 로 센다. 걸림은 작은 id(옛 것) 쪽에 달고, `Related` 에 큰 id 를 넣는다.
- **상한** : 기억 하나당 3쌍(`nearPairMax`, C13·C19 와 같은 값). (가)와 (나)가 같은 짝이면 (가)로 한 번만 낸다.
- **까닭 글** : (가)는 「`<id>` 와 닮았다 (정렬 0.xx · 닮음 0.xxx). 하나로 합칠지 본다」, (나)는 「`<id>` 와 같은 근거 `<근거>` 를 달았고 날짜가 n일 차이다. 한 내용이 둘로 쪼개졌는지 본다」.

**C17(덮임 닮음) · C19(모순) 과 같은 짝을 두 번 내지 않는다.** 닮은 짝 하나(`NearPair`)를 아래 차례로 한 곳에만 보낸다.

1. **C13 이나 C19 에 걸린 짝 → contradict 만.** 어긋나는 둘을 합치면 틀린 쪽이 섞인다. C19 는 review 에서 나므로 review 가 큐에 담을 때 같은 짝의 merge 줄을 지운다.
2. **한쪽이 분명히 더 새것이고 새 쪽 본문에 바뀜 말이 있으면 → C17 (conflict).** 「분명히 더 새것」은 날짜가 하루 이상 다르다는 뜻이다(같은 날 쓴 둘은 어느 쪽이 고친 것인지 모른다). 「바뀜 말」은 C16 의 낱말(덮/대신/바꾼/고친/뒤집)에 「이제」·「더 이상」·「폐기」·「취소」를 더한 것이다. 이 둘이 다 있어야 「새 것이 옛 것을 고쳤다」로 본다. C17 은 옛 쪽에 단다.
3. **나머지 중 (가)·(나)를 만족하는 짝 → C20 (merge).** 날짜가 같거나, 새 쪽이 옛 쪽을 고친다는 말이 없으면 「같은 것을 두 번 썼다」 쪽으로 본다. (가)·(나) 둘 다 아니면(정렬값만 0.35 를 넘는 짝) 어느 큐에도 안 간다 — C19 의 짝 후보로만 남는다.

C17 은 caution·howto·fact 만 보므로(결정 4) decision·history·issue 짝은 2번을 건너뛰고 바로 3번으로 온다. 단 decision 은 공통 조건대로 C05·C08 이 먼저 맡는다.

## 4. `review --kind value` 버그

## 6. 출력 꼴

- **`--scope a,b`** : 보고 싶은 scope 만 남긴다. 큐에 담을 때 거른다. `CheckRepo` 는 저장소 전체로 돈다 — 근거(C14)가 다른 scope 에 걸쳐 있을 수 있어서다.
- **`--table`** : 큐마다 `## 종류 (n건)` 아래 scope 별 `### scope (n건)` 과 표 `| 날짜 | id | 제목 | 까닭 | 같이 볼 것 | 다음 |` 를 찍는다. 상한은 (종류, scope) 마다 `--limit`(기본 20)이다. 넘친 건수는 지금처럼 「못 본 것」에 적는다.
- **기본 출력** : 지금 목록 꼴 그대로다. 훅과 기존 시험이 이 꼴을 읽는다.
- **AI 용 꼴 둘** :
  - `--json` : 지금 것에 Item 의 `scope` 칸과 Report 의 `by_scope` 칸을 더한다.
  - `--ids` : 한 줄에 `kind\trule\tid\trelated(쉼표)`. 머리말이나 꾸밈은 없다.
- **`--all`** : 상한을 없앤다. AI 가 한 번에 다 받을 때 쓴다.
- 글은 지금처럼 전부 `safe.Summary` 를 지난다 (불변조건 I3).

## 7. `mem gc --retired`

- **고르는 것** : 조건 넷을 다 만족하는 기억이다.
  - `superseded_by` 가 있거나 `invalid_at` 이 지났다
  - `state` 가 cold 가 아니다
  - pinned 가 아니다
  - 살아 있는 모음 카드의 `mem:` 근거가 아니다 — 접으면 본문 해시가 바뀌어 카드가 [낡음] 이 된다. `exemptSQL` 의 같은 조건을 떼어 함께 쓴다
- **나이·건수 문턱은 없다.** 한 번 상한(`EffectiveBatchLimit`, 200건)만 지킨다.
- **기본은 미리보기**이고, `--apply` 를 줘야 접는다. 지금 gc 는 `--dry-run` 을 줘야 미리보기라 기본이 반대다. 그래서 `--retired` 를 줬을 때만 이 기본을 쓰고, 도움말에 따로 적는다.
- **접기** : `foldOne` 을 그대로 쓴다 — 원본은 아카이브에 남기고, `log.md` 에 `(gc --retired)` 를 적는다. 되돌리기는 `mem gc --restore <id>`.
- **자리** : `gc/retired.go`(고르기) · `gc/gc.go: dispatch` 갈래 · `cmd/mem/cmd_gc.go`(`retired`·`apply` 깃발).

## 다음 세션이 알아야 할 것

- **allow 규칙** : 지금 allow 규칙은 `mem review` 와 `mem review --kind:*` 뿐이다. `mem review --table` 이나 `--scope` 로 시작하면 승인 창이 뜬다. 쓸 때는 **`--kind` 를 맨 앞에** 둔다. 규칙을 늘릴지는 사용자에게 묻는다.
- **0단은 혼자 먼저 한다.** rules.go 와 `RepoOptions` 꼴을 먼저 박아야 1~4단 갈래들이 서로 안 막힌다.
- **D02 줄이 겹치지 않게 한다.** lint 는 `lintOwnRules` 로 CheckRepo 의 D02·D03 을 뺀다. D05 는 그 표에 넣지 않는다 — lint 에 자기 D05 가 없으므로 CheckRepo 쪽을 그대로 낸다.
- 스튜디오 기준 첫 실행에서 `retired` 는 약 75건으로 볼 수 있다(덮임 73 + 무효만 2, 접힌 것은 빠지므로 그보다 적을 수 있다).
- **NLI 서버 확인** : 8092 서버는 `~/.aimemory/llm.toml` 의 `nli_url` 로 붙는다. 시작할 때 `/health` 를 본다.
- 구현이 끝나면 커밋을 묻기 전에 코드리뷰를 한 번 한다(인수인계 순서).
