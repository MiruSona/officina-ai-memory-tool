## 0. 결론 먼저

1. **원칙을 「LLM 0」에서 「검색·훅은 LLM 0, 그 밖은 값어치가 있을 때만 · 가능하면 로컬」로 고친다.** 판정·분류·근거 문장 고르기·검증은 **바깥 LLM 에 글자 하나로 묻고**(SemIf 방식 — 글을 안 만든다), 글 쓰기만 생성을 시킨다. 둘 다 **설정에 적은 주소의 바깥 LLM**(가능하면 로컬)이고, 주소가 없으면 그 기능만 건너뛴다. **`mem` 안에 새로 들어가는 모델은 없다.** 검색 지연·훅·결정적 검색은 지금 그대로다.
2. **자동으로 넣은 기억은 보류 없이 바로 쓴다 (사용자 결정).** 그래서 무게가 두 자리로 옮겨 간다 — **넣는 순간 기계로 막는 「자동 관문」**(근거 문장이 대화 기록에 글자 그대로 있나 · 숫자·경로 대조 · LLM 주소가 있을 때 근거 지지 판정 · 합치기 금지 · 개수 상한)과 **나중에 한꺼번에 되돌리는 길**(`origin` 표시로 골라 보류로 되돌림 — 지우지 않음).
3. **A 알아서 쌓기의 주 길은 「지금 도는 AI 에게 시키기」다** (추가 모델 0). `Stop` 훅이 세션당 한두 번 「남길 것 정리해 `mem add`」를 알린다. 로컬 모델 길은 **알림을 못 받은 세션(압축·갑작스런 종료)** 을 나중에 건지는 뒷길이다.
4. **B 모음 기억은 md 한 파일(새 종류 `observation`)** · 묶음은 코드가 정하고 생성 LLM 은 글만 · 다시 쓰기는 delta 연산(안 건드린 줄은 글자 그대로). **C 뜻으로 찾기는 넣을 때 「찾을 말」(`keys`)을 같이 적기**가 토큰 0 으로 가장 싸다. `mem` 이 검색 때 LLM 을 부르는 길은 안 한다.
5. **차례** : ① A1 `Stop` 알림 + 자동 관문 + 되돌리기 → ② C1 `keys` (cross-encoder 재순위는 미룸 — 4-5) → ③ B1 모음 그릇 + 코드 조립 카드(LLM 0) → ④ K 바깥 LLM 판정 붙이기 → ⑤ B2 생성 LLM 글 → ⑥ A2 로컬 모델 큐 처리. **스튜디오와 게임 저장소에 같이 켠다 (사용자 결정)** — 저장소마다 scope·종류표를 그 저장소 `vocab.toml` 에서 읽는다 (7절).

### 1-3. 판정과 생성의 몫 나누기 (U2 · U5)

**생각** : 판정·고르기는 답이 「예/아니오 · 글자 하나 · 점수」라 **지어낼 수가 없다**(입력에 없는 글을 못 낸다). 지어낼 수 있는 일(글 쓰기)만 생성에 남기면 날조가 들어올 자리가 그만큼 준다.
**실측 뒤 고친 점** : 초안은 판정을 「`mem` 안에 까는 작은 분류 모델」에 맡기려 했다. 재 보니 **따로 들일 분류 모델이 없다.** 판정도 생성과 같은 바깥 LLM 에 묻되, 글을 쓰게 하지 않고 **첫 글자 하나의 확률만 읽는다** (SemIf 방식).

**판정 방식 — SemIf (정함)**

| 항목 | 정함 | 근거 |
| --- | --- | --- |
| 묻는 꼴 | 선택지를 **영문 글자(A/B/C…)** 로 주고 글자 하나로 답하게 한다. 선택지 설명은 한국어여도 된다 | 한글 글자(가/나/다)는 영문보다 나은 갈래가 없고, 7지선다 뒷글자가 위 20개 확률 밖으로 빠졌다 [실측] |
| 요청 | **생각 끔 · `max_tokens 1` · 첫 토큰 확률 읽기**(위 20개). 글자 토큰은 **정확 일치**로 모은다 | 생각을 안 끄면 첫 토큰이 생각 글이라 통째로 안 된다 · 쌍둥이 글자(「 A」)를 합쳐도 답이 바뀐 요청 0 [실측] |

### 2-2. 훅 셋 — 무엇을 하나 (전부 LLM 0)

공식 문서로 확인한 이벤트 성질 [문서 `code.claude.com/docs/en/hooks`, 2026-10-05] :

| 이벤트 | 막기 | 글 넣기 | 시간 | 우리 쓰임 |
| --- | --- | --- | --- | --- |
| `Stop` | 됨 (`decision: block`) | **됨** (`hookSpecificOutput.additionalContext`) · `stop_hook_active` 로 되풀이 막기 · `last_assistant_message` 받음 | 기본 600초 | **(가) 알림** |
| `PreCompact` | 됨 | **안 됨** | 600초 | 「이 세션이 압축된다」 표만 남김 |
| `SessionEnd` | 안 됨 | 안 됨 | **모든 훅 합쳐 1.5초** | 「이 세션이 끝났다」 표만 남김 |

**`mem hook stop` — 알림 조건 (전부 맞아야 낸다)**

1. `stop_hook_active` 가 거짓이다.
2. 이 세션에서 **일한 흔적이 문턱을 넘었다** — 지난 오프셋 뒤로 파일 고침(Edit·Write 류) 도구 호출 ≥ `[retain] nudge_edits`(예 5) **또는** 사용자 턴 ≥ `nudge_turns`(예 8). 최근 14일 세션 24개 중 절반은 32KB~320KB 짧은 판이라 [실측] 문턱 없이 내면 대부분 잡음이다. 게임 저장소의 그림·소리 일은 Bash 로 툴을 부르는 일이 많아 Edit 수가 적을 수 있다 → 턴 문턱이 받친다 (7절).
3. 마지막 알림 뒤로 같은 문턱만큼 또 일했다 (세션당 많아야 `nudge_max`, 예 2번).
4. 마지막 알림 뒤로 이 세션의 `mem add` 가 아직 없다 (`Memory/local/` 명령 기록).
5. 자식 세션이 아니다 (`MEM_RETAIN_CHILD=1` 이 켜진 프로세스면 침묵).

상태는 `Memory/local/retain-state.json` (git 밖) — `session_id → {transcript_path, 오프셋, 알림 수, 마지막 알림 때}`. `session_id` 가 세션 안에서 같다는 것은 실측됐다 (mem `20261001-a370fae4`).
**대화 기록은 지난 오프셋 뒤만 읽는다** — 큰 파일(5.7MB [실측])을 매 턴 통째로 읽지 않는다.
**`transcript_path` 를 여기 적어 두는 것이 자동 관문의 열쇠다** — 나중에 `mem add --origin stop` 이 그 세션 기록을 찾아 근거를 대조한다.

**알림 글 (자료 표시 바깥 · 6줄 안쪽)** — 꼴만 정하고 문구는 구현 때 다듬는다. scope 목록은 **그 저장소 `vocab.toml`** 에서 읽어 한 줄로 붙인다 (`subagent-start` 와 같은 방식).

```text
[mem] 이 세션에서 고친 것이 쌓였다. 다음 세션에 쓸모 있는 것만 골라 남겨라.
- 정한 것 → --type decision · 밟은 함정 → caution · 남은 일 → todo
- 코드·git 으로 알 수 있는 것, 이번 세션만 쓸 메모는 넣지 않는다
- 넣을 때 --origin stop 을 붙인다. 남길 것이 없으면 「남길 것 없음」 한 줄로 끝낸다
- 쓸 수 있는 scope : <vocab.toml 목록>
```

- 「남길 것 없음」을 허락하는 줄이 중요하다 — 없으면 억지 기억을 만든다 [추정].
- 알림이 지시 꼴인 것은 훅이 내는 글이라서다. 기억 블록은 여전히 자료 표시 안에만 있다(I3).

**`PreCompact` · `SessionEnd` — 표만 남김.** `Memory/local/retain-queue/<session_id 앞 8자>.json` 에 `{session_id, transcript_path, 까닭(compact|end), 때, 오프셋, covered}`. 100ms 안쪽이라 1.5초 예산에 맞는다 [추정]. 그 세션에서 `--origin stop` 기억이 이미 있으면 `covered: true` — A2 가 건너뛴다. 큐는 `[retain] queue_days`(예 14) 지나면 닫는다 — 모델이 없는 기계에서 끝없이 쌓이지 않게.

### 2-3. 자동 관문 — 넣는 순간 기계로 막는다 (U3)

- **(가)에 R1·R3 을 필수로 안 둔 까닭** : (가)는 지금 AI 가 쓰고, 그 AI 는 대화를 요약해서 말한다 — 글자 그대로 따오라 하면 기억 글이 대화체로 망가진다 [추정]. 대신 R2(숫자·경로)는 필수로 둔다.
- **세션 기록을 못 찾으면** (상태 파일에 없음 · 파일 지워짐) : (가)는 R2 를 저장소 파일 대조로만 하고 경고 한 줄, (나)는 거절.
- **LLM 주소가 없으면** R3 는 안 돌고 규칙 관문(R1·R2·R4~R8)만 돈다. (가)는 그대로 들어오고, (나)는 켜지지 않는다. **주소는 있는데 서버가 안 닿으면** (가)는 R3 를 건너뛰고 경고 한 줄, (나)는 그 세션을 큐에 남겨 다음에 다시 한다.
- **판정 하나만 믿지 않는다 — 규칙 관문과 겹쳐 쓴다.** 실측에서 「보고↔diff」 갈래는 문턱 0.5 에서 「맞음」 쪽으로 쏠렸고(어긋난 짝에도 0.7~0.98), 「고쳤다고 했는데 diff 에 그 줄이 없는」 거짓 완료를 **모든 판이 놓쳤다** [실측]. 「없는 것을 있다고 함」은 판정보다 R1(글자 그대로 근거)·R2(조각 대조) 같은 규칙이 잘 잡는 꼴이다.
- 관문은 **다시 잴 수 있어야** 한다. 그런데 SemIf 판정은 같은 입력을 두 번 물으면 확률이 최대 0.23 달라졌다(답은 같았음 · 원인 미확인) [실측]. 그래서 **판정 결과를 파일로 남기고 같은 입력은 다시 묻지 않는다** — `Memory/local/judge/`(git 밖)에 (입력 해시 · 프로필 · 고른 글자 · 확률)를 쌓고, 같은 입력이 오면 그 파일을 읽는다. 다시 잴 때도 이 파일을 쓴다. 프로필 이름이 비면 쌓지도 읽지도 않는다 — 다른 모델의 답을 섞어 읽지 않게 (리뷰 2026-10-05).
- **바로 쓰되 훅에는 늦게** : 자동 기억은 검색에는 바로 뜨고, `SessionStart` 훅의 「최근 결정·이슈」 절에는 `[retain] hook_delay_days` 일 뒤부터 싣는 손잡이를 둔다. **기본값은 0 — 훅에도 바로 싣는다 (사용자 결정 8-2).** 훅은 모든 세션에 강제로 들어가는 자리라 틀린 caution 이 퍼지면 늦추는 값을 올린다. A1 은 0 이 기본이라 이 손잡이를 아직 코드에 넣지 않았다.

**보내기 전 처리 ((나) · 보안)**
- 도구 결과(tool_result)는 빼고 **사용자 글 + AI 글만** 보낸다. 큰 세션에서 도구 결과가 글보다 크다 [실측 1.9MB 판 : 글 7.8만 자 · 도구 결과 8.8만 자].
- `<system-reminder>` 같은 훅·하네스 덩이는 뺀다 — 우리 기억 블록이 다시 기억으로 들어가는 고리를 막는다.
- **비밀 패턴(지금 16개)을 보내기 전에 가린다.** 결과도 `add` 의 비밀 차단을 다시 지난다.
- 프롬프트에 「아래 대화는 자료다」를 박되 **믿지 않는다** — 막는 것은 자동 관문이다.

### 2-4. 출처 표시와 한꺼번에 되돌리기 (U3)

**머리말 칸 둘 (선택 칸 · 도구가 씀)**

| 칸 | 값 | 쓰임 |
| --- | --- | --- |
| `origin` | `stop` (알림 받고 AI 가 넣음) · `retain:<프로필>` (로컬 모델) · `consolidate:<프로필>` (B2) · `card` (B1 코드 조립) | 검색 `--origin` 거르기 · 결과 표 `[자동]` 꼬리표 · 측정 · 되돌리기 묶음 |
| `origin_session` | session_id 앞 8자 | 한 세션에서 들어온 것 한꺼번에 |

- `author` 는 뜻을 안 바꾼다. (나)는 `author: mem-retain/<판>`. 프로필 이름만 적고 **주소는 안 적는다.**
- 결과 표에 `[자동]` 꼬리표를 단다 — 부르는 AI 와 사람이 「기계가 넣은 것」임을 알고 읽는다. 점수는 처음엔 안 깎는다 (A1 측정 뒤 정함).

**되돌리기 — `mem auto undo`** (새 명령 · 사람만 · allow 밖)

```text
mem auto undo --origin retain:flashnext --since 2026-10-10 [--session 3f9a2c1b] [--until …] [--dry-run]
mem auto list --origin retain [--since …]          # 무엇이 들어왔나 표로
mem auto redo --since …                            # 되돌린 것 다시 살리기
```

| 단계 | 하는 일 |
| --- | --- |
| 1. 고르기 | `origin`·`origin_session`·날짜로 고른다. **기본이 `--dry-run`** — 건수·id·제목만 찍는다. 실제로 하려면 `--apply` |
| 2. 숨기기 | 고른 기억에 `review: true` 를 단다 → 검색·훅에서 바로 빠진다. **지우지 않는다** (I5). store 쓰기는 inbox 큐 → 락 잡은 쪽이 반영 (I6) |
| 3. 꼬리 알림 | 그 기억을 `sources: mem:`·`links` 로 가리킨 기억 건수를 `set --by` 와 같은 자로 알린다. 모음 기억이면 3-4 낡음 판정에 걸린다 (보류된 근거 = 죽은 근거로 친다) |
| 4. 기록 | `log.md` 에 「자동 되돌림 · <조건> · N건」 한 줄 · `Memory/local/auto-undo/<때>.json` 에 id 목록 (redo 용) |
| 5. 그 뒤 | 하나씩 볼 사람은 `mem review --kind held --origin …` → 살릴 것은 `--promote`, 버릴 것은 `mem review --reject <id>`(archive 로 접음 · 새 명령) |

- **md 라서 `git revert` 도 그대로 듣는다** — 자동 기억이 든 커밋을 통째로 되돌릴 수 있다. 다만 같은 커밋에 사람 기억이 섞이면 위 명령이 낫다.
- **R4(합치기 금지) 가 되돌리기를 가능하게 한다** — 자동 글이 사람 기억 안에 붙어 있으면 파일 단위로 못 되돌린다.

### 2-5. 겉모양

| 명령 | 뜻 |
| --- | --- |
| `mem hook stop` | 2-2 알림. 조건 안 맞으면 침묵 · 종료 0 |
| `mem hook pre-compact` · `mem hook session-end` | 큐 표만 남김 |

`mem.toml [retain]` (git 추적 · 팀 공유) : `nudge` · `nudge_edits` · `nudge_turns` · `nudge_max` · `per_session` · `per_day` · `hook_delay_days` · `queue_days`.
`~/.aimemory/llm.toml` (git 밖 · 개인) : 바깥 LLM 주소 · 판정용·생성용 프로필 이름 · 키. **없으면 LLM 을 쓰는 기능만 건너뛴다** — `add` 관문은 R3 없이 규칙만, `retain`·`consolidate --llm` 은 「LLM 주소 없음 — 건너뜀」 한 줄을 찍고 종료 `0`. 따로 까는 분류 모델은 없다 (`mem install --classifier` 는 만들지 않는다).

**생성 LLM 요청 꼴 (A2 둘째 단)** — 판정 단이 고른 조각 묶음(근거 후보)만 넣는다.

### 3-1. 왜 · 우리 약점과 잇기

| 약점 | 지금 값 | 모음 기억이 하는 일 | 기대 [추정] |
| --- | --- | --- | --- |
| multisession (답이 여러 기억에 흩어짐) | 0.438 (08-24 · 16건) · v3 「규모가 커지면 어디가 느려지나」 둘째 정답이 후보에도 없음 | 흩어진 N건을 한 문서로 — 한 번 맞으면 근거 id 가 같이 보인다 | 오를 수 있다. 단 **eval 자를 안 바꾸면 안 보인다** (3-7) |
| update (바뀐 결정) | 0.800 · 놓친 2건은 덮음 사슬이 아니라 순위 문제 (후보넓히기 4-2) | 덮음 사슬 카드 「예전 X → 지금 Y」 | **그 2건에는 안 닿는다.** 「옛 말로 물으면 새 결정을 못 찾는」 꼴에만 듣는다 |

### 3-2. 저장 꼴 — md 한 파일, 새 종류 `observation`

**왜 원본인가** : 생성 LLM 글은 다시 돌리면 다르게 나온다. 다시 만들 수 없는 것은 파생물이 아니다(I2). 또 사람이 PR 에서 본다. 그래서 `Memory/store/` 의 md 다.
B1 코드 조립 카드는 결정적이라 파생물로 둘 수도 있지만, **두 판의 겉모양을 하나로** 하려고 같은 그릇을 쓴다.

```yaml
---
id: 20261012-5c1e77a0
type: observation
title: 훅 지연은 규모보다 색인 따라잡기 탓
summary: 훅이 느려지는 자리는 기억 수가 아니라 색인 따라잡기다. 시간 예산으로 잘라 1초 안을 지킨다
tags: [hook, perf]
scope: aimemorytool
date: 2026-10-12
author: mem-consolidate/0.4.0
origin: consolidate:flashnext      # 코드 조립이면 card
sources: [mem:20260824-38f16960, mem:20260901-cbe301b4, mem:20260830-7cc2714a]
basis_hash: 9f3a1c0e               # 근거들 본문 해시를 이은 것의 앞 8자
rev: 2
---
1. 훅 시간은 기억 수보다 색인 따라잡기에 달려 있다. [mem:20260824-38f16960]
2. 따라잡기에 시간 예산을 두어 1초 안을 지킨다. [mem:20260901-cbe301b4]
3. 예산을 줄이면 잘림 안내가 붙어 블록이 오히려 커진다. [mem:20260830-7cc2714a]
```

| 칸 | 뜻 |
| --- | --- |
| `sources` | **근거 기억 id 목록.** 기존 `mem:` 칸 → `show` 의 「나를 근거로 삼은 기억」 · `review --kind basis` · `set --by` 뒤 알림이 **코드 0줄로** 따라온다 |
| 근거 수 | `sources` 의 `mem:` 개수. 따로 안 적는다 |
| `basis_hash` | 쓸 때 근거 본문의 해시. 근거가 **죽지 않고 고쳐졌을 때**를 잡는다 |
| `rev` | 다시 쓴 횟수. 이력 본문은 기존 「본문 교체 → `archive/` 접기」 + git |
| 본문 | **번호 줄만.** 줄마다 끝에 `[mem:<id>]` 근거 하나 이상. 번호가 delta 연산의 블록 id |

**종류 `observation` 의 취급 (`[type.observation]` 기본값)** : `sources = required` · `body = numbered` · `gate = false` · `half_life = none` · `gc_keep = true` · `hook = "요지"` · `search_bonus = false`.
**DUP 예외** : 자기 근거와의 닮음은 DUP 으로 안 친다. 다른 모음 기억과의 닮음은 그대로 친다.
**U3 를 B 에도 같이 읽었다** — 모음 기억도 보류 없이 바로 쓰고, 3-6 검증표가 관문 노릇을 한다. 이 읽기가 다르면 B2 만 보류로 돌리면 된다 (칸 하나).

### 3-3. 무엇을 묶나 — 코드가 정한다

**생성 LLM 에게 묶음을 맡기지 않는다.** 묶음을 맡기면 818건을 다 보여 줘야 하고(입력 10⁵ 토큰), 「왜 이 셋이 묶였나」를 사람이 다시 못 짚는다.

| 묶음 씨앗 | 규칙 | 겨누는 것 |
| --- | --- | --- |
| ① 덮음 사슬 | `superseded_by` 로 이어진 기억 2건 이상 | update |
| ② 링크 무리 | 같은 scope 안에서 `links` ∪ `auto_links` 연결 요소, 3~12건 | multisession |
| ③ 의미 무리 | 같은 scope · 같은 종류 계열 · 코사인 ≥ 문턱인 무리 3~8건 (임베딩 설치 때만). 경계 쌍은 바깥 LLM 판정(SemIf)이 「같은 주제인가」를 본다 (선택 · LLM 주소가 있을 때 · 안 잼) | multisession · paraphrase |

- 자동 기억(`origin` 있음)은 **다른 근거가 둘 이상 같이 있을 때만** 무리에 든다 — 자동 기억끼리만 묶여 기계 글이 기계 글을 근거로 삼는 고리를 막는다.
- 이미 모음 기억이 있는 무리는 새로 안 만들고 다시 쓰기 후보로 돈다.
- `mem consolidate --plan` 은 무리 목록만 찍는다 — 처음 몇 판은 사람이 보고 고른다.

### 3-4. 언제 다시 쓰나 — delta 연산

**낡음 판정 (색인 때 · LLM 0)** : ① 근거 하나가 죽었다(`superseded_by`·`invalid_at` · **되돌려져 보류됨**) ② `basis_hash` 가 지금 근거 본문과 다르다 ③ 같은 무리 규칙으로 새 구성원이 생겼다.
낡은 모음은 `review --kind stale` 에 오고, `consolidate` 가 다시 쓸 후보로 잡는다. **스스로 다시 쓰지 않는다** — 사람이 부르거나 정해 둔 배치(쉴 때)가 부른다.

**delta 연산 — 생성 LLM 이 내는 것은 이것뿐이다** (hindsight `engine/reflect/delta_ops.py` 와 같은 생각 · 조사 3-3).

```json
{"ops":[
  {"op":"replace","n":2,"text":"…","cites":["mem:20261010-aa11bb22"]},
```

**코드가 하는 일**
1. 꼴 검사 — 틀리면 통째로 거절하고 한 번만 다시 묻는다. 두 번 틀리면 그 무리는 건너뛴다.
2. 없는 줄 번호 · 무리 밖 `cites` 를 가리키는 연산은 버린다.
3. **안 건드린 줄은 글자 그대로 복사한다.** 연산 0개 = 문서 그대로 → drift 가 구조적으로 없다.
4. 새·바뀐 줄만 3-6 검증표에 건다. 걸린 줄의 연산은 버린다 (나머지 연산은 산다).
5. 번호를 다시 매기고 `rev` +1 · `basis_hash` 새로.
6. 옛 본문은 `archive/` 로 접는다 (I5).

처음 만들 때도 같은 꼴이다 — 빈 문서에 `insert_after 0` 연산들.

| 기본 | **`mix = false` (2026-10-05 사용자 결정 · 3차 판).** 1차 판은 ② (fresh-A +0) ③ (밀림 2 = 살아남 2) 미달. 2차 판은 ③ ④ ⑤ 는 넘고(fresh-B 밀림 0) ① (v3 +2) ② (fresh-B +2) 를 1건씩 못 넘었다. 한때 0.58 로 켰으나 헛답이 늘어(probe 15 → 18/29), 바닥 0.60 으로 조여 다시 쟀다 — 그래도 probe 15 → 16/29 · fresh-B 답 없음 abstain 2 → 0/9 라 껐다 (측정 문서 9절). 켜려면 `mix = true` (바닥 0.58 · 뜻 순위 3). 모델이 없으면 섞기가 안 돈다 |

**다시 켤 조건** : 2차 판으로 「낱말 상위 답이 밀린다」는 흠은 고쳤다(fresh-B 밀림 0). 남은 흠은 **오르는 폭이 작다**(+2)는 것과 헛답(+2~3)이다. 바깥 천장(측정 7-1)으로 보면 몸통을 키워도 처음 보는 질문의 순수 뜻 r@5 는 거의 안 오른다(fresh-A ko-v2 17 · e5-base 18 · bge-m3 17 /26). 그래서 몸통 교체만으로 켤 근거는 없고, 헛답을 막는 관문(뜻 답 전용 문턱 학습 등)과 같이 다시 잴 때 켠다. 판정에는 새 눈가림 셋을 만든다 (fresh-B 는 한 번 썼다).

- **A1 이 맨 앞인 까닭** : 토큰 0 이고, 자동 기억을 바로 쓰기로 했으니(U3) **관문과 되돌리기를 첫 자동 기억보다 먼저** 깔아야 한다. 사용자가 말한 ① 「어느 정도는 알아서 쌓기」의 대부분이 이것으로 된다 [추정].
- **K 를 B2·A2 앞에 둔 까닭** : 생성 모델이 쓴 글이 바로 쓰이므로, 그것을 막는 판정이 먼저 있어야 한다. 판정 방식은 실측으로 정했다(1-3). 다만 그 실측은 손으로 만든 한국어 50문항(갈래당 12~14)이라 쉬운 쪽이고, 실제 대화 조각·긴 입력의 정확도와 지연은 안 쟀다 — 그래서 K 의 통과선이 「실제 자료로 다시 잰다」다.
- **B1 을 B2 앞에** : 생성 글이 카드보다 낫다는 것을 잴 기준판이 있어야 한다. 카드로 충분하면 B2 는 안 한다.
- **A2 가 맨 뒤** : A1 로 놓친 세션이 얼마나 되는지 알아야 값어치를 잰다. 적으면 안 한다.
- 로컬 생성 단계(B2·A2)는 스튜디오 규칙대로 **한 번에 한 판 · 실측 중엔 다른 세션이 안 쓰기 · 프로필 묶어 처리(전환 20~40초)**. `consolidate`·`retain` 은 순차로만 돈다.
- C1 은 `internal/search`·`internal/index` 를 만진다. K 는 바깥 LLM 부르기(새 패키지)와 `add` 관문을 만지고 `internal/embed` 는 안 건드린다 — 둘을 나란히 해도 패키지가 겹치지 않는다 [추정 — 구현 계획 때 다시 본다].

## 7. 게임 저장소에도 켜기 (U4)

### 7-1. 저장소마다 다른 것

| 무엇 | 스튜디오 | 게임 저장소 | 설계가 하는 일 |
| --- | --- | --- | --- |
| scope | 툴 이름 열두 개 (`aimemorytool` …) | `game` · `design` · `art` · `sound` · `code` | **알림 글·자동 관문·`retain` 프롬프트가 scope 목록을 그 저장소 `vocab.toml` 에서 읽는다.** 코드에 scope 를 박지 않는다. (나)의 후보 scope 가 목록 밖이면 R8 처럼 거절 |
| 종류표 | 기본 7 + `observation` | 그 저장소 `vocab.toml [type.*]` 덮어쓰기 | `observation` 기본값은 코드에, 저장소가 덮어쓸 수 있다. 알림 글의 「정한 것 → decision」 줄도 종류표의 `label` 에서 만든다 |
| 일의 꼴 | 코드·문서 고침 (Edit 많음) | 그림·소리 툴을 Bash 로 부름 · 기획 문서 | `nudge_turns` 가 받친다. 문턱은 저장소 `mem.toml [retain]` 에서 따로 |
| 골든셋 | 있음 (v3 81건) | 없음 | 게임 저장소는 **잡음률·되돌림률만** 잰다. 검색 품질 자는 스튜디오에서만 |
| 로컬 모델 | 이 기계엔 있음 | 다른 팀원 기계엔 없을 수 있음 | 모델 단계는 개인 설정이 있는 기계에서만 켜짐 |
| 기억 공개 | 스튜디오 비공개 | 게임 저장소는 공개 예정 | **자동 기억도 git 에 들어가 공개될 수 있다** → R8 비밀 차단 그대로 + 공개 전 `mem auto list` 로 한 번 훑기 |

### 7-2. 켜는 절차 (사람 · 한 번)

1. **exe 바꾸기** — 스튜디오에서 새 판 빌드 → `~/.aimemory/bin/mem.exe` 교체 (기계마다 한 번 · 두 저장소가 같은 exe 를 쓴다).
2. **스튜디오에 켜기** — `mem init --retain` (새 인자) 이 `.claude/settings.json` 에 `Stop`·`PreCompact`·`SessionEnd` 훅 셋을 **병합**하고 `mem.toml` 에 `[retain]` 절 기본값을 넣는다. `.claude/` 는 AI 가 못 고치는 보호 경로라 **사람이 돌리고 커밋**한다 (`훅연동.md` 2절과 같은 규칙).
3. **확인** — `mem status --doctor` 가 훅 넷(`SessionStart`·`SubagentStart`·`Stop`·`PreCompact`/`SessionEnd`)을 한 줄씩 보고 · `mem hook stop --dry-run < 시험입력` 이 알림 글을 찍는지.
4. **게임 저장소에 켜기** — 게임 저장소 뿌리에서 같은 `mem init --retain`. 그 저장소의 `vocab.toml` scope 다섯이 알림 글에 나오는지 3번처럼 본다. 커밋은 그 저장소 규칙대로(사용자 승인).
5. **(선택) 모델 단계** — 바깥 LLM 서버가 닿는 기계에서만 `~/.aimemory/llm.toml` 작성. 따로 까는 모델은 없다. 저장소마다 다른 설정이 아니라 **기계 설정**이다.
6. **끄기** — `mem.toml [retain] nudge = false` 한 줄 (훅은 붙어 있어도 침묵) 또는 `mem init --retain --undo`.

- `mem init` 이 훅을 병합할 때 **백업 + 재대조 후에만** 쓴다 (`훅연동.md` 1절 규칙 그대로).
- 게임 저장소는 `Tools/` 서브모듈과 `setup.ps1` 을 쓰지만, 이 절차는 **전역 `mem` 과 `mem init` 만** 쓴다 — 서브모듈 갱신이 없다.
