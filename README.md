# AIMemoryTool

AI 에이전트가 쓰는 **독립된 기억 저장소 툴**이다.
`mem` 이라는 Go CLI 하나로 기억을 걸러 넣고 · 색인하고 · 찾고 · 정리한다. **LLM 을 부르지 않는다(토큰 0).**
**MCP 없음 · 서버·데몬 없음 · 스킬 없음.** Claude Code 와는 `SessionStart` 훅 1개 + Bash 로 부르는 CLI 로만 붙는다.

기억 원본은 프로젝트 안 `Memory/store/` 의 작은 Markdown 파일들이고,
`Memory/index.db`(SQLite FTS5)와 `Memory/vectors.bin`(문서 벡터)은 **지워도 되는 파생물**이다 — `mem index --full` 로 완전히 복구된다.

> **상태 : 4회차(v0.4) 2차 동결 + 사용자 실측 끝 — 2026-08-24.** 검색+문서 품질을 다듬은 작은 회차. 명령 16개 · 규칙 62개 · `internal/` 20패키지.
> **2026-09-03 에 폴더를 정리했다** — 회차 폴더(`v0.1`~`v0.4`)와 옛 뿌리 코드를 걷어내고 **v0.4 를 이 폴더 바로 아래로 올렸다.**
> 모듈 경로도 분리될 공개 저장소 이름(`github.com/mirusona/officina-ai-memory-tool`)으로 미리 바꿨다.
> **목표 판정 요약** : G2·G3·G6②③④ **합격**, **G5 합격**(진짜 세션에서 T1·T2·T3·T18 사용자 실측 넷 다 통과, `Docs/History/2026-08-24-사용자실측.md`), G1·G4·G6① **미달**(천장을 실측으로 확인 — 자를 옮기지 않았다).
> **수치(색인 시간 · 검색 지연 · DB 부피 · recall · 훅 시간 · G1~G6 판정)는 `Docs/History/2026-08-24-최종측정.md` 를 본다.**
> **지금 상태와 남은 것은 `Docs/Todo/진행상황.md`, 재는 법은 `Docs/Guide/측정절차.md` 다.**
> 이 README 는 수치를 따로 적지 않는다 — 두 곳에 적으면 반드시 어긋난다.

**우선순위는 문서의 품질이 검색의 품질보다 앞이다.** 아무리 잘 찾아도 들어 있는 것이 엉망이면 답이 엉망이다.

## 설치 (세 걸음)

**받는 방식은 「소스를 clone 해서 각자 빌드」다** (결정 20). 미리 빌드한 exe 는 GitHub Release 에 덤으로만 둔다.
내 PC 에서 빌드하면 SmartScreen 평판·Mark-of-the-Web 문제가 통째로 사라지고, AI 에이전트가 `go build` 를 직접 돌릴 수 있다.

```powershell
# 1. 받는다
git clone <저장소> ; cd <저장소>

# 2. 빌드한다 — Go 1.26 이상. C 컴파일러가 필요 없다 (CGO_ENABLED=0)
.\build.ps1
#   또는 손으로 :  $env:CGO_ENABLED="0"; go build -trimpath -ldflags="-s -w" -o bin\mem.exe .\cmd\mem

# 3. 기계에 한 번 깐다 — exe 복사 · PATH · 그리고 의미 검색 모델까지
bin\mem.exe install                # 계획 표만 보여준다. 아무것도 안 고친다
bin\mem.exe install --apply        # 실제로 적용한다 (PATH 는 새 터미널부터)
```

`build.ps1 -Install` 로 2·3 을 한 번에 해도 된다. 인터넷이 없으면 `build.ps1 -Install -Bundle <꾸러미폴더>`.

### 설치가 받는 것

| 무엇 | 어디에 | 크기 |
| --- | --- | --- |
| `mem.exe` | `%USERPROFILE%\.aimemory\bin\` | — |
| `onnxruntime.dll` | `%USERPROFILE%\.aimemory\bin\` (exe 옆 · **절대경로로 로드**한다) | — |
| 모델 `model_int8.onnx` + `tokenizer.json` | `%USERPROFILE%\.aimemory\models\` | — |

- **모델은 기본으로 받는다.** 낱말 검색만 쓰려면 `mem install --no-embed --apply`.
- **인터넷이 없거나 못 받으면 설치는 그대로 성공하고 낱말 모드로 떨어진다.** 어느 명령도 모델이 없다고 실패하지 않는다(결정 16).
- 받은 파일은 **exe 안에 박아 둔 SHA-256** 으로 검사한 뒤에만 쓴다. 안 맞으면 지우고 낱말 모드다.
- **모델을 GitHub Release 에 올리기 전까지는 `--bundle <폴더>` 로만 깐다.** 온라인 받기 주소(`embed.ReleaseBase`)가 아직 비어 있다.
- 지금 무엇이 깔렸고 어느 모드인지는 `mem install --check` · `mem status --embed`.
- 쓰는 경로는 **`Memory/` · `.claude/settings.json` · `~/.aimemory/` 셋뿐**이다. 새 경로를 안 만든다.
- 자동으로 내려받지 않고, DLL 을 임시 폴더에 푸는 짓도 안 한다 — 그건 악성코드가 하는 짓이라 EDR 이 잡는다.

## 첫 사용 (다섯 줄)

```powershell
cd <프로젝트>
mem init                                  # 저장소 뼈대 · 훅 · allow 규칙 · 규칙 블록을 붙인다
mem tags --add-scope unity-build          # 이 저장소의 이름(scope)을 한 번 정한다
mem add --type decision --scope unity-build --tags build,ci --title "…" --summary "…" --sources file:… --body "…"
mem index                                 # 큐를 승격하고 색인한다 (벡터도 여기서 만든다)
mem search 야간 빌드                      # 찾는다
```

`mem init --dry-run` 이 무엇이 어떻게 될지 표로 먼저 보여준다.
scope 를 정하기 전까지는 목록 밖 태그·scope 가 **경고로만** 뜨고, 정하는 순간부터 거절이다(「배우는 중」).

### 팀원 온보딩 3줄

```
1. 저장소를 clone 하고  ->  .\build.ps1 ; bin\mem.exe install --apply            (새 터미널을 연다)
2. 쓸 프로젝트를 git clone 한다              ->  훅과 Memory/ 는 이미 들어 있다
3. Claude Code 를 열고 폴더를 신뢰한다       ->  끝. 세션 시작에 기억이 뜬다
```

`.claude/settings.json` 의 훅과 `Memory/` 뼈대가 **git 에 커밋돼 있기 때문**이다. `mem init` 은 저장소를 처음 만드는 사람만 한 번 돌린다.
**3번을 빼먹으면 안 된다** — 훅은 신뢰 전에도 돌지만 `permissions.allow` 는 신뢰해야 살아서, 안 누르면 `mem` 호출마다 승인 창이 붙는다.

## 명령 16개

| 명령 | 하는 일 | v0.3 에서 늘어난 것 |
| --- | --- | --- |
| `install` | exe 를 `%USERPROFILE%\.aimemory\bin\` 에 복사하고 PATH 에 넣고 **모델·DLL 을 받는다**. 기계마다 한 번 | `--bundle <폴더>` · `--no-embed` · `--check` · `--model <이름>` |
| `init` | 이 프로젝트에 저장소를 붙인다 (뼈대·`mem.toml`·`vocab.toml`·`사용법.md`·`.gitignore`·훅·allow 규칙·규칙 블록). 여러 번 돌려도 안전 | — |
| `add` | 기억 한 건을 **관문에 걸고** 통과하면 쓰기 큐에 넣는다 | **`--hold`** (보류로 넣기) |
| `set` | 있는 기억의 도구 칸을 고친다. `--by` 로 결정을 덮고 `--body` 로 본문을 간다 | **`--link <id>`** (링크 하나 더하기. `--links` 는 통째 교체) |
| `search` | 찾는다. **질의가 없으면 조건 목록**만 준다. `--facet` · `--explain` | **`--include-held`** |
| `show` | id 로 본문을 꺼낸다. `--head` 로 앞부분만, `--from-archive` 로 접힌 원본도, `--raw` 는 원문 그대로 | — |
| `hook` | 훅 진입점. 사람이 직접 칠 일은 없다 | — |
| `index` | 큐를 승격하고 바뀐 파일만 색인한다. `--full` · `--clear-bad` · `--verify` | **`--json`** (한 줄 JSON) |
| `migrate` | 옛 규격(v0.1) 기억을 지금 규격으로 옮긴다. **`--dry-run` 이 기본** | **칸별 부분 이전** · 비밀정보 차단 시 **종료 코드 4** |
| `gc` | 오래된 기억의 본문을 접는다. **파일은 안 지운다.** `--fold` · `--restore` | 변경 없음 |
| `lint` | 문서 품질 검사. 규칙은 `add` 관문과 **같은 표**를 쓴다. `--fix` · `--rule` · `--synonym` | 규칙 넷 신설(아래) |
| `review` | **사람이 판정할 것만** 모아 보여준다 (만료·모순·낡음·값 있나·차가움·링크 후보·제목 없음) | **`--promote <id>`** — 보류 기억을 사람이 연다. **이 옵션만 allow 규칙 밖** |
| `tags` | 태그·scope 표준 목록을 손본다 (`--add` · `--add-scope` · `--alias` · `--rename` · `--check`) | **`--suggest`** (동의어·대표말 후보 제안 · 아무것도 안 고친다) |
| `eval` | 골든셋으로 **검색 품질**과 **문서 품질**(`--quality`)을 잰다. `--tune-dup` · `--golden` · `--repo` | **골든셋이 없으면 종료 코드 3** |
| `status` | 저장소 자리·건수·색인 건강. `--quality` · `--db` · `--doctor` · `--log` | **`--embed`** (지금 어느 모드인지 · 벡터 몇 건인지) |
| `help` | 한글 도움말. `mem help <명령>` 은 `mem <명령> --help` 와 같다 | — |

옵션은 `mem help <명령>` 으로 본다. 메시지는 전부 한글이다.
종료 코드는 **0 정상 · 1 사용법 잘못 · 2 검사 실패 · 3 저장소 없음 · 4 보안 차단 · 5 파일·DB 손상 · 6 락 실패** 다 (`hook` 만 늘 0).
**`mem eval` 은 골든셋 파일이 아예 없을 때도 3 이다** — 「잴 것이 없다」를 0(통과)으로 말하면 부르는 쪽이 속는다.
**모델이 없는 것은 오류가 아니다** — exit 0 · 낱말 모드다.

> 도움말 글(`mem help install` · `mem help status`)에 **`install` 의 새 옵션 넷과 `status --embed` 가 아직 안 적혀 있다.**
> 옵션은 코드에 다 있고 동작한다. 도움말 글 고치기는 다음 판 몫이다.

## v0.2 에서 바뀐 것

| 갈래 | 무엇이 바뀌었나 |
| --- | --- |
| **의미 검색(임베딩)** | 정적 표(`ko.bin`) 폐기 → **ONNX 모델 + `onnxruntime.dll`**(cgo 없는 purego 바인딩). 문서 벡터는 `add`·`index` 때 1회 계산해 `Memory/vectors.bin` 에 담고, 검색은 질의 한 줄만 인코딩한다. **벡터 파일이 있으면 저절로 켜진다** — `[embed] enabled` 는 이제 옛 정적 표 쪽 손잡이다 |
| **어느 모드인지 말한다** | 결과 머리에 **`[낱말]` / `[낱말+의미]`** 를 찍는다. 낱말 모드로 떨어지면 stderr 로 크게 알린다 |
| **대표말 통일(`norm`)** | 색인할 때 `[canon]` 표로 대표말을 치환한 `norm` 텍스트를 따로 만들어 DB 열(`fts_norm`)에 넣는다. **질의도 같은 함수를 탄다** — 「인덱싱」과 「색인」이 같은 글자가 된다. `[synonym]` 4번 칸은 외래어·1:다 용으로 그대로 남는다 |
| **자동 링크** | 기계가 이웃을 찾아 **`index.db` 의 `auto_links` 파생 표**에만 담는다(색인할 때마다 다시 만든다). **머리말 `links:` 는 사람이 적은 것만** 남는다. 검색 1-hop 은 둘의 합집합을 본다 |
| **검색 랭킹** | RRF 신호가 8 → **10** (`norm` 바이그램 · 임베딩 코사인). MMR(λ=0.7)로 겹치는 답을 눌러 묶고, 그 뒤에 1-hop 가산이 온다. **1-hop 은 가산으로만** — 링크 이웃이라는 이유로 새 문서를 후보에 안 넣는다 |
| **중복(DUP) 2단** | 1단(재현율)은 **문장 최대 정렬 지문 ∪ simhash 밴딩 ∪ 코사인**으로 후보를 넓게 뽑고, 2단(정밀도)은 **숫자·고유명사·경로·날짜가 어긋나는가**로 확정한다. 벡터 항은 **서로가 서로의 가장 가까운 하나(mutual top-1)** 일 때만 더한다 |
| **보류 저장** | **`mem add --hold`** — 머리말에 `review: true` 가 붙어 검색·훅에 안 뜬다. 사람이 `mem review --promote <id>` 로 연다. AI 가 **확신 없이 자동 저장할 때만** 쓴다 |
| **문서 품질 규칙** | **57 → 62.** `link-missing`(같은 주제인데 링크 없음) · `no-value`(확인 가능한 조각이 없다) · `stale-age`(종류별 나이) · `stale-conflict-pair`(뜻은 가깝고 결론이 어긋난다) · `tag-shape`(규격 밖 태그를 `index` 와 같은 자로 거절) |
| **관문 조이기** | `decision-gate`(C04)가 태그 겹침 1 → **2** + 요약 닮음 AND. `notation-drift`(C11)를 실제로 켰다(숫자 표기) |
| **allow 규칙** | 10 → **명령 11개 × Bash·PowerShell 두 꼴 = 22줄.** `Bash(mem review:*)` 를 **`Bash(mem review)` + `Bash(mem review --kind:*)`** 로 갈라 **`--promote` 만 승인 창**을 타게 했다. 옛 넓은 규칙은 `--undo` 가 같이 뺀다. (2026-08-24 사용자 실측으로 고침 : Windows 의 Claude Code 는 `Bash` 가 아니라 `PowerShell` 도구로 명령을 돌려 처음 넣은 11개가 하나도 안 맞았다. **Windows 는 `PowerShell(mem …)` 꼴을 같이 넣는다** — `mem init` 이 두 꼴을 다 넣도록 끝냈다(2026-08-24 뒷정리, `Docs/History/2026-08-24-뒷정리.md`)) |
| **색인 스키마** | 2 → **3.** `fts_norm`(contentless) · `memories.review` 열 · `auto_links` 표 신설. 판이 다르면 자동으로 전체 재색인 |
| **판 상수** | `SchemaVersion` 3 · `token.Version` `"6"` · `config.Tokenizer` 에 `+norm` · `eval.Version` 4 · `i18n.Version` `"0.3.0"` — **하나라도 안 올리면 옛 색인을 조용히 잘못 읽는다** |
| **배포** | 사내 zip → **GitHub 소스 + 각자 빌드**(`build.ps1`). exe 는 Release 에 덤. 모델·DLL 은 git 에 안 넣고 `mem install` 이 받는다 |
| **패키지** | `internal/link` 신설(자동 링크 후보). `internal/embed` 는 정적 표 → **ORT 경로로 새로 짬**(옛 코드는 `embed/static.go` 로 남겼다) |

**안 바꾼 것** : 훅(`SessionStart` 하나 · 예산 · 600ms 따라잡기) · 종료 코드 · 명령 개수 16 ·
합격선 G1~G6(자를 옮겨 점수를 벌지 않는다) · 시간 감쇠 표 · `gc --fold` · 골든셋 v2 80건 ·
불변조건 I1~I8 과 v0.2 가 값을 치르고 고친 자국 전부 (→ `Docs/Guide/지키는장치.md`).

- **머리말 칸을 넷으로 갈랐다** — 제목·메타·요약·본문을 각각 다른 열로 색인한다(`HeadField` · 색인 스키마 v4).

- **`relative-date`(상대 날짜 표현)를 거절로 올렸다** — 절대 날짜 없이 "어제"·"최근" 같은 표현만 쓴 기억을 막는다.
- **`lint` 오탐이 줄었다** — 실기억 206건 검사 시간이 17.90~18.59초 → 14.64~15.66초로 **약 −18%**.
- **`index --json`**(한 줄 JSON) · **`set --link`**(링크 하나 더하기) · 검색 결과 머리의 **`[낱말]`/`[낱말+의미]`** 모드 표기 · **`eval` 은 골든셋이 아예 없으면 종료 코드 3**을 새로 넣었다.
- **`migrate`** 가 큐에 쌓인 건수와 예상 시간을 미리 안내하고, `index.db` 에 남던 잔재(`inbox_seen`)를 정리했다.

## 문서 품질 장치

**넣기 전에 거른다.** v0.1 은 품질 장치를 `lint`(사후)에 몰아 뒀고, 실제 기억 206건은 「들어오고 나면 아무도 안 고친다」를 보여 줬다.

| 장치 | 무엇 |
| --- | --- |
| **`add` 관문** | 규칙(**62개**)을 저장 전에 돌린다. 거절이면 **저장이 안 되고** 다음에 칠 명령을 같이 준다. `--check` 는 관문만 돌리는 미리보기 |
| **`mem lint`** | 이미 들어간 것을 훑는다. **`add` 와 같은 검사 함수**를 쓴다 — 두 곳에 따로 적으면 반드시 어긋난다. `--fix` 는 되돌릴 수 있는 것만 |
| **`mem review`** | 도구가 판정 못 하는 것(만료·모순·낡음·값 있나·차가움·링크 후보·제목 없음)만 모아 **사람에게 넘긴다** |
| **`mem add --hold`** | **확신 없는 자동 저장**은 보류로 넣는다. 머리말에 `review: true` 가 붙어 검색·훅에 안 뜨고, 사람이 `mem review --promote <id>` 로 연다 (결정 6) |
| **`mem eval --quality`** | 규칙이 **실제로 듣는지** 잰다. 규칙마다 정밀도·재현율을 내고 **정밀도 0.80 미만이면 자동으로 경고로 내리고 0.60 미만이면 끈다** |
| **`mem status --quality`** | 저장소 통계 S01~S06 — 근거 붙은 비율 · 링크 밀도 · 표준 밖 태그 · 기억당 경고 · 거절률 · 최근 결함률 |

| 등급 | 하는 일 |
| --- | --- |
| 거절 | 저장을 막는다 (종료 코드 2, 보안이면 4) |
| 경고 | **넣되 알린다.** 경고가 뜨고 id 가 찍혔으면 들어간 것이다 |
| 후보 | 사람이 판정할 자리만 좁힌다 (`mem review`) |

**새 관문 넷도 v0.2 관문 규칙 셋을 그대로 탄다** — ① 거절할 때 **무슨 규칙·어느 기억·다음에 칠 실제 명령** 셋을 말한다
② 거절도 `log.md` 에 남긴다 ③ 정밀도 0.80 미만이면 자동 경고 강등, 0.60 미만이면 끈다.

### 무엇을 안 넣나

**이 규칙이 gc 보다 앞에 온다.** 안 들어온 건 정리할 필요가 없다.

- 코드를 보면 아는 것 (폴더 구조·의존성·함수 이름) — git 이 안다
- 이번 세션에만 쓸 임시 메모 — 다음 세션에 쓸모가 없으면 기억이 아니다
- 대화 기록 전문·긴 코드 조각 — `파일:줄` 포인터로 대신한다
- 비밀값·개인정보 — **자동으로 막힌다** (종료 코드 4)
- 이미 있는 기억과 같은 얘기 — 중복 검사가 기본으로 켜져 있다
- 「~해라」 꼴 지시문 — 기억은 자료지 지시가 아니다

**넣는 기준 한 줄** : *코드에서도 규칙 문서에서도 알 수 없고, 다음 세션에 쓸모 있는 것.*
그리고 구체적으로 쓴다 — "인증 버그 고침" 은 쓸모없고, "토큰 만료를 1시간에서 24시간으로 바꿈 (`src/auth/config.ts`)" 은 쓸모 있다.

### 종류 7개

| 종류 | 언제 | 더 필요한 것 |
| --- | --- | --- |
| `todo` | 다음에 할 일 | `--todo-status open\|doing\|done` |
| `history` | 끝난 일의 경위·공수 | — |
| `issue` | 증상 → 원인 → 해결 | `--severity` · `--sources` · 본문에 `## 증상`·`## 해결` 각 2줄 이상 |
| `caution` | 다시 밟지 말 함정 | `--severity` · `--sources` |
| `decision` | 뒤집을 수 있는 선택 | `--sources`. **한 건에 결정 하나** |
| `howto` | 하는 법 | 번호 목록 2단계 이상 |
| `fact` | 환경 사실 — 결정도 문제도 아닌 그냥 사실 (예: 집 회선은 KT 500M) | `--sources`. severity·todo-status 는 안 붙는다. 360일 지나면 낡음 후보 |

**결정이 뒤집혔으면 고치지 않고 새로 쓴다** — 새 기억을 넣고 `mem set <옛id> --by <새id>`.
덮을 새 기억이 아직 없으면 `mem set <옛id> --by-new` 로 검토 큐에 올린다.
**`superseded_by` 를 파일에 쓰는 것은 사람이 친 이 명령뿐이다** — 도구가 자동으로 무효를 만들지 않는다.

**종류별 취급은 `Memory/vocab.toml` 의 `[type.<이름>]` 절로 덮어쓸 수 있다.** 기본 7종은 못 지운다 —
지우면 이미 저장된 기억이 통째로 규격 밖이 된다. 종류를 늘리는 명령은 없고, `vocab.toml` 을 직접 고친다.

```toml
[type.fact]
label        = "환경 사실"   # 도움말·오류 문구에 쓰는 이름 (새 종류는 필수)
sources      = "required"    # required | warn | none        기본 none
severity     = false         # true 면 필수, 아니면 붙이면 거절  기본 false
todo_status  = false         # 위와 같다                        기본 false
body         = "free"        # free | issue-sections | numbered  기본 free
evidence     = false         # 본문에 확인 가능한 조각 요구      기본 false
conclusion   = false         # 결론 문장 요구                    기본 false
one_thing    = true          # 한 건에 하나. true=거절, false=경고  기본 false
gate         = false         # 저장 전 충돌 관문(C04)            기본 false
stale_days   = 360           # 낡음 후보 일수. 0 = 안 봄         기본 0
half_life    = "none"        # none | history(90일) | decision(720일)  기본 none
gc_keep      = true          # 본문 접기 면제                    기본 false
search_bonus = false         # 검색 가산 +0.3                    기본 false
hook         = "환경"        # 세션 훅 절 이름. 비우면 안 실림   기본 ""
```

## 검색 팁

| 상황 | 이렇게 한다 |
| --- | --- |
| 기본 | `mem search 색인 성능` — **낱말을 띄어서.** 따옴표는 필터가 아니라 **점수 가산**이라 셸이 먹어도 결과가 크게 안 갈린다 |
| 0건이 나면 | 알아서 완화해 다시 찾는다. 결과 줄에 **어느 칸에서 찾았는지** 꼬리표가 붙는다 |
| 같은 것을 **다르게 부를 때** | `Memory/mem.toml` 의 **`[canon]`** 에 **변이 = 대표말** 한 줄씩 적는다 (`"인덱싱" = "색인"` · `"index" = "색인"`). 색인 때 대표말로 통일되므로 **재색인이 필요하다** |
| 외래어·1:다 매핑 | `[synonym]` 에 적는다. **양방향이라 한 줄이면 된다.** 낱말당 최대 3개, **찾을 때만 쓰므로 재색인이 필요 없다** |
| 후보를 추천받고 싶을 때 | `mem tags --suggest` — 표에 넣을 만한 동의어·대표말 쌍을 제안한다. **아무것도 안 고친다** |
| 보류 기억까지 | `--include-held` — `add --hold` 로 넣은 것은 기본으로 빠진다 |
| 몇 건까지 | `--limit` 은 **최대 100**. 더 크게 주면 100 으로 깎고 알린다 |
| 태그·범위로 좁힐 때 | 질의 안에 `#태그` · `scope:이름` 을 그냥 섞어 쓴다. 옵션으로도 된다 |
| 시간으로 좁힐 때 | `어제` `지난주` `최근 7일` `2026-08` 을 질의에 넣거나 `--since 30d` |
| 목록만 볼 때 | 질의 없이 조건만 — `mem search --type decision --scope unity-build --since 30d` |
| 뒤집힌 옛 결정까지 | `--all` — 무효가 된 것에는 `[무효]` 꼬리표가 붙고 점수가 절반으로 깎인다 |
| 왜 이 순서인지 | `--explain` — rrf 신호별 순위 · 가산 · 감쇠 · 신뢰계수와 어느 칸에서 맞았는지 |

### 0건이 났을 때 읽는 법

조용한 0건이 이 툴의 가장 비싼 실패다. 그래서 **0건이면 반드시 왜 0건인지 말한다.**

```
검색 : "타일맵 셰이더"  → 0건
  · 저장소에 "셰이더" 가 들어간 기억이 하나도 없다.   ← ① 어느 낱말이 아예 없나
  · "타일맵" 은 3건 있다.                             ← ② 있는 낱말은 몇 건인가
  · 비슷한 낱말 : 셰이더그래프(1) · 셰도우(2)          ← ③ 닮은 낱말
  · 보류 2건은 뺐다 (--include-held 로 같이 본다)      ← ⑤ 보류가 있을 때만
  · 다시 해 보기 : mem search 타일맵                   ← ④ 바로 칠 수 있는 다음 명령
```

**①이 진짜로 봐야 할 줄이다** — "그 낱말이 저장소에 아예 없다" 와 "기억이 없다" 는 다른 말이다.
`--json` 이면 같은 내용이 `why` 로 오고, **0건이어도 `hits` 는 `null` 이 아니라 `[]`** 다.

**"없으면 없다고 한다" 를 지키는 장치** : 정확히 찾은 칸에 앉으려면 두 관문을 지나야 한다 —
**질의 낱말의 과반이 저장소에 실제로 있어야 하고**, 문서는 **그중 과반을 맞춰야** 한다.
낱말 넷 중 셋이 없는데 남은 하나로 5건을 내놓는 일이 이래서 안 생긴다.
**임베딩도 이 관문을 못 넘는다** — 섞기는 낱말 후보 창 안에서 자리만 바꾸고, 창 밖 문서를 데려오지 않는다.

## AI 에게 시키는 법

**진짜 안내서는 `Memory/사용법.md` 다.** `mem init` 이 그 파일과 규칙 문서 끝의 **규칙 블록 6줄**을 넣는다.
AI 는 세션 시작에 훅이 밀어 넣는 요약만 읽으면 된다. 여기 README 는 사람이 보는 자세한 판이다.

| 언제 | 무엇 |
| --- | --- |
| 넣을 때 | `mem add --type <종류> --title "제목" --summary "한 줄" --tags a,b --scope <범위> --sources file:… --body "자세히"` |
| 찾을 때 | `mem search 낱말 낱말` · 본문은 `mem show <id>` |
| 고칠 때 | 본문·요약은 파일을 고치고 `mem index`. 결정이 뒤집혔으면 `mem set <옛id> --by <새id>` |
| 목록을 늘릴 때 | `mem tags --add <태그>` · `mem tags --add-scope <이름>` · 지금 뭐가 밖인지는 `mem tags --check` |
| **확신이 없을 때** | `mem add … --hold` — 보류로 들어가 검색·훅에 안 뜬다. **사람이** `mem review --promote <id>` 로 연다 |
| 언제 넣나 | **작업 완료 보고를 쓰기 직전에 "남길 것 있나" 를 한 번 본다.** 한 세션에 보통 0~3건 |
| 오류가 나면 | 작업을 멈추지 않는다. 그 기억은 포기하고 보고에 "기억 못 넣음" 한 줄 |

### 개인 기억은 어디에 두나

**개인용 전역 저장소는 없다.** v0.1 의 `~/.aimemory/global/` 과 `--global`·`--no-global` 은 v0.2 에서 걷어 냈다.

| | 프로젝트 저장소 | 개인 기억 |
| --- | --- | --- |
| 어디 | `<프로젝트>/Memory/` | Claude 내장 기억 (auto memory) |
| git | 추적한다 (팀과 공유) | git 밖 · 그 기계 안에만 |
| 무엇을 | **팀이 나눠 볼 결정·기록·조사 결과** | 개인 취향·말투 |

기준은 하나 — **"팀원이 봐야 하는 말인가?"** 그러면 `mem`, 아니면 내장 기억.

## 보안

| 무엇 | 어떻게 |
| --- | --- |
| 비밀정보 | `add` · `add --jsonl` · `set` · 승격 · `lint` **다섯 자리에서 차단**(+ `migrate`). **`--force` 같은 우회는 만들지 않았다** |
| 값은 안 찍는다 | 걸린 자리는 "몇째 줄, 어느 규칙" 까지만. 오류 메시지가 비밀을 두 번 새게 두지 않는다 |
| 경로 감옥 | `Memory/` 밖은 읽지도 쓰지도 않는다. 뿌리와 대상을 `EvalSymlinks` 로 정규화해 비교하므로 **중간 폴더가 링크여도** 못 나간다 |
| 주입 중화 | 훅·`search`·`show`·`review`·`tags --suggest`·`status --embed` 가 **같은 함수 하나**(`internal/safe`)를 지난다. `show --raw` 만 원문이다 |
| 자동 삭제 없음 | 지우는 코드 경로가 아예 없다. `gc` 는 접기만 하고 `--restore` 가 늘 있다 |
| `settings.json` | 고치기 전에 백업하고, 쓰기 직전에 다시 읽어 대조한다. 그 사이 남이 고쳤으면 **안 쓰고 손으로 하라고 안내한다** |
| 그림자 exe | 저장소 안에 `mem.exe` 가 딸려 오면 그것이 먼저 돈다. `init` 이 `.gitignore` 에 넣고 규칙 E04 가 **거절**로 잡는다 |
| 받아 온 바이너리 | 모델·DLL 은 **박아 둔 SHA-256** 을 맞춘 뒤에만 쓴다. DLL 은 **절대경로로** 로드한다 (System32 의 옛 `onnxruntime.dll` 이 잡히면 죽는다) |

### 판 올리기

**자동 업데이트는 안 만든다.** 새로 `git pull` → `.\build.ps1` → `mem install --apply` 를 다시 돌리면 덮어쓴다(옛 판은 `.bak`).

- exe 가 DB 보다 **새로우면** 색인을 다시 만들고 계속한다. `index.db`·`vectors.bin` 은 파생물이라 **잃는 것이 없다.**
- exe 가 DB 보다 **낡았으면** DB 를 안 건드리고 "새 판을 받아라" 만 찍고 **종료 코드 2**.
- 지금 판·규격 판·DB 판은 `mem status` 가, 모델 판은 `mem status --embed` 가 보여준다.

## 만드는 사람용

```powershell
.\build.ps1
go build ./... ; go vet ./... ; go test ./...
go test ./internal/search ./internal/hook -update    # 골든 출력 다시 만들기
```

- 한글 문자열은 `internal/i18n` 안에만 둔다. 그 밖에는 한글 리터럴을 두지 않는다.
- 같은 규칙을 두 곳에 적지 않는다 — `add` 관문과 `lint` 는 `internal/quality` 의 같은 함수를 쓴다.
- **이 폴더는 다 만들면 떼어 내 독립 git 저장소가 된다.** 그래서 코드·문서 어디에서도 바깥 폴더를 가리키지 않는다.
- **시험용 뒷문 환경변수** — 아래는 **다음 판이 다른 모델·다른 섞는 법을 다시 재 볼 수 있게 남긴 것**이다.
  **평소에는 아무도 안 준다.** 값을 바꾼 채로 잰 수치는 그대로 믿으면 안 된다.

| 환경변수 | 무엇 | 기본 |
| --- | --- | --- |
| `MEM_EMBED_MODEL` | 의미 검색 모델 이름 | `mem.toml [embed] model` → 비면 exe 기본 모델 |
| `MEM_EMBED_BLEND` | 낱말 점수와 코사인을 섞는 법 (`rrf` `mix` `flat`) | `rrf` |
| `MEM_EMBED_ALPHA` | `mix` 일 때 코사인 몫 | `0.5` |
| `MEM_EMBED_TOPN` | 코사인을 재는 상위 몇 건까지 | `50` |
| `MEM_EMBED_FLATGAP` | `flat` 일 때 「납작하다」고 볼 점수 차 | `0.25` |
| `MEM_EMBED_MAXTEXT` | 한 기억에서 임베딩에 넣는 글자 수 | `600` |
| `MEM_EMBED_MAXTOKENS` | 한 번 추론에 넣는 토큰 수 | `128` |
| `MEM_DUP_BETA` | 중복 판정에서 벡터가 얹는 몫 | `1.0` |
| `MEM_DUP_C0` | 그 몫을 세기 시작하는 코사인 문턱 | `0.50` |
| `MEM_DUP_RANK` | 「서로가 서로의 가장 가까운 k 안」의 k. `0` 이면 절대 문턱만 | `1` |
| `MEM_DUP_ONEWAY` | 값이 있으면 **한쪽만** 가까워도 친다 | 없음 (서로 가까울 때만) |

- **뒷문이 아닌 것 셋** — `CLAUDE_PROJECT_DIR`(훅이 받는 프로젝트 폴더 · Claude Code 가 준다) ·
  `MEM_DEBUG=1`(훅이 왜 조용한지 stderr 한 줄) · `MEM_INSTALL_NO_PATH`(`install` 이 PATH 를 안 건드림).
  전체 표는 `Docs/Guide/명령명세.md` 9절.

## 라이선스

의존은 전부 **허가형(permissive)** 이라 사내 툴에 넣는 데 제약이 없다. GPL·AGPL·LGPL·MPL 계열은 하나도 없다.
같이 받아 오는 **ONNX Runtime(MIT)** 과 **모델(MIT)** 도 마찬가지고, `mem install` 이 라이선스 글까지 같이 놓는다.
실제로 exe 에 들어가는 목록과 저작권 고지는 **`THIRD-PARTY.md`** 에 있다.
`go.mod` 를 늘리려면 사용자 승인을 받는다.
